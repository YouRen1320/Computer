# 第 48 周：发布候选、最终考核与下一阶段

## 本周定位

最后一周不是继续完善到“永远不发布”，而是冻结范围、完成最终验证，并基于事实决定下一阶段。达到标准不等于拥有多年生产经验；它表示你具备相邻岗位可面试、受控任务可交付和使用 AI 后能承担结果的基础。真实投递只在你明确恢复求职后启动，不作为技术结业门槛。

## 前置条件

- Week 47材料和模拟面试完成；
- 项目不存在已知严重越权、数据损坏或密钥泄漏；
- 有完整测试/评估/故障和已知限制；
- 已安排最终无AI考核时间。

## 本周目标

- 冻结R6 release candidate，完成安全/质量/部署清单；
- 运行全部测试、AI评估和恢复演练；
- 完成G8无AI端到端需求、故障定位和项目答辩；
- 发布可访问演示或可重复本地演示包；
- 建立能力缺口闭环；恢复求职后再基于真实投递和面试反馈定向补强；
- 形成48周事实复盘和入职后学习路线；
- 明确哪些能力已验证、哪些仍只是概念。

## 必须理解的概念

- release candidate、version/tag、changelog和artifact；
- code freeze、bug bar和scope control；
- release checklist、go/no-go和rollback trigger；
- data migration不可简单随镜像回滚；
- feature flag和降级；
- vulnerability/secret/license基础检查；
- evidence-based self assessment；
- job funnel、conversion rate和small sample；
- offer/岗位选择与长期能力复利；
- 入职后30/60/90天学习计划。

## 时间与任务（15—18小时）

下方最终无AI考核计入任务2—3，不在总时长之外重复增加。

### 任务1：发布冻结和全量验证（3小时）

- 创建release branch/tag和changelog；
- 运行Java、Node、Python、Flutter全量检查/测试/构建；
- 跑OpenAPI/事件契约检查；
- 跑80+条AI评估和安全集；
- 扫描依赖、镜像和仓库secret；
- 确认迁移、种子、备份和恢复；
- 只修阻塞发布的高优先级问题。

### 任务2：最终无AI需求（3小时）

从[ASSESSMENTS.md](../ASSESSMENTS.md)随机选择一项端到端需求，180分钟内完成：需求澄清、迁移、Java规则、API、测试、一个客户端最小交互和说明。允许查官方文档，不使用AI。

### 任务3：故障定位与答辩（2小时）

- 随机处理两个故障；
- 完成8分钟产品演示；
- 完成12分钟架构讲解；
- 接受20分钟追问；
- 记录不知道和未验证的部分，不猜答案。

### 任务4：发布演示（2小时）

选择一种：

- 受控云/VPS演示；
- 本地Docker演示包和录制视频；
- 两者都有。

公开演示必须使用假数据、受限账户、费用上限和最小暴露面。没有安全条件时，宁可提供本地可复现演示，不把数据库/管理端暴露公网。

### 任务5：职业证据与反馈闭环（3—5小时）

- 求职仍暂停时：用四类岗位能力画像核对 R3/R4/R5/R6 证据，完成一次简历事实核验、一次综合模拟和一次薄弱项复测；
- 若已恢复求职：为当周15—25个岗位逐个选择对应证据版本，在简历和沟通中突出真实证据；
- 真实面试在24小时内复盘，连续两次同类失败立即安排复测；
- 只记录真实投递与 Offer，不用模拟数据冒充求职漏斗；无投递数据时明确写“不适用”。

### 任务6：48周总结和下一步（2小时）

输出：

- 已达到L3/L4的能力；
- 只有L1/L2的能力；
- 项目已验证/未验证清单；
- 最有价值的三个错误；
- AI提高效率与造成错误的真实案例；
- 求职已恢复时记录漏斗数据；暂停时记录“不适用”和替代训练结果；
- 如果已有offer：入职30/60/90天计划；
- 如果暂无offer：未来4周只补哪两个最高回报缺口。

## FactoryCare项目增量

- R6 release candidate/tag/changelog；
- 最终测试、AI评估和安全报告；
- 可访问或可复现演示；
- 最终答辩与已知限制；
- 项目进入维护而非无限开发状态。

## AI协作边界

发布清单、漏洞修复和简历文字可以由AI审查，但最终考核必须关闭AI。AI不得替你决定是否公开服务、是否忽略安全告警、是否执行数据迁移或是否在简历中夸大。

## 无AI训练与最终考核（至少240分钟）

严格执行[ASSESSMENTS.md](../ASSESSMENTS.md)的G8：

- 180分钟端到端需求；
- 60分钟两个故障；
- 产品/架构答辩；
- 求职材料核验。

## 求职动作（恢复求职后启用）

- 集中投递15—25个高匹配岗位；
- 使用数据比较四版简历；
- 对offer从职责、团队、成长、稳定、加班/驻场、薪资和城市成本综合比较；
- 不因为计划结束就停止按面试反馈迭代。

求职暂停时，本节不执行、不计入 G8；任务5的作品证据核验、综合模拟和薄弱项复测作为替代交付。

## 交付物

- [ ] release candidate、tag和changelog；
- [ ] 全量测试/构建/契约结果；
- [ ] AI评估与安全回归；
- [ ] 备份恢复和回滚检查；
- [ ] G8最终考核记录；
- [ ] 演示链接或本地复现包；
- [ ] 求职已恢复时提交15—25次本周投递和累计数据；暂停时提交替代训练记录；
- [ ] 48周总结和下一阶段计划。

## 验收标准

- [LEARNING_PLAN.md](../LEARNING_PLAN.md)第10节核心标准达到；
- 总评分至少75，任何领域不低于60；
- 严重安全/数据问题为0；
- 所有能力声明能指向代码、测试、报告或明确口述；
- 未验证内容已显式标注；
- 可以独立完成小需求、定位常见故障并讲清系统；
- G8技术考核通过；求职已恢复时进入真实求职循环，暂停时此项标记为“不适用”。

## 如果没有通过

不要重跑整个48周，也不要新增技术栈。按失败类别建立2—4周补强：

- Java/SQL不过：每天无AI小题 + 一个项目修复；
- 项目讲不清：补ADR、图和故障证据；
- AI质量不过：固定评估集逐层定位；
- 求职已恢复且沟通率低：修改定位/简历，而不是继续堆项目；
- 面试算法弱：集中补基础结构和高频题；
- 多端不稳：保留一个主端，诚实降低另一个声明等级。

## 本周明确不做

- 发布前临时增加大功能；
- 求职已恢复后因追求完美延迟投递；
- 求职暂停期间为凑验收数字强行投递；
- 忽略高风险告警换取演示效果；
- 把最终考核交给AI；
- 把“完成计划”写成商业年限；
- 未经比较就继续学习新的语言/框架。

## 计划结束后的维护节奏

- 每月依赖/安全更新和完整回归；
- 每次真实面试更新错题和项目证据；
- 每季度选择一个真实约束深化，而不是横向加栈；
- 入职后优先学习公司业务、代码库、发布和故障流程，再决定Spring Cloud、MQ或其他专项。
