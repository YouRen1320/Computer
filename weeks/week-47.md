# 第 47 周：作品集、架构表达、系统设计与综合模拟

## 本周定位

技术能力只有被陌生读者快速看懂并经得起追问，才会成为可复用的职业证据。本周不堆新框架，集中把 FactoryCare 整理成可信作品，并针对 Java、Vue、多端和 AI 能力进行综合模拟。求职仍暂停时，所有真实投递任务自动替换为作品校准和复测，不影响本周验收。

## 前置条件

- R6生产候选可运行；
- 主要测试、评估、故障和部署证据齐全；
- 已记录已知限制与未验证声明；
- 已有目标岗位能力画像；若已恢复求职，再补充当期真实岗位样本和投递数据。

## 本周目标

- 完成面向陌生读者的README和作品导航；
- 完成必要架构、数据、状态、权限和AI图；
- 准备8分钟演示、12分钟架构讲解和追问；
- 形成Java/SQL/Vue/多端/AI错题库；
- 完成多轮技术面、项目面、系统设计和HR模拟；
- 根据能力画像整理事实版材料；恢复求职后再根据真实 JD 生成定向简历，不篡改事实；
- 修复影响面试的最高优先级缺口。

## 必须理解的概念

- portfolio不是源码堆积，而是问题、决策、证据和限制；
- C4/上下文/容器/组件图的层级；
- sequence、state、ER、deployment图各自用途；
- ADR、trade-off、migration和rollback；
- 项目介绍的STAR/问题-约束-行动-验证结构；
- 系统设计中的需求、容量、数据、一致性、API、故障和安全；
- 不确定时如何澄清、假设和标注未验证；
- 简历关键词与真实证据映射；
- 行为面试、冲突、失败、成长和AI使用伦理；
- offer比较维度。

## 时间与任务（15—18小时）

下方180分钟无AI训练计入任务4—5的现场编码、演示与追问，不在总时长之外重复增加。

### 任务1：README与作品导航（3小时）

README首屏在2分钟内回答：

- 解决什么问题；
- 哪些角色和主流程；
- 架构和技术为什么这样选；
- 三端与Java/Python边界；
- 如何快速运行演示；
- 有哪些测试、AI评估和故障证据；
- 哪些是已知限制。

补充文档目录、截图/短GIF、演示账户和安全提示。不要在README堆徽章和完整依赖清单掩盖业务。

### 任务2：架构材料（2—3小时）

至少完成：

- 系统上下文与容器图；
- Java模块依赖图；
- 核心ER图；
- 工单状态机；
- 权限矩阵；
- 报修/派单/AI诊断时序图；
- RAG数据流；
- 部署图。

每张图回答一个问题，保持与当前代码一致。

### 任务3：演示脚本（2小时）

准备两种版本：

- 5—8分钟：产品价值和一条主链路；
- 12—15分钟：加入架构、失败路径和AI评估。

演示使用稳定种子数据和fake/受控模型备选。包含至少一个失败/降级，不只展示顺利路径。

### 任务4：知识矩阵和现场编码（3小时）

- 从[ASSESSMENTS.md](../ASSESSMENTS.md)汇总薄弱项；
- Java集合/并发/Spring/事务/SQL各做一组限时题；
- Vue状态/SSE做一个小修；
- AI评估/权限做一个故障解释；
- 数据结构与算法复习数组、链表、栈队列、哈希、树、排序、二分、DFS/BFS和复杂度，不追求竞赛题海。

### 任务5：模拟面试（4—5小时）

至少完成：

1. Java/Spring/SQL技术面2次；
2. Vue/全栈项目面1次；
3. AI/RAG项目面1次；
4. 系统设计1次；
5. HR/自我介绍/职业转型1次。

每次使用模板复盘，并在48小时内复测最重要问题。

### 任务6：事实材料与证据映射（1—2小时）

- 完成R1—R4事实一致版本；
- 为 Java 后端、Java 全栈、Vue 前端和 AI 应用四类能力画像逐项映射证据；
- 删除无证据技术词；
- 准备学历、薪资、到岗、转型和职业规划的诚实回答；
- 仅在已恢复求职时，选择10个真实岗位校准材料并投递15—20个高匹配岗位；暂停时用同等时间补最高优先级技术缺口。

## FactoryCare项目增量

- 求职版README和作品导航；
- 全套架构/ER/状态/时序/部署图；
- 演示脚本和可选短视频；
- 测试、AI评估、故障和已知限制摘要；
- 面试题证据链接。

## AI协作边界

AI可以模拟面试、压缩文字和检查文档一致性，但不能编造业务结果、工作年限、用户数、并发或准确率。AI生成的项目描述必须逐句能指向真实代码/测试/报告。

## 无AI训练（180分钟）

完成一次完整模拟：90分钟现场需求或修bug，30分钟项目演示，30分钟架构追问，30分钟复盘。只允许官方文档，不允许AI提示。

## 求职动作（恢复求职后启用）

- 集中投递15—20个高匹配岗位；
- 联系可信前同事/朋友进行一次真实反馈；
- 对连续失败类别进行48小时专项修复，不增加新框架；
- 记录每版简历的沟通率。

求职暂停时，本节不执行、不计入验收；改为做一次 README 陌生读者检查、一次模拟项目追问和一次错题复测。

## 交付物

- [ ] 完整README和作品导航；
- [ ] 至少8类必要图；
- [ ] 两版演示脚本；
- [ ] 四版简历和事实库；
- [ ] 至少6次模拟面试复盘；
- [ ] 无AI综合模拟；
- [ ] 求职已恢复时提交15—20次定向投递记录；暂停时提交三项替代训练记录；
- [ ] 本周周复盘。

## 验收标准

- 陌生读者2分钟知道项目价值和证据；
- 图与代码/数据库一致；
- 8分钟演示不依赖临时手工修数据；
- 能讲三项取舍、两项限制和一次失败；
- 简历所有技术点都有证据或诚实标为了解；
- 模拟面试薄弱项有复测结果。

## 本周明确不做

- 为简历新增框架；
- 重写整个UI；
- 编造量化结果；
- 背固定项目稿却无法接受追问；
- 把个人项目说成公司生产系统；
- 因准备不完美暂停全部投递。
- 在求职暂停期间为凑计划数字强行投递。
