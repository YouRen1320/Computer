# 练习：stdin、stdout、stderr、管道与退出码

先独立保存预测和诊断，再看私有解析。所有命令只允许作用于教材固定目录或新建临时目录，不得覆盖真实项目文件。

## A. 画连接图

画出键盘、输入文件、进程 A、进程 B、终端、结果文件之间的连接。分别标出 A 的三条标准流、B 的三条标准流和两张退出回执。说明 `A | B` 默认连接哪两条流，哪条诊断不会自动进入 B。

## B. 四列预言

对合法状态、非法状态、空输入分别写精确 `stdout`、`stderr`、退出状态和是否应继续 `&&` 右侧。不要用“有结果”“报错”代替精确内容。

## C. 重定向边界

给定已有 `result.txt` 内容为 `old`，预测 `> result.txt` 与 `>> result.txt` 在成功和程序随后失败时可能留下什么。解释为什么文件存在不能证明成功，以及为什么 `2>/dev/null` 不是诊断修复。

## D. 管道失败传播

预测以下两组的管道状态和原因：前段 7、末段 0；前段 0、末段 1。再说明默认规则与 zsh `PIPE_FAIL` 下证据有什么差异。不能只答“开 pipefail”。

## E. 短路

分别解释 `A && B`、`A || B`、`A ; B`。若 A 在 stdout 打印 `SUCCESS` 但状态为 3，哪些 B 会运行？若 A 静默返回 0，又有哪些 B 会运行？

## F. 故障日志

一条 FactoryCare 状态筛选管道生成了正确的一条设备 ID，但状态为 65，stderr 为 `invalid trailing row`。指出最先可信证据、为什么不能判成功、是否可以保留部分 stdout、下一条最小诊断动作与修复后的复跑预言。

## G. 需求变更

将允许状态增加 `WAITING_PART`，成功字段从 `accepted` 改为 `accepted_status`。列出生产者、管道消费者、结果预言、错误路径和回归案例中必须改与不得改的内容。

## H. 安全审查

审查 AI 给出的命令：它把两条流合并后追加到主目录中的旧日志，并用 `|| true` 强制成功。指出覆盖/隐私/证据/失败传播风险，设计只在临时目录运行的观察方案；不要执行原命令。

## I. 无 AI

关闭 AI，限时 45 分钟完成 A—F。用 120 秒解释“三条传送带与一张回执”，保留一个错误预言，注明错在 token、stream、redirect、pipeline、status 还是 short-circuit。
