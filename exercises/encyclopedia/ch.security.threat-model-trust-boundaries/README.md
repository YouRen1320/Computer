# 独立练习：修复威胁模型可追踪性

`ThreatModelChallenge.java` 有四个 TODO。你要实现：

1. 信任域变化时必须有边界，同域流不得伪造边界；
2. 模型必须同时包含管理员和内部人；
3. 每个威胁必须有控制与验证 ID；
4. 认证绕过、越权、篡改、泄露四类滥用场景必须齐全。

先预测 starter 第一条失败，再运行：

```bash
./verify.sh
```

初始脚本应报告 `VALID_CROSSING_REJECTED`，这表示练习夹具就绪。完成后直接编译运行类，目标输出见题目中的 `System.out`，且所有正反断言都必须保留。不要把方法统一改成 `true`，那会接受注入的坏模型。

练习完全离线，不含账号、凭据或生产端点。完成后再查看私有解析。
