# 练习：预期值、测试预言、断言、AAA 与测试层级

先独立回答，再查看私有解析。

## A. expected 与 actual

1. 为什么 `expected = calculate(input)` 通常是循环预言？
2. actual 与 expected 相等能证明什么，不能证明什么？
3. 需求含糊时，应该猜一个 expected 还是先澄清？

## B. AAA

把“31 分钟、每块 5000 分、零配件，结果 10000 分”拆成 Arrange、Act、Assert。指出每段若混入多个业务动作会造成什么问题。

## C. 分类设计

为“按已开始的 30 分钟块计费”列出正常、零值、边界和非法输入。为什么只测 60 分钟不能发现向下取整缺陷？

## D. 失败、错误与没运行

判断以下日志：

1. `Tests run: 8, Failures: 2, Errors: 0`；
2. `Tests run: 0, Failures: 0, Errors: 0`；
3. `BUILD SUCCESS`，没有测试摘要；
4. expected 10000、actual 5000；
5. 测试启动前配置解析异常。

哪些是业务断言失败，哪些是测试基础设施错误，哪些根本没有执行测试？

## E. T0—T4

把下列证据映射到本书层级：手算输出、显式断言、JUnit/pytest 单元测试、数据库集成/浏览器测试、性能/安全/恢复演练。解释为什么高层不是自动替代低层。

## F. 首个可信证据

日志先显示编译失败，后面保留了一段旧测试报告。当前运行的首个可信失败是什么？为什么不能先修最后一个 assertion？

## G. AI 生成测试

AI 同时生成实现和 expected，并声称“全部通过”。写出验证清单，至少包含独立规则来源、故障注入、边界、测试计数和恢复复跑。

## H. 无 AI

关闭 AI，限时 40 分钟完成 A—G。随后执行公开红—绿循环，保留三次摘要与退出码，并做 120 秒复述。
