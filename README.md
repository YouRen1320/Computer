# 36 周 AI-First 企业全栈求职工作区

这个工作区服务于一个明确目标：用 36 个正式学习周，把已有的 Vue3、TypeScript、Nuxt、Flutter、Python 基础，升级为能够投递南昌 Java/Vue 全栈、Java 应用开发和 AI 应用岗位的可验证能力。

本计划不是课程收藏夹，也不是让 AI 代写一个展示项目。所有知识最终都要进入同一个真实业务项目，并通过代码、测试、部署、故障演练、口述和无 AI 小考留下证据。

## 已确认的技术路线

| 层次 | 主技术 | 职责 |
| --- | --- | --- |
| 企业 Web | Vue3、TypeScript、Vite | 管理、调度、知识库、报表 |
| SSR/官网 | Nuxt 4 | 产品门户、公开内容、SEO 和 SSR 概念 |
| 小程序 | uni-app（Vue3） | 扫码报修、进度、确认、评价 |
| 移动 App | Flutter、Dart | 现场技师、拍照扫码、离线工单和同步 |
| 核心后端 | Java 25 LTS、Spring Boot 4 | 权限、事务、资产、工单、SLA 和审计 |
| AI 服务 | Python 3.14、FastAPI | 文档处理、RAG、工具调用、受控 Agent 和评估 |
| 数据与工程 | PostgreSQL、pgvector、Redis、MinIO、Docker | 业务数据、派生检索、缓存、对象存储和部署 |

Java 是业务事实和写操作的唯一中心；Python 只提供 AI 建议、草稿、检索证据和派生索引。三个客户端服务不同角色，不重复制作三套后台。

## 每周投入

默认每周 15—18 小时，建议分配为：

- 4 小时：官方资料、核心概念和笔记；
- 6—8 小时：练习与旗舰项目增量；
- 2 小时：测试、日志、排错和代码审查；
- 2 小时：关闭 AI 的编码、SQL 或口述考核；
- 1—2 小时：岗位采样、简历、投递和面试复盘。

36 周约 540—650 小时。遇到面试或工作任务时，可以按阶段门回退或暂停，但不改变知识依赖顺序。

## “了解概念”的合格定义

本计划不要求背框架源码，但“了解”至少同时满足：

1. 能用自己的话解释它解决什么问题；
2. 能与相邻方案比较适用条件和代价；
3. 能借助 AI 完成一个最小实现；
4. 能阅读 AI 生成的代码并指出关键数据流；
5. 能通过测试、日志或命令验证结果；
6. 能在没有 AI 时修改一个小需求或定位一个常见故障。

只看完教程、复制成功或能说出名词，都不算掌握。

## AI-First 执行闭环

1. 人先写目标、约束、接口和验收标准。
2. AI 解释概念、比较方案或生成小范围实现。
3. 人检查 diff、类型、事务、权限和错误路径。
4. 自动运行格式化、静态检查、测试、构建和集成验证。
5. 人关闭 AI 后口述关键链路，并完成一个小改动。
6. 小步提交，任何阶段都能回滚。

AI 可以加速输入代码，不能替你承担需求解释、数据模型、权限、事务、安全、测试结论和生产回滚责任。

## 旗舰项目

贯穿全程的项目是 **FactoryCare：多租户设备运维与智能工单平台**。

它包含设备资产、扫码报修、派单、现场处理、SLA、知识库、RAG、AI 分诊、报告草稿、人工审批和审计。完整范围与非目标见 [PROJECT_SPEC.md](./PROJECT_SPEC.md)。

## 明确不做

- 不学习 React 作为本轮主线。
- 不同时制作多个普通 CRUD 项目。
- 不默认拆 Spring Cloud 微服务，不为了简历硬上 Kafka 或 Kubernetes。
- 不同时深挖多个 Agent 框架。
- 不把 AI 应用计划包装成算法工程师训练营。
- 不把个人项目写成 Java、AI、Flutter 的商业工作年限。
- 不让 Flutter、uni-app 和 Nuxt 分别复制整套后台。
- 不因为“有 AI”而跳过 SQL、测试、权限、日志和排错。

## 执行原则

- 每周只有通过验收才进入下一周；未通过时优先补缺口，而不是继续堆框架。
- 版本在进入对应阶段时锁定当前稳定 patch，学习周期内不追逐 nightly。
- 从第 1 周就可以投递原有 Vue 岗；从阶段门逐步扩展到 Java/Vue 全栈和 AI 应用岗位。
- 获得合适 offer 后，计划可以切换为在职节奏，不需要为了“学完”拒绝工作机会。
