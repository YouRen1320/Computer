# 隔离解析：预期值、测试预言、断言、AAA 与测试层级

完成公开练习并保存预测后再阅读。

## A 组

若 expected 调用与 actual 相同的实现或算法，两者会一起犯错，测试只证明“实现等于自己”。expected 应来自需求、手算、可信参考模型、不变量或独立数据。相等只证明这个输入下观察符合该预言；不能证明预言正确、所有输入覆盖、无副作用或系统级安全。需求含糊时先澄清并记录决策，不能把猜测固化成绿色测试。

## B 组

Arrange：准备 `labor_minutes=31`、`block_rate_cents=5000`、`parts_cents=0` 和 expected=10000。Act：只调用一次 quote。Assert：actual 必须等于 10000。多动作混在一起会让失败来源不唯一，准备阶段执行业务又会隐藏副作用。

## C 组

正常可用 60；零值用 0；边界至少 1、30、31、1440；非法有负数、越上限和错误类型。60 恰好整除 30，向下/向上取整都得 2，无法杀死取整缺陷；1 和 31 才区分算法。

## D 组

1 是两条断言不匹配；2 是零测试，不能算绿；3 只证明构建命令成功，测试状态未知；4 是可定位的 expected/actual failure；5 是测试执行前的基础设施/配置 error，应先修它，业务断言尚未运行。

## E 组

本书映射：手算/输出/退出码 T0；预言与断言 T1；语言单元框架 T2；Mock、数据库集成、容器、浏览器或设备 T3；系统、性能、安全、恢复 T4。该命名是本仓治理层级，不是行业统一编号。更高层覆盖更广但更慢、更难定位，不能替代低层快速预言；低层也不能证明系统属性。

## F 组

当前运行最先可信失败是编译失败，因为测试二进制/代码尚未形成；后面的旧报告不是本次执行证据。先修构建并重新运行，才评价 assertion。

## G 组

应把 expected 与实现来源分开，手算关键 case；补正常、零、边界、非法输入；故意注入能被预言杀死的错误；核对 Tests run/Failures/Errors 与退出码；确认没有 skip/filter；恢复后原命令再绿；记录未覆盖的集成、并发、安全和性能边界。
