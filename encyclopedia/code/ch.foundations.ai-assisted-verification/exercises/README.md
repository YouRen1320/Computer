## A. 任务简报

把“帮我修一下 FactoryCare 计价”改写成 Goal、Context、Constraints、Done when。说明上下文过少和整仓库无差别上传各有什么风险。

## B. 权限边界

把以下动作分为“默认可读”“逐次批准”“本任务禁止”：读取指定源文件、修改一个允许文件、运行本地测试、安装依赖、联网、写生产数据库、推送远端、删除目录。给出判断依据，不依赖某家工具的按钮名称。

## C. 隐私与秘密

为什么“供应商说不训练”仍不足以授权发送生产日志？列出数据分类、最小化、保留、第三方工具、日志 / 反馈、本地缓存和事件响应七个检查点。若真实凭据已发送，应做什么？

## D. 幻觉与时效

模型给出一个看似可信的 API、一个测试通过日志和一条网页引用。分别写出可证伪主张、独立证据、失效反例和信息日期。为什么“模型很自信”不能提高证据等级？

## E. 逐 hunk 审查

设计一张最小审查表，必须覆盖作用域、行为、权限 / 网络、隐私、依赖 / 许可证、测试、生成文件和回滚。解释为什么不能只看最终文件。

## F. 负测保护

候选补丁修复了正常用例，却删除负数输入测试。你应在运行前、运行中、运行后各检查什么？为什么“测试全绿”可能反而是红旗？

## G. 许可证与来源

候选代码声称“来自常见开源实现”，但无 URL、版本、作者、许可证文本或 SPDX 标识。哪些结论可以自动化，哪些必须人工或法律审查？说明 SPDX 标识和 OSI 批准都不能单独证明与你的分发方式兼容。

## H. 可重复证据

设计一个完全离线的验证器，证明：静态候选自述会被忽略；隐藏网络、删除负测和未知来源依赖会被拒；好候选通过独立 oracle；拒绝项不修改工作树；回滚恢复摘要；相同输入两次结果一致。

## I. 工具中立工作流

分别用 Codex 和 Claude 作为候选生成器时，哪些环节可以完全共用？哪些数据保留、权限模式和本地缓存属于随产品、计划与日期变化的表面，必须查当日官方文档？

## J. 无 AI 考核

关闭 AI，在 45 分钟内审查公开 fixtures，保存 expected / actual、拒绝理由、回滚摘要和 120 秒复述。你的证据必须让另一位同学在无账号、无网络、无真实凭据的环境中复跑。
