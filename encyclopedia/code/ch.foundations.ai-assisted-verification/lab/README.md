# 实验：审查 AI 候选补丁，而不是相信它

## 目标

为 FactoryCare 的“零分钟不收费”小改动建立安全审查闭环：先写清任务和权限边界，再逐 hunk 审查静态候选，独立运行 oracle，拒绝夹带项，接受最小候选，最后回滚并重验基线。

本实验专门在无模型条件下训练审查能力。所有“AI 输出”都是仓库内静态教学 fixture；敏感值是明确标注的合成占位；不会调用 Codex、Claude 或其他在线服务，不需要真实账号、付费额度、API key 或网络。

## 开始前

1. 阅读 `task_brief.json`，用自己的话写出 Goal、Context、Constraints、Done when。
2. 预测旧回归和新需求 oracle 在补丁前分别应为 PASS 还是 FAIL。
3. 不运行脚本，逐个阅读 `candidates.json`，为每个 hunk 写“接受 / 拒绝 / 需更多证据”及理由。
4. 确认终端当前目录是仓库根目录。不要把真实秘密复制到 worksheet、终端参数、shell history 或聊天。

## 运行

```bash
ruby labs/encyclopedia/ch.foundations.ai-assisted-verification/run_lab.rb
```

该命令只使用 Ruby 标准库读取本地 fixture。若输出与预测不同，先定位第一条可信失败，不要先改 expected、删除负测或相信候选自述。

## 必交证据

- 填写后的 `worksheet.md` 副本，包含补丁前预测；
- 每个候选的逐 hunk 决定和权限、隐私、依赖 / 许可证、测试影响；
- 一次完整运行输出和退出码；
- 隐藏网络请求、删除负测、伪造成功日志三类故障的第一处可信证据；
- 接受候选的两套 oracle 结果；
- 回滚前后摘要、回滚后旧回归 PASS、新需求 oracle 预期 FAIL；
- 120 秒复述：为什么模型自述、一次成功和未审补丁都不是事实。

## 验收

- 提示或记录中没有真实秘密、个人数据或生产数据；
- 每项 AI 主张都有独立证据，或明确标为“未验证”；
- 被拒候选的工作树摘要与基线完全相同；
- 接受候选没有隐藏网络、测试削弱或新依赖；
- 回滚恢复原摘要，原回归 oracle 仍通过；
- 相同输入复跑产生同一报告摘要。

## 边界

通过本实验只能证明你能审查这个透明教学模型。它不证明真实模型永不泄密、不证明实际沙箱绝对安全、不证明第三方代码许可证兼容，也不替代真实仓库的 `git diff`、测试、安全扫描、组织审批和法律审查。
