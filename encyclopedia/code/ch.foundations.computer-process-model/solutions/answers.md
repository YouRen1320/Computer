# 隔离解析：CPU、内存、磁盘、程序与进程

完成公开练习并保存预测后再阅读。

## A

CPU 执行指令，内存保存运行期可直接访问的代码与数据，磁盘持久保存程序、配置和日志字节。加载程序涉及从磁盘读入内存并由 CPU 执行，所以归类要写观察阶段。未保存对象通常在内存；已保存日志主要占磁盘；缓存通常占内存但也可能有磁盘实现。

## B

一份程序文件可以产生多个进程。连续或并发两次启动会得到独立运行实例与当时分配的 PID；进程各有自己的地址空间模型，不等于天然共享全部内存。进程退出不会删除程序文件，PID 也不是可长期硬编码的业务身份。

## C

进程会经历创建、由调度器管理的可运行/运行、等待某事件、退出与回收等阶段。一次“正在运行”观察只证明该时刻；等待不等于结束。进程彻底结束后，系统未来可以把数值相同的 PID 分配给另一个进程，因此要结合时间、父子关系和程序身份。

## D

父子关系描述创建关系：zsh 是 Ruby 的父，Ruby 是短任务的父。程序文件的所有权属于文件系统与权限模型，不能由 PPID 推断。父进程退出后的子进程行为受平台、信号、会话和程序设计影响，本章证据不足时必须标未验证。

## E

1. 磁盘容量不能证明内存充足；观察内存使用、限制与分配失败。
2. 程序文件大小不限制堆、栈、映射与运行期数据；观察进程常驻/虚拟内存并结合限制。
3. 进程生命与持久文件生命不同；退出前后复核同一路径及字节。

修复动作后必须重测原指标，不能只看“感觉更快”。

## F

当前证据支持 CPU 是主要嫌疑，但还可能是忙等、算法低效、线程竞争或外部工作排队。快照不能单独证明根因。并发改为两个进程后，要验证总 CPU 调度、每进程与总内存、临时文件容量、PID 追踪、父进程回收和自然/异常退出后的清理；不能简单把单进程指标乘二当成真实结论。
