## A. 资源归位

把下列对象主要归入 CPU、内存或磁盘，并说明“主要”不等于“只涉及”：正在执行的加法、尚未保存的对象、已保存的日志文件、加载程序所需的字节、计算结果缓存、磁盘剩余容量。

## B. 程序与进程

同一个 `worker.rb` 连续启动两次。回答：程序文件有几份、可能观察到几个 PID、两个进程是否天然共享全部内存、第一次退出是否删除程序文件、第二次 PID 是否应当写死在配置中。

## C. 生命周期

为“创建、可运行/运行、等待、退出”画状态图。标出哪些状态一定表示 PID 仍属于一个活进程，哪些观察只能说明某一时刻，为什么结束后的旧 PID 不能永久当成身份。

## D. 父子关系

终端中的 zsh 启动 Ruby，Ruby 又启动一个短任务。画出父子树，区分“由谁启动”与“谁拥有程序文件”。父进程结束是否必然保证所有后代同时结束？把不确定部分标成未验证。

## E. 故障诊断

审查三句话：

1. “磁盘还有 100GB，所以内存不可能不足。”
2. “程序文件只有 20MB，所以进程最多占 20MB 内存。”
3. “进程退出了，所以磁盘上的配置也消失了。”

逐条写出混淆、最先观察的指标、可证伪预测和安全复测方法。

## F. FactoryCare 事件

导入任务启动后 CPU 长时间接近满载，常驻内存平稳，磁盘空间充足。先提出 CPU 瓶颈假设，再写至少两个替代假设和一个不能由当前快照证明的结论。随后需求变为“允许同时启动两个导入进程”，列出 PID、内存上限、磁盘临时空间和退出清理方面要重新验证的条件。
