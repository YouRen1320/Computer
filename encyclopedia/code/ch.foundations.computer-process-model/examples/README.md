# 示例：同一程序文件，两次进程生命

固定验证器只观察它自己启动的两个短 Ruby 子进程。`child_probe.rb` 是磁盘上的程序文件；每次启动都会获得一个运行实例、PID 和父 PID。子进程把最小记录写入新临时目录，验证器等待它自然结束，再确认原程序文件仍存在且字节摘要未变。

`resource-cases.json` 是三份教学快照，不是通用系统监控器。它刻意让 CPU 繁忙、内存接近上限、磁盘空间不足三种证据彼此分离，防止把所有“变慢”都叫成内存问题。

在本目录执行：

```text
ruby verify.rb
```

预期最后一行是 `process-model verification: PASS`。脚本不遍历其他用户进程，不读取 shell 环境或个人文件，不用进程间管道；子进程最长存活 0.40 秒并自然退出。退出后再次检查 PID 得到“不存在”是预期失败证据。
