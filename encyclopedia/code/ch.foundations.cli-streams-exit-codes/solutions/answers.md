# 隔离解析：标准流、管道与退出状态

完成公开练习并保存自己的预测后再阅读。

## A

管道只把 A 的 `stdout` 接给 B 的 `stdin`。A 的 `stderr` 默认仍去原诊断目标；A、B 各自有退出状态，Shell 再按管道规则产生组合状态。终端、文件与管道只是连接对象，不是流本身。

## B

合法输入应只产生规范化 stdout、空 stderr、状态 0，并允许 `&&` 右侧。非法与空输入应没有正常结果、产生安全诊断、状态非零，并阻止 `&&` 右侧。精确状态以探针合同为准，不能从自然语言猜。

## C

`>` 可能在程序完成前截断旧内容；失败后仍可能留下空文件或部分文件。`>>` 保留旧内容但会混入重复与历史。文件存在仅证明目录中有对象，不证明来源、内容和本轮状态。丢弃 stderr 删除证据，不修复故障。

## D

默认 zsh 管道通常反映末段，所以“前 7、后 0”可表现为 0，“前 0、后 1”表现为 1。启用 `PIPE_FAIL` 后，任一段非零会使整体非零，避免末段零掩盖前段；仍应记录各段和诊断，不能把选项当业务修复。

## E

短路只看状态，不看 `SUCCESS` 文字。A 为 3 时 `&&` 右侧跳过、`||` 右侧执行、`;` 右侧执行；A 静默为 0 时 `&&` 执行、`||` 跳过、`;` 执行。

## F

正确的一行 stdout 只是部分证据；状态 65 和 trailing-row 诊断说明整体合同未完成。先固定原输入并核对行边界，决定部分结果是否允许发布。若合同要求全量有效，应隔离部分 stdout，修复尾行后以同一预言复跑，不能只把状态改为 0。

## G

允许集合、成功字段、消费者解析预言和相应正例需要更新；空输入、其他非法状态、stderr 隔离和非零失败传播必须保留。应增加旧消费者不再接受旧字段的显式迁移证据。

## H

主目录旧日志可能含隐私，合并流丢失来源，追加混入历史，`|| true` 制造假成功。安全方案是在新临时目录使用固定无秘密输入，分别捕获两条流和原状态，先阅读命令与路径，不执行未知远程或破坏性程序。
