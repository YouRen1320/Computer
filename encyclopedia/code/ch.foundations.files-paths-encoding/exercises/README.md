## A. 路径预测

给定：

```text
project/
├── README.md
└── docs/
    └── guides/
        └── start.md
```

1. 从 `project/` 到 `start.md` 的相对路径是什么？
2. 从 `docs/guides/` 到 `README.md` 的路径图应怎样向父目录移动？
3. `docs/guides/start.md` 若从 `docs/` 解释，会指向哪里？为什么错误？
4. 写出一个本机绝对路径模型，并明确它为什么不应硬编码到团队项目。

## B. 名称与类型

解释 `.env`、`archive.tar.gz`、`config.json.txt` 和无扩展名 `LICENSE`。分别指出隐藏展示、最后扩展名和“名称不能证明内容”的边界。

## C. 字符与字节

已知 UTF-8 中 `A`、`修`、`🔧` 分别占 1、3、4 字节。预测 `A修🔧` 的字节数；再解释为什么编程语言的字符串长度不一定等于 3，也不一定等于 8。

## D. 故障诊断

为以下现象写“原因假设—第一项观察—单一修复—复跑”：

1. 编辑器找到 `device.txt`，程序却说文件不存在；
2. 修改 `config.json` 后行为不变；
3. 中文 CSV 打开乱码；
4. Git 显示整份文件每行都改变。

## E. 需求变更

FactoryCare 原来只导入英文 LF 文件，现在要支持中文与 Windows CRLF。先写输入/输出预言和未支持边界，再列出要验证的编码声明、真实字节、行尾和错误恢复。不要把“UTF-8”三个字当成全部实现。
