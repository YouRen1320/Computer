# 实验：绘制项目树并诊断路径、编码与换行

## 边界

本实验只要求图示、编辑器项目面板、面包屑、文件属性和状态栏观察。不要为了完成本章提前学习 Shell 的创建、移动、复制或删除命令。配套 Ruby 程序是可选只读验证器，不要求理解其语法。

## 一、路径树

打开 `workspace/tree.md`，以 `workspace/` 为起点补全三个目标路径：

- 中文设备记录；
- 点开头的环境示例；
- 双重扩展名反例。

然后分别把起点改为 `workspace/data/` 与实验根，重新写路径。每条答案必须同时标注起点。

## 二、字符与字节

打开 `workspace/data/device-note.txt`，观察编码和换行状态。填写 `worksheet.md`：

- 文本中 `A修🔧` 的可见符号数；
- 三个符号的码点表示；
- UTF-8 总字节数；
- 文件整体字节数为什么还包含标点和换行。

关闭标签后从项目树重新打开，确认中文未损坏。不要把一次正常显示夸大为所有编码均已验证。

## 三、故障注入

1. **错误起点**：故意把 `data/device-note.txt` 按 `workspace/data/` 为起点解释，画出错误目标；再恢复正确起点。
2. **同名/扩展名**：解释为什么 `config.json.txt` 不能仅凭图标当成 JSON。
3. **错误编码**：先复制实验文件作为副本；用编辑器“使用其他编码重新打开”观察现象，不覆盖唯一原件；改回 UTF-8 后关闭重开。
4. **换行差异**：新建两份相同两行文本，分别选择 LF 与 CRLF；记录状态栏差异。若编辑器不支持直接切换，写出手工预期即可。

## 四、验收

- 绝对/相对路径均指向预期文件，并明确起点；
- 树中正确标注目录、普通文件、隐藏名称、真实扩展名；
- UTF-8 中文保存—关闭—重开往返无损；
- 能解释字符数与字节数不是同一指标；
- 错误起点、错误编码与换行差异各有可观察反例；
- 修复只改变一个条件，并重新打开原目标；
- 未执行的平台和文件系统明确写为未验证。

可选验证：在示例目录执行 `ruby verify.rb` 检查仓库固定夹具。它不检查你的手绘树和口头解释。
