# 四类故障与断点实验

`verify.sh` 从同一绿色项目分别注入四个单一故障：编译语法错误、运行时除零异常、测试 expected 错误、业务实现逻辑错误。脚本保存 `build/*.log`，并验证每类故障确实在预期阶段出现。

自动脚本不能替你证明断点操作。完成以下人工记录：

1. 在 `RepairCost.calculate` 第一行设置断点，用 `120, 6000, 500` 调试 `calculatesTwoHoursAndParts`。
2. 命中后记录当前 stack frame、三个参数值和尚未计算的返回表达式。
3. Step Over 一次，确认控制仍在当前 frame；不要把 Step Into 当成“下一行”。
4. 对逻辑故障只保留一条失败测试，手算 12500，比较变量窗口中的中间值。
5. 修复最小一处，先重跑原失败输入，再重跑完整四条测试。

禁止从末尾 `BUILD FAILURE` 猜原因，也不要一次同时修改实现和 expected。日志里的第一处项目源码位置，通常比框架栈帧和最后的汇总更可信。
