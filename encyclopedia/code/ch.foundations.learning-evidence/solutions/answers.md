# 隔离解析：学习证据、掌握标准与间隔复习

完成公开练习并保存预测后再阅读。

## A 组

1. 四小时课程是过程痕迹，只证明记录者声称投入了时间；不证明能解释、构建或诊断。
2. 源码文件是产物存在；不证明来源、可运行性、需求正确或学习者能修改。
3. 两个断言及完整日志是这两个预言范围内的可重放证据；不证明未覆盖输入、部署和安全。
4. 延迟后独立需求变更同时支持长期检索与迁移；仍要声明工具、输入与未覆盖边界。

## B 组示例

“给定项目树和明确项目根，在不看完整答案时，能分别写出从项目根与 chapters 目录到目标文件的相对路径，并解释同一字符串在错误起点为何指向不存在位置；用编辑器面包屑复核；本轮不声称 Windows 文件系统行为已验证。”

## C 组修复原则

把宽泛 claim 缩到单一概念；三类任务分别验收解释、独立产物和失败恢复；先写固定输入与预测，再记录实际；`artifact_exists` 只能作为产物事实；最后明确边界与 1/3/7 天检索。

## D 组顺序

需求变更先改变正确性的定义。若先改实现，开发者可能让测试迎合当前结果。先写数量 0、阈值和负数的期望，再实现并观察红—绿证据，才能区分规则变更与偶然输出。
