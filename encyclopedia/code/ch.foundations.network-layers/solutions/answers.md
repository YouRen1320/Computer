# 隔离解析：IP、DNS、端口、TCP 与 TLS 分层

完成公开练习并保存预测后再阅读。

## A 组

1. DNS 成功有证据，TCP 尝试有证据且结果为拒绝；TLS 与应用层未执行。不能从拒绝反推名称解析错误。
2. 失败发生在 TLS 身份校验。DNS 只负责把输入名称解析成地址；解析正确不保证证书为该名称签发。
3. `ping` 不证明目标 TCP 端口监听、不证明防火墙允许该协议、不证明 TLS 身份与信任、不证明应用健康，也不证明业务权限。
4. IP 标识网络接口/地址，端口在主机传输层命名通信端点；同一 IP 可以有多个端口，各自由不同进程或服务状态控制。

## B 组

顺序为名称解析 -> TCP 目标端口 -> TLS 证书与握手 -> 应用数据。第一步失败后，后续是“未执行”，不是失败，更不是成功。把未执行写成失败会伪造观察；写成成功则更严重。

## C 组

拒绝通常很快收到明确否定，例如本机没有监听或中间设备主动拒绝；超时表示在预算内没有获得所等待的完成信号。超时可能来自错误地址、丢包、过滤、路由、拥塞、服务卡住或预算过短，不能单独证明服务器宕机。完整记录至少包含时间、目标、阶段、预算、退出码、stderr、已收字节与重试条件。

## D 组

`-k` 跳过证书校验，删除了“对端是否为预期身份”的安全预言，只能作为受控诊断对照，不能作为修复。证书还需验证签发链/信任锚、主机名、有效期、用途和握手参数。加密只阻止旁观者直接读明文；若通道终点本来就是攻击者，加密会安全地把数据交给错误对象。

## E 组示例

已确认：名称得到保留示例地址，目标 443 可建立 TCP；TLS 主机名校验失败，因为证书仅覆盖旧名称。未确认：HTTP、应用健康和权限均未执行。下一步应核对部署证书 SAN 与正式服务名的配置/变更记录，修正证书或目标名后重新进行严格校验，不使用跳过验证选项。

## F 组

可使用 `{target, ok, failed_layer, visited_layers, skipped_layers, elapsed_ms, error_class}`。未执行层应进入 `skipped_layers` 或显式 `not_run`，因为布尔 `false` 通常表示“执行后失败”，会丢失因果顺序。

## 实验预言

- 正常：`visited=[dns,tcp,tls]`，`failed_layer=nil`；
- 非法名称：`visited=[dns]`，TCP/TLS 未执行；
- 关闭端口：`visited=[dns,tcp]`，TLS 未执行；
- 证书名不匹配：三层都进入，在 TLS 失败；
- 有界等待：TCP 已连接，失败标记为 `tcp-wait`，不能改写成 connect timeout。
