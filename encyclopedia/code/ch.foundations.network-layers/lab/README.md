# 实验：把“网络坏了”拆成可重放的四层证据

## 目标与安全边界

你将观察名称解析、TCP 连接、TLS 握手和有界等待。所有监听与连接都限制在本机回环地址；不得把脚本改成扫描局域网或公网端口，不得关闭防火墙，不得使用 `-k`/`--insecure` 掩盖证书错误，也不得导入真实企业根证书。

## 步骤

1. 打开 `worksheet.md`，先预测五个场景会经过哪些层、在哪一层停止。
2. 执行 `ruby run_lab.rb`，把 JSON 中的 `visited`、`failed_layer`、错误类型和事实填入表格。
3. 执行 `ruby ../../../examples/encyclopedia/ch.foundations.network-layers/verify.rb`，确认固定断言全部通过。
4. 把 `certificate-name-mismatch` 的验证主机名改回 `localhost`，只改变一个条件后复跑；然后撤销自己的临时改动。
5. 用自己的话画出 `名称 -> IP -> IP:端口 -> TCP -> TLS`，在每个箭头旁写一个证据和一个不能由该证据推出的结论。

## 观察要求

- 正常链必须同时出现解析地址、TCP 对端、TLS 协议、证书 subject 与应用前的固定测试载荷；
- 名称错误的 `visited` 只能含 `dns`，不能声称端口关闭；
- 关闭端口的 `visited` 只能到 `tcp`，不能声称证书错误；
- 主机名不匹配必须到达 `tls`，并且不能用禁用校验来“修复”；
- 超时场景必须写成“TCP 已连接，等待字节超时”，不能写成“连接超时”；
- 每次修复只改变一个变量，并保留修复前与修复后的退出状态。

## 验收

实验通过需要：DNS、TCP、TLS 正常链有可重放证据；名称、端口、证书三种故障准确停在不同层；任一底层失败后未执行的上层没有成功主张；有界等待的阶段描述准确；验证器最终退出码为 0。

平台边界：脚本已针对仓库当前 macOS/Ruby 环境设计，但不代表 Windows、Linux、企业代理、真实 CA 或公网 DNS 已验证；这些项只记录为未验证，不靠猜测补齐。
