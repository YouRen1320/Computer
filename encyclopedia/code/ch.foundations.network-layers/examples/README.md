# 示例：在回环地址上逐层观察 DNS、TCP 与 TLS

本示例用 Ruby 标准库和 OpenSSL 在 `127.0.0.1` 临时启动服务。它不会访问公网，不修改 DNS、代理、防火墙、证书库或系统配置，也不会写入任何真实凭据。测试证书与私钥仅在进程内生成，进程结束即丢弃。

运行：

```bash
ruby verify.rb
```

最后一行应为：

```text
network-layers verification: PASS
```

`local_network_lab.rb` 产生五类可观察结果：

1. `localhost` 被解析为回环 IP，TCP 建连后完成受信任的 TLS 握手；
2. 含空格的非法主机名在 DNS/名称解析阶段停止，TCP 与 TLS 不执行；
3. 回环地址上的已关闭端口返回连接拒绝，TLS 不执行；
4. TCP 已连接但证书只签给 `localhost`，以另一个主机名校验时在 TLS 层失败；
5. 本地服务接受 TCP 后暂不发送字节，客户端的有界等待到期。这个场景证明“超时”必须注明等待哪一步，不能冒充 TCP 建连超时。

脚本的断言不依赖公网是否可用，也不把错误文字的具体语言当作唯一预言；它断言失败层、执行过的层和进程退出状态。
