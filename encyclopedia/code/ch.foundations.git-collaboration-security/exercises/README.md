+
## 提交文件与同一验证入口

本目录已提供可编辑的 `submission.md`。先保留五个占位行运行 `./verify.sh`，确认得到精确的教材预期红；再把每个 `TODO：请替换本行。` 改成自己的预测、实验、失败证据、修复复跑和复述。

- `0` + `EXERCISE_GREEN`：五个栏目均有内容，机器只确认结构完成；
- `41` + `EXPECTED_RED`：仍是完整的公开 starter；
- `43`：文件缺失、只改了一部分占位行、标题损坏或其他未知状态，需要先读诊断，不能冒充预期红。

`EXERCISE_GREEN` 不批改答案含义，也不证明掌握；正文结论、命令输出与复述仍需教师或独立真人语义复核。

先独立保存答案，再查看私有解析。只允许在配套验证器创建的一次性仓库或你另建的无 remote 临时仓库操作；不得在教材主仓运行写命令，不得使用真实身份、凭据、remote 或生产文件。

## A. 四层状态图

画工作树、index、HEAD 提交和分支引用。按“新建→add→再编辑→commit”标出每一步改变哪层，预测最后 commit 包含 add 时版本还是编辑器最新版本。

## B. 读 porcelain

逐项解释 `??`、` M`、`M `、`MM`、`A `、`D `、`UU`。每项写普通 diff、cached diff 与 status 分别可能显示什么，不能只展开英文缩写。

## C. 提交审查

一次 staged diff 同时含业务源码、`target/`、IDE 个人配置、调试日志和 `local.env`。设计不丢工作树内容的拆分流程，说明哪些应取消暂存、忽略、删除或升级安全响应。

## D. 分支图

给定 A—B 为共同历史，main 有 C，feature 有 D—E。画引用与 HEAD，判断从 main 合并 feature 为何需要三方合并。说明删除 feature 名称与删除 D/E 对象不是同义动作。

## E. 冲突解决

main 规则为 `priority=urgent`，feature 为 `safety=always-urgent`。写出错误的单边选择会丢什么，设计保留双方意图的最终文件、cached diff 预言和两条回归测试。

## F. 远端边界

区分 remote、`origin/main`、本地 main。分别解释 fetch、merge、pull、push，指出 commit 成功、push 成功、CI 成功和部署成功为何是四种证据。

## G. ignore 与跟踪

`local.env` 已提交后才加入 `.gitignore`。预测 status，并解释 `git rm --cached -- local.env` 对 index、工作树、下一提交、旧历史的影响。设计 `local.env.example` 迁移，不包含秘密值。

## H. 凭据事件

真实 Token 出现在提交与 CI 日志。按分钟级优先级列出停止传播、撤销/轮换、范围评估、替换配置、当前树清理、历史协调和审计。说明为什么删除最新文件、ignore、关闭 PR 都不能替代轮换。

## I. 历史重写风险

列出提交 ID、分支、标签、PR、fork、已有克隆、签名和协作者重新同步会受到的影响。说明在什么前置条件下才升级给仓库管理员；不要写或执行具体重写命令。

## J. FactoryCare 需求变更

将普通工单阈值从 4 改为 5，同时保留安全告警一律紧急。设计两个小提交或一个完整提交的边界，给出冲突解决、测试和回滚证据；说明 Git 自动合并无冲突为何仍可能业务错误。

## K. AI 命令审查

AI 建议 `git add .`、强制推送、递归取消跟踪并把 remote URL/环境输出到日志。逐条指出范围、数据丢失、协作和秘密风险，改写为先观察、再获得授权、再执行最小路径的方案。

## L. 无 AI

限时 60 分钟独立完成 A—H，在一次性仓库复现 `MM`、一次冲突和一次 ignore 已跟踪失败。最后用 120 秒解释“为什么 Git 可恢复版本错误，却不能撤销凭据泄露”。
