# 教师用解析：`ch.java.program-structure`

> 本文件不进入公开书籍、站点或搜索索引。批改时先看学习者的预测、源码和日志，再按缺口揭示局部解析。

## 预测题要点

1. 输出依次为 `A`、`C`。注释不执行，也不会产生 `B`。
2. `commandLineArguments` 是标识符；参数名可以修改，只要 main 的固定参数类型和整体入口形状保持不变。
3. package 声明和两条方法调用语句以分号结束。由内到外的三个右花括号依次结束嵌套块、main 块、class 块。
4. 删除普通注释不改变完整类名、class 输出路径或预定运行输出。编译产生的二进制细节可能因调试信息而不同，因此不应承诺 class 文件字节完全相同；本题只判断结构路径和行为。

## 修改题要点

- 修改 main 参数名不改变入口匹配，也不改变输出。
- 普通缩进和空行不改变 token 序列，因此不改变预定行为。
- 修改字符串字面量会改变输出；重新编译后的 class 文件仍在同一 package/class 路径。

## 故障题要点

- 数字开头的 class 名在词法/语法处理阶段不能成为合法类型标识符。
- 缺分号和缺右花括号都是编译错误；后一种常在文件末尾显示“解析时已到达文件结尾”。
- 只改变 package 后，直接编译该文件可能成功，生成的 class 会按声明 package 放入输出目录；继续按旧完整类名启动时才会找不到主类。
- 实验脚本的 package/路径案例通过 `-sourcepath` 和另一个编译单元请求期待的完整类型，因而在编译阶段暴露“找到的源文件没有声明期待类型”。两种结果都是真实行为，不能把目录惯例误说成 Java 语法总会强制检查的规则。

## 独立题参考

参考源码位于本目录的 `src/com/factorycare/learning/RepairIntake.java`。批改时检查的结构事实：

- package 与完整类名一致；
- class、main、嵌套块三层花括号配对；
- 三条输出语句各有分号；
- 两类注释存在且不含秘密；
- `verify.sh` 退出码为 0，输出与 `expected-output.txt` 完全一致。
