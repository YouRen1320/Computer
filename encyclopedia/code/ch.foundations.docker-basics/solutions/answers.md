# 隔离解析：Docker 基础

完成公开练习并保存预测后再阅读。

## A

镜像是只读层组成的运行模板；容器是由镜像创建、以主进程为生命周期核心的运行实例，并有自己可写层。删除容器不删除镜像。无挂载数据随可写层丢失；named volume 或 bind mount 位于容器生命周期之外，是否删除取决于独立清理动作。

## B

先确认进程在容器内监听 8080 和正确地址，再看 `docker inspect`/`docker container port` 是否有 `127.0.0.1:18080→8080`，最后检查主机端口占用和防火墙。`EXPOSE` 是镜像元数据/约定，不自动创建主机端口映射。

## C

named volume 由 Docker 管理，适合容器生成的持久数据；bind mount 直接映射主机路径，适合主机与容器共同访问明确文件，但依赖主机目录并默认可能可写。把 `/` 可写挂入会扩大容器对宿主文件的修改能力，超出最小权限。

## D

`inspect` 的 Mounts.Destination 显示实际目标，应用日志显示写入路径，容器 diff/文件检查显示数据落在可写层。修复为应用路径与 mount target 完全一致，写入后替换容器并用同一 volume 复验。

## E

同一用户定义 bridge 上的容器可按名称解析并直接访问目标容器监听端口，不需要为了容器间通信把数据库端口发布给主机。容器内 `localhost` 指当前容器自身的网络命名空间，不代表 API/数据库伙伴。

## F

逐项清理影响最小且所有权清楚；`--rm` 适合退出即丢的临时容器，并对匿名卷有特定行为；全局 prune 会影响所有未使用资源，不适合共享开发机教学脚本。记录唯一前缀、创建成功标志、停止顺序和要保留的基础镜像/卷。

## G

未发布端口用 inspect/port 和主机请求定位；挂错路径用 Mounts.Destination 与应用写入路径对照；无卷丢失用替换前后文件证据确认。每次先预测失败，再修正一个边界，复跑原请求，最后只清理本次拥有的资源。
