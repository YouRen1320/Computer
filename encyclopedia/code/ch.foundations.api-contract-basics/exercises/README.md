# 练习：API 资源、错误、版本、分页、缓存与幂等语义
+
## 提交文件与同一验证入口

本目录已提供可编辑的 `submission.md`。先保留五个占位行运行 `./verify.sh`，确认得到精确的教材预期红；再把每个 `TODO：请替换本行。` 改成自己的预测、实验、失败证据、修复复跑和复述。

- `0` + `EXERCISE_GREEN`：五个栏目均有内容，机器只确认结构完成；
- `41` + `EXPECTED_RED`：仍是完整的公开 starter；
- `43`：文件缺失、只改了一部分占位行、标题损坏或其他未知状态，需要先读诊断，不能冒充预期红。

`EXERCISE_GREEN` 不批改答案含义，也不证明掌握；正文结论、命令输出与复述仍需教师或独立真人语义复核。

先独立回答，再查看私有解析。题目中的地址和标识都是文档值，不应实际请求。

## A. 资源与表示

1. “设备”与某次 JSON 表示有什么区别？
2. 为什么数据库行不应直接等同公开资源表示？
3. 为设备写最小稳定字段，并指出哪些内部字段不应公开。

## B. 稳定错误

未知异常包含 SQL、类名、文件路径和堆栈。设计一个 500 Problem，既能让客户端稳定分类，又不泄露实现。哪些信息只进内部日志？如何用关联标识连接两侧？

## C. 兼容版本

分别判断并说明迁移成本：新增可选字段、删除字段、字段改名、扩大枚举值、把整数改成字符串、改变 null 语义。不要只按“URL 版本号没变”判断。

## D. 分页漂移

原顺序为 `D,C,B,A`，第一页取两个；随后顶部插入 `E`。计算 offset=2 的第二页与 after-C 的第二页。哪一种重复？游标还需要哪些稳定排序与唯一性条件？

## E. 缓存验证器

首次 GET 得到 200、ETag `"abc"` 与 Body。再次请求携带相同验证器。写出命中时 status、ETag 和 Body 预期；解释 304 为什么不是空资源。

## F. 幂等重试

客户端提交创建请求后连接中断，不知道服务端是否已创建。比较：无键重试、同键同 payload、同键不同 payload。为每种情况写资源数量与响应预期。

## G. FactoryCare 变更

设备列表要新增 `location`，错误响应要隐藏内部异常，列表切换游标分页，创建工单支持安全重试。写一张契约迁移表，包含影响、客户端过渡、回滚和明确非目标。

## H. 无 AI

关闭 AI，限时 45 分钟完成 A—G。再运行公开验证器，故意制造字段改名和幂等冲突放宽两种故障，恢复后复跑。保留预测、失败输出、修复和最终 exit 0。
