# Java：String、数组与控制流

## 1. String：Java 中的文本

`String` 用来保存一段文本，例如设备编号、工单类别和状态名称。虽然它看起来很常用，但有几个规则需要先弄清：字符串和单个字符不是同一种类型；字符串方法通常会返回新结果；空字符串、空白字符串和 `null` 也不是一回事。

### 1.1 String 用来保存一段文字

下面的变量保存了一个设备编号：

```java
String deviceCode = "PUMP-01";
```

`String` 不是 `int`、`boolean` 这样的基本类型，它是 Java 提供的一个类。现在不用研究这个类的内部实现，只要先知道：`String` 变量用来引用一个字符串对象。

双引号表示一段字符串，单引号表示一个字符：

```java
String text = "A";
char letter = 'A';
```

虽然这两个例子看起来都只有一个字母，但类型不同。`"A"` 是 `String`，`'A'` 是 `char`，不能随意互换。

### 1.2 String 方法不会直接改掉原字符串

字符串创建以后，它本身的内容不能在原位置修改。这个特点叫作“不可变”。例如：

```java
String raw = "  pump-01  ";
String normalized = raw.strip().toUpperCase(java.util.Locale.ROOT);
```

这段代码会得到两个结果：

```text
raw        = "  pump-01  "
normalized = "PUMP-01"
```

执行过程是：

1. `strip()` 根据 `raw` 的内容产生一个去掉首尾空白的新字符串；
2. `toUpperCase(...)` 再根据上一步的结果产生一个大写的新字符串；
3. 最终的新字符串交给 `normalized` 保存；
4. `raw` 仍然保存原来的内容。

因此，只调用方法却不接住返回值是没有效果的：

```java
raw.strip();
raw.toUpperCase(java.util.Locale.ROOT);
```

这两行通常可以编译和运行，但 `raw` 不会发生变化。这属于逻辑错误：程序没有崩溃，结果却不是想要的结果。

### 1.3 空字符串和只有空格的字符串

下面两个值都不是 `null`，它们都是实际存在的字符串：

```java
String empty = "";
String blank = "   \t";
```

区别在于：`empty` 一个字符也没有，`blank` 中有空格或制表符。

| 检查方式 | `""` | `"   "` | 它在检查什么 |
| --- | --- | --- | --- |
| `length()` | 0 | 3 | 字符串长度 |
| `isEmpty()` | `true` | `false` | 长度是不是 0 |
| `isBlank()` | `true` | `true` | 是不是没有内容，或者只有空白 |

处理用户输入时，`isBlank()` 往往比 `isEmpty()` 更符合“没有填写有效内容”的意思，因为用户只输入几个空格也会被判断为空白。

更深入一点说，Java 的 `length()` 计算的是 UTF-16 存储单元数量，某些 Emoji 的显示字符数可能和它不完全一致。现阶段知道这个边界即可，需要处理复杂 Unicode 文本时再查询。

### 1.4 清理并统一机器编码

设备编号、状态码和类别名称经常需要先清理，再参与比较。例如，`"  safety "` 可以统一成 `"SAFETY"`：

```java
String normalized = raw
        .strip()
        .toUpperCase(java.util.Locale.ROOT);
```

这里做了两件事：

- `strip()` 去掉开头和结尾的空白；
- `toUpperCase(...)` 把字母统一成大写。

这种把不同写法整理成统一形式的过程，通常叫作“正规化”或“标准化”。它适合机器编码和固定状态，不代表所有文字都应该转成大写。用户姓名、留言等自然语言内容应该怎样处理，需要根据实际业务决定。

`Locale.ROOT` 表示使用不依赖某个国家或语言的大小写规则，可以避免程序部署到不同语言环境后，机器编码的转换结果发生变化。这个参数目前会使用、知道用途即可，不需要背它的内部规则。

### 1.5 split：把一段文本拆成多个部分

`split()` 可以根据分隔符把字符串拆成数组。例如，设备路径是 `PUMP.01`，希望按句点拆开：

```java
String route = "PUMP.01";
String[] fields = route.split("\\.");
```

结果中会有两个字符串：`"PUMP"` 和 `"01"`。

这里不能直接写 `split(".")`，因为 Java 的 `split()` 接收的不是普通文本分隔符，而是“正则表达式”。在正则表达式中，句点 `.` 表示“任意字符”，如果只想匹配普通句点，就要写成 `\.`。

Java 源码里又需要对反斜杠进行一次转义，所以最后看起来是两个反斜杠：

```text
Java 源码写 "\\."
        ↓ Java 先处理字符串转义
正则表达式收到 \.
        ↓ 正则把它理解为普通句点
最终按字符 . 分割
```

竖线 `|` 在正则中也有特殊含义，作为普通分隔符时同样需要转义：

```java
"PUMP.01".split("\\.");
"PUMP|01".split("\\|");
```

现阶段必须掌握的是：Java 的 `split()` 使用正则表达式，句点和竖线不能直接当作普通分隔符。更复杂的正则规则需要时再查。

### 1.6 为什么有时要写 split(..., -1)

默认情况下，`split(regex)` 会删除字符串末尾分割出来的空字段。例如：

```java
"PUMP.01.".split("\\.");
```

最后一个句点后面虽然没有内容，但默认结果中不会保留这个空位置。

如果文本协议规定“最后一列即使为空也有意义”，可以传入第二个参数 `-1`：

```java
String[] fields = "PUMP.01.".split("\\.", -1);
```

此时结果包含三个部分：`"PUMP"`、`"01"` 和 `""`。

这个 `-1` 不需要死记。只要知道默认分割可能删除末尾空字段；真正处理 CSV、固定格式文本或接口协议时，再根据格式要求决定是否保留。

### 1.7 什么时候用加号，什么时候用 StringBuilder

只拼接少量固定内容时，使用 `+` 最直观：

```java
String message = "device=" + deviceCode + ", priority=" + priority;
```

如果在循环中不断追加很多段文本，可以使用 `StringBuilder`：

```java
StringBuilder builder = new StringBuilder();
builder.append("PUMP");
builder.append('|');
builder.append("01");
String result = builder.toString();
```

`StringBuilder` 可以在同一个容器中不断追加内容，最后通过 `toString()` 得到普通字符串。现在只需要知道它适合“多次、逐步拼接”；不用为了猜测微小性能，把所有清楚的 `+` 都改成 `StringBuilder`。

这一节现在必须掌握的是：区分 `String` 和 `char`，接住字符串方法的返回值，并能判断 `null`、空字符串和空白字符串。`Locale.ROOT`、正则转义、保留尾部空字段和 `StringBuilder` 的细节目前理解用途、需要时查询即可。

## 2. 引用、同一个对象、相同内容与 null

理解字符串和数组时，经常会遇到两个看起来相似但实际不同的问题：两个变量保存的内容是否相同，以及它们是否指向同一个对象。Java 会把这两个问题分开处理。

### 2.1 基本类型变量和引用类型变量

基本类型变量直接保存一个简单值：

```java
int priority = 4;
boolean stopped = false;
```

可以把它们想成两个小盒子，盒子里分别放着数字 `4` 和布尔值 `false`。

`String`、数组以及以后会学习的普通对象属于引用类型：

```java
String category = "SAFETY";
int[] priorities = {2, 4, 5};
```

引用类型变量中保存的是一个“引用值”，程序通过这个引用找到真正的字符串或数组。初学时不需要计算真实内存地址，可以使用下面这个简单模型：

```text
category   ──> 字符串 "SAFETY"
priorities ──> 数组 [2, 4, 5]
```

也就是说，变量和对象不是同一个东西。变量保存引用，对象或数组是它指向的目标。

### 2.2 `==` 和 `equals()` 检查的不是同一件事

对基本类型使用 `==` 时，比较的是两个基本值：

```java
int firstPriority = 4;
int secondPriority = 4;
System.out.println(firstPriority == secondPriority); // true
```

对引用类型使用 `==` 时，检查的是两个变量是否指向同一个对象，而不是对象中的内容是否相同：

```java
String first = new String("SAFETY");
String second = new String("SAFETY");

System.out.println(first == second);      // false
System.out.println(first.equals(second)); // true
```

这里创建了两个不同的字符串对象，所以 `first == second` 是 `false`。但两个对象的文本内容都是 `SAFETY`，所以 `first.equals(second)` 是 `true`。

因此，比较字符串内容时应该使用 `equals()`，不要使用 `==`。

字符串字面量有时会被 JVM 复用，导致下面这种代码碰巧得到 `true`：

```java
String a = "SAFETY";
String b = "SAFETY";
System.out.println(a == b);
```

这不代表 `==` 可以用来比较文本。它只是碰巧指向同一个被复用的对象，业务代码不能依赖这种情况。

几种常见写法：

```java
first.equals(second);                   // first 不能是 null
"SAFETY".equals(category);              // category 可以是 null
java.util.Objects.equals(first, second); // 两边都可以是 null
```

`Objects.equals(null, null)` 会返回 `true`，但这只说明两个 Java 值都缺失。业务上是否应该把两个缺失值当成相等，仍然要看具体规则。

### 2.3 null、空字符串和文字 "null"

下面四种情况含义不同：

| 值 | 实际含义 | 能否调用字符串方法 |
| --- | --- | --- |
| `null` | 当前没有字符串对象 | 不能 |
| `""` | 有字符串对象，但长度为 0 | 可以 |
| `"   "` | 有字符串对象，但内容只有空白 | 可以 |
| `"null"` | 有字符串对象，内容是四个普通字符 | 可以 |

如果变量是 `null`，却直接调用它的方法：

```java
category.isBlank();
```

程序会在运行阶段抛出 `NullPointerException`。因此，要先检查对象是否存在，再调用它的方法：

```java
if (category == null || category.isBlank()) {
    throw new IllegalArgumentException("category is required");
}
```

这里使用 `||` 很重要。只要左边的 `category == null` 已经是 `true`，整个“或者”条件就已经成立，Java 不会继续执行右边的 `category.isBlank()`，因此避免了在 `null` 上调用方法。

这种“结果已经确定后，不再执行另一边”的行为叫作“短路”。后面的条件章节还会继续说明。

这一节现在必须掌握的是：基本类型的 `==` 比较值，引用类型的 `==` 检查是不是同一个对象，字符串内容使用 `equals()` 比较；还要明确 `null`、空字符串和空白字符串不是一回事。真实内存地址和 JVM 字符串池的内部实现目前不需要深入。

## 3. 一维数组：把一批同类型数据放在一起

数组适合保存一批类型相同的数据。例如，一次批量处理可能包含多个工单优先级，可以把它们统一放在一个 `int[]` 中，而不是分别声明很多个变量。

### 3.1 数组、元素和索引

下面的数组中保存了三个优先级：

```java
int[] priorities = {2, 4, 5};
```

数组中的每个位置叫作“元素”，访问位置时使用的编号叫作“索引”：

```text
索引                 0  1  2
元素                 2  4  5
priorities.length    3
```

Java 数组索引从 0 开始，所以：

- `priorities[0]` 是第一个元素，值为 2；
- `priorities[1]` 是第二个元素，值为 4；
- `priorities[2]` 是第三个元素，值为 5。

数组长度 `length` 表示元素数量，不是最后一个索引。长度为 3 的数组，最后一个索引是 2，也就是 `length - 1`。

### 3.2 创建数组的两种常见方式

如果只知道需要三个位置，还不知道每个位置的具体值，可以先创建固定长度的数组：

```java
int[] values = new int[3];
```

Java 会给元素填入默认值。`int` 数组的默认值是 0，所以当前内容相当于：

```text
[0, 0, 0]
```

如果创建时已经知道所有初始值，可以直接写出来：

```java
int[] priorities = {2, 4, 5};
String[] statuses = {"CREATED", "ASSIGNED"};
```

一个数组只能保存规定类型的元素。`int[]` 保存 `int`，`String[]` 保存字符串引用。

数组创建以后长度固定。可以修改某个元素：

```java
priorities[0] = 3;
```

但不能让原来的数组在原位置从 3 个元素扩展成 4 个元素。如果确实需要另一种长度，只能创建新数组。以后学习集合时，会接触能够自动扩展的容器。

### 3.3 数组使用 length，String 使用 length()

数组和字符串都能得到长度，但写法不同：

```java
int arraySize = priorities.length;
int textSize = text.length();
```

- 数组的 `length` 后面没有括号；
- 字符串的 `length()` 是方法，后面有括号。

这是 Java 本身的语法差异，不需要寻找更深的共同规则。写代码时让 IDE 补全即可，但阅读代码时要能区分。

### 3.4 索引为什么不能等于 length

数组的合法索引必须满足：

```text
0 <= index，并且 index < array.length
```

长度为 3 时，合法索引是 0、1、2。索引 3 已经越过数组末尾。

下面的代码可以通过编译，因为语法和类型都正确：

```java
int index = priorities.length;
System.out.println(priorities[index]);
```

但是程序真正运行到访问数组的位置时，会抛出 `ArrayIndexOutOfBoundsException`。这是运行阶段错误，不是编译错误。

### 3.5 怎样逐项读取数组

如果需要当前索引，可以使用普通 `for`：

```java
for (int i = 0; i < priorities.length; i++) {
    System.out.println("index=" + i + " value=" + priorities[i]);
}
```

这段代码从索引 0 开始，每轮把 `i` 加 1，只要 `i` 仍小于数组长度就继续。

如果只关心每一个值，不关心索引，可以使用增强 `for`：

```java
for (int priority : priorities) {
    System.out.println(priority);
}
```

它可以读成：“依次取出 `priorities` 中的每个值，本轮把它叫作 `priority`。”

要注意，增强 `for` 中的 `priority` 是一个本轮使用的局部变量。给这个变量重新赋值，不会修改数组原位置：

```java
for (int priority : priorities) {
    priority = 0;
}
```

循环结束后，原数组元素仍然不变。如果要修改数组中的指定位置，应该使用普通 `for` 和索引：

```java
for (int i = 0; i < priorities.length; i++) {
    priorities[i] = 0;
}
```

这一节现在必须掌握的是：数组索引从 0 开始，长度为 `length`，最后一个索引是 `length - 1`；还要能根据是否需要索引，选择普通 `for` 或增强 `for`。

## 4. 逐项处理数组：计数、最大值、查找和分布

把数组从头到尾看一遍，并在每个元素上执行同一套规则，通常叫作“扫描数组”。一次扫描可以用来计数、寻找最大值、查找某个元素，或者统计每种值出现了多少次。

### 4.1 统计符合条件的元素数量

如果要统计优先级大于等于 4 的工单数量，可以使用一个从 0 开始的计数变量：

```java
int urgentCount = 0;

for (int priority : priorities) {
    if (priority >= 4) {
        urgentCount++;
    }
}
```

执行过程是：

1. 还没有处理任何元素时，数量是 0；
2. 每次取出一个优先级；
3. 如果它大于等于 4，就把 `urgentCount` 加 1；
4. 循环结束后，`urgentCount` 就是紧急工单数量。

这种专门记录“发生了多少次”的变量通常叫作“计数器”。

### 4.2 寻找数组中的最大值

对一个非空数组，可以先把第一个元素当作目前的最大值，再检查后面的元素：

```java
int highest = priorities[0];

for (int i = 1; i < priorities.length; i++) {
    if (priorities[i] > highest) {
        highest = priorities[i];
    }
}
```

为什么循环从索引 1 开始？因为索引 0 的元素已经被放进 `highest` 作为第一个候选值，没有必要再和自己比较一次。

每遇到一个更大的值，就更新 `highest`。循环结束时，数组中的所有元素都已经比较过，所以 `highest` 保存最大值。

不要对任意整数数组随便把最大值初始化为 0。如果数组内容是 `{-8, -3, -5}`，真正的最大值是 -3，而从 0 开始会错误地得到 0。

这段写法还要求数组不能为空，因为它一开始就读取了 `priorities[0]`。空数组应该返回什么，需要提前规定。例如，FactoryCare 可以约定 0 表示“当前批次没有最高优先级”，也可以直接拒绝空数组。选择哪一种是业务规则，不是 Java 自动决定的。

### 4.3 查找第一个匹配的位置

合法索引从 0 开始，所以可以用 `-1` 表示“暂时没有找到”：

```java
int foundIndex = -1;

for (int i = 0; i < priorities.length; i++) {
    if (priorities[i] == 5) {
        foundIndex = i;
        break;
    }
}
```

如果找到了第一个优先级 5，就把它的索引保存到 `foundIndex`，然后用 `break` 结束循环。这里可以提前结束，是因为当前任务只需要“第一个 5 在哪里”，后面的元素不会改变这个答案。

如果循环还需要统计全部工单、计算最大值或记录每个优先级的数量，就不能在找到第一个 5 后立即 `break`。否则后面的元素没有被扫描，其他统计结果会不完整。

`-1` 在这里是一个不会和合法索引冲突的特殊值，这类用来表示“未找到”或“结束”的特殊值有时叫作“哨兵值”。理解用途即可，不需要背术语。

### 4.4 统计每个优先级出现了多少次

如果优先级只允许 1 到 5，可以用另一个数组保存每种优先级的数量：

```java
int[] distribution = new int[6];

for (int priority : priorities) {
    distribution[priority]++;
}
```

这里把优先级直接当作索引：

```text
distribution[1] → 优先级 1 的数量
distribution[2] → 优先级 2 的数量
...
distribution[5] → 优先级 5 的数量
distribution[0] → 有意不用
```

数组长度写成 6，是为了让索引 1 到 5 都存在。空出索引 0 可以让代码更直接，不必每次写 `priority - 1`。

这段代码有一个前提：每个 `priority` 都必须在 1 到 5 之间。如果数组中出现 6 或负数，直接把它当索引可能越界。因此，输入应该在进入统计前已经通过校验，或者统计方法自己明确拒绝非法值。

### 4.5 数据变多时，扫描需要多少工作

如果数组有 `n` 个元素，而程序从头到尾检查每个元素一次，那么数据增加一倍，检查次数大约也增加一倍。这种增长方式通常写作 `O(n)`，可以读成“线性时间”。

长度固定为 6 的 `distribution` 不会随着工单数量变大，因此它使用的额外空间可以看作固定大小，通常写作 `O(1)`。

如果四个方法分别扫描同一个数组，总检查次数可能接近 `4n`。从数学增长趋势看，它仍然属于 `O(n)`，但真实运行中当然还是做了四遍工作。是否把多个统计合并到一次循环，要综合考虑：

- 数据量是否真的很大；
- 一次循环里塞太多规则会不会难读；
- 多个结果应该怎样返回；
- 这些统计是否总是一起需要。

现阶段不需要为了大 O 符号强行合并所有循环。优先把规则写清楚，等真实数据规模或性能证据表明确有需要时再优化。

这一节现在必须掌握的是：能用循环完成计数、最大值和首次查找，并知道只有“后面的数据不会再影响目标结果”时才能提前结束扫描。`O(n)`、`O(1)` 和哨兵值的术语目前理解含义即可。

## 5. 两个变量可能指向同一个数组

数组属于引用类型。把一个数组变量赋值给另一个变量时，Java 不会自动复制所有元素，而是复制“怎样找到这个数组”的引用值。因此，两个变量可能操作的是同一个数组。

### 5.1 数组赋值不会创建新数组

看下面的代码：

```java
int[] first = {2, 4, 5};
int[] alias = first;
alias[0] = 3;
```

执行 `int[] alias = first` 后，可以画成：

```text
first ──┐
        ├──> 同一个数组 [2, 4, 5]
alias ──┘
```

`first` 和 `alias` 是两个不同的变量，但它们指向同一个数组。随后执行 `alias[0] = 3`，修改的是这个共享数组，所以通过 `first[0]` 读取到的也会是 3：

```text
first ──┐
        ├──> 同一个数组 [3, 4, 5]
alias ──┘
```

这种多个变量指向同一对象的情况有时叫作“别名”。术语不重要，重要的是能意识到：从任何一个变量修改共享数组，其他变量都能看到变化。

### 5.2 怎样得到一个独立数组

如果希望得到内容相同、但以后可以独立修改的基本类型数组，可以使用 `clone()`：

```java
int[] copy = first.clone();
copy[0] = 9;
```

这时是两个不同的数组：

```text
first ──> [3, 4, 5]
copy  ──> [9, 4, 5]
```

修改 `copy` 不会再影响 `first`。

如果数组中保存的是对象引用，`clone()` 只会复制每个位置中的引用，不会继续自动复制每个对象。这通常叫作“浅复制”。对象的深度复制属于后面的对象章节，现阶段知道这个边界即可。

### 5.3 null 数组和空数组不是一回事

下面两个变量表示不同状态：

```java
int[] absent = null;
int[] empty = new int[0];
```

- `absent` 表示当前没有数组对象，访问 `absent.length` 会抛出 `NullPointerException`；
- `empty` 指向一个真实存在的数组，只是长度为 0；
- 遍历 `empty` 时循环执行 0 次，这是安全的正常行为。

方法接收批量数据时，应该提前规定这些情况分别意味着什么。例如：

| 输入或结果 | 可以采用的明确规则 |
| --- | --- |
| 参数是 `null` | 调用方没有提供批次，直接拒绝 |
| 参数是空数组 | 合法批次，只是没有工单，数量为 0 |
| 空数组的最高值 | 返回 0、返回其他表示“没有”的值，或拒绝；必须提前约定 |
| 没有找到目标索引 | 返回 `-1` |

Java 只负责区分这些值，不会替业务决定它们的含义。

这一节现在必须掌握的是：数组变量赋值只复制引用，两个变量可能共享同一个数组；同时要区分 `null` 数组和长度为 0 的真实数组。对象数组的浅复制目前见过即可。

## 6. 二维数组：数组里面再放数组

二维数组可以理解为：外层数组中的每个位置，又指向一个内层数组。它适合表示“多行数据”，例如多个班次中分别有哪些员工。

```java
String[][] shifts = {
        {"Alice", "Bob"},
        {"Chen"},
        {"Diana", "Eric", "Frank"}
};
```

可以画成：

```text
shifts
  ├─ 第 0 行 → ["Alice", "Bob"]
  ├─ 第 1 行 → ["Chen"]
  └─ 第 2 行 → ["Diana", "Eric", "Frank"]
```

### 6.1 外层长度和每一行的长度

`shifts.length` 表示外层有多少行，每一行又有自己的 `length`：

```java
int rowCount = shifts.length;       // 3，外层有三行
int firstRowSize = shifts[0].length;  // 2，第 0 行有两个元素
int secondRowSize = shifts[1].length; // 1，第 1 行有一个元素
int thirdRowSize = shifts[2].length;  // 3，第 2 行有三个元素
```

Java 的二维数组不要求每一行长度相同，所以它不一定是整齐的长方形。访问 `shifts[2][1]` 时，可以分两步理解：

1. `shifts[2]` 先找到第 2 行；
2. `[1]` 再找到这一行中的第 1 个索引，也就是 `"Eric"`。

### 6.2 使用两层循环逐项读取

遍历二维数组时，外层循环负责行，内层循环负责当前行中的列：

```java
for (int row = 0; row < shifts.length; row++) {
    for (int column = 0; column < shifts[row].length; column++) {
        System.out.println(shifts[row][column]);
    }
}
```

内层条件必须使用当前行的 `shifts[row].length`。如果错误地假设每一行都和第 0 行一样长，遇到较短的行就可能越界，遇到较长的行又可能漏掉元素。

### 6.3 三种容易混淆的空状态

下面三种写法含义不同：

```text
new String[0][]        → 外层长度为 0，一行也没有
new String[][]{{}}     → 外层有一行，但这一行长度为 0
new String[][]{null}   → 外层有一个位置，但这个位置没有内层数组
```

第三种情况下，直接访问 `shifts[0].length` 会抛出 `NullPointerException`，因为第 0 行本身是 `null`。

现阶段只需要建立一个核心认识：二维数组的外层和每一个内层数组都有自己的长度与空值边界。本章不进行矩阵运算，也不要求记住复杂的多维数组写法。

## 7. if/else：根据条件选择要执行的代码

程序默认从上到下执行。`if`、`else` 和 `else-if` 可以让程序根据条件选择不同路径，例如判断工单是否紧急、设备是否停机，或者输入是否合法。

### 7.1 条件最终必须得到 boolean

Java 中的条件必须得到 `true` 或 `false`，也就是 `boolean`：

```java
priority >= 4
category == null
affectedUsers >= 20 && machineStopped
```

这些表达式分别在询问：

- 优先级是否大于等于 4；
- 类别是否为 `null`；
- 受影响人数是否至少 20，并且设备是否已经停机。

Java 不会自动把数字、字符串或对象当作真假值。下面的写法不能编译：

```java
if (priority) {
}
```

因为 `priority` 是 `int`，不是 `boolean`。必须把它写成一个明确的问题，例如 `priority >= 4`。

### 7.2 &&、|| 和 ! 怎样组合条件

三个常用逻辑操作符是：

```java
&& // 并且：左右两边都为 true，结果才为 true
|| // 或者：至少一边为 true，结果就为 true
!  // 取反：把 true 变成 false，把 false 变成 true
```

例如，只有“受影响人数至少 20”并且“设备已经停机”同时成立时，下面的条件才成立：

```java
affectedUsers >= 20 && machineStopped
```

`&&` 和 `||` 还有一个重要行为：当左边已经足够确定最终结果时，Java 不会继续执行右边。这叫作“短路”。

```java
if (category != null && !category.isBlank()) {
    System.out.println("category is valid");
}
```

如果 `category != null` 是 `false`，整个“并且”条件一定为 `false`，Java 不会执行右边的 `category.isBlank()`，因此不会在 `null` 上调用方法。

短路不只是为了少执行一次代码，它经常用来保证右边的操作是安全的。阅读这类条件时，要从左到右看：前面的检查是否在保护后面的调用。

### 7.3 if、if/else 和 else-if 分别适合什么

只有条件成立时才做一件额外的事，可以使用单独的 `if`：

```java
if (priority >= 4) {
    urgentCount++;
}
```

必须在两个结果中选择一个，可以使用 `if/else`：

```java
if (machineStopped) {
    priority = 5;
} else {
    priority = 2;
}
```

有多个结果时，可以使用 `else-if`：

```java
if (priority == 5) {
    level = "CRITICAL";
} else if (priority >= 3) {
    level = "HIGH";
} else {
    level = "ROUTINE";
}
```

`else-if` 会从上到下检查条件，一旦找到第一条为 `true` 的分支，就执行这一条，并跳过后面的分支。

因此，条件顺序本身就是规则的一部分。输入 5 同时满足 `priority == 5` 和 `priority >= 3`。上面的代码先检查更特殊的 `== 5`，所以结果是 `CRITICAL`。如果把 `priority >= 3` 放到前面，输入 5 会提前得到 `HIGH`，后面的 `== 5` 永远没有机会执行。

这种前面的宽条件让后面的特殊条件无法执行的情况，通常叫作“条件遮蔽”。不需要背术语，但要记住：`else-if` 只采用第一条成立的规则。

### 7.4 先处理不能继续的输入

如果某种输入根本不应该进入后面的正常流程，可以在方法开头先处理：

```java
if (priority < 1 || priority > 5) {
    throw new IllegalArgumentException("invalid priority");
}
```

只要优先级小于 1 或大于 5，程序就在这里拒绝它，后面的代码便可以直接按照“优先级已经是 1 到 5”来编写。

这种把非法或无法继续的情况放在前面处理的写法叫作 `guard clause`，中文常译为“守卫子句”。它的作用不是让代码显得高级，而是尽早结束错误路径，避免把正常逻辑包在很多层嵌套中。

只有当这条路径真的不应继续时，才适合抛异常或提前返回。如果两个分支后面还需要共同执行其他代码，普通 `if/else` 可能更清楚。

这一节现在必须掌握的是：Java 条件必须是 `boolean`，能用 `&&`、`||` 和 `!` 组合条件，知道 `else-if` 只执行第一条成立的分支，并能先拒绝非法输入。短路、条件遮蔽和 `guard clause` 的名称理解即可。

## 8. switch：根据一个值选择不同结果

`switch` 解决的是一种很常见的问题：程序先查看一个值，再根据这个值选择对应的结果。

例如，工单类别可能是 `SAFETY`、`PRODUCTION` 或 `GENERAL`。不同类别需要得到不同的基础优先级。这时使用 `switch`，通常比连续写很多个“是否等于”的 `if` 更容易阅读。

### 8.1 switch 是怎样选择结果的

下面的代码根据工单类别计算优先级：

```java
int priority = switch (normalizedCategory) {
    case "SAFETY" -> 4;
    case "PRODUCTION" -> 3;
    case "GENERAL" -> 2;
    default -> throw new IllegalArgumentException("unknown category");
};
```

它的执行过程是：

1. 先查看 `normalizedCategory` 当前保存的内容；
2. 如果是 `SAFETY`，整个 `switch` 得到结果 `4`；
3. 如果是 `PRODUCTION`，得到 `3`；
4. 如果是 `GENERAL`，得到 `2`；
5. 如果前面的值都没有匹配，就执行 `default`。

这里的整个 `switch` 会产生一个 `int` 结果，然后把结果赋值给 `priority`。因为外面是一条完整的赋值语句，所以最后需要写分号。

有些资料会把这种情况称为“一个值与有限标签匹配”。这里的“有限标签”并不神秘，指的就是 `case` 后面这些提前知道的固定选项。

### 8.2 什么情况适合 switch

当判断始终围绕同一个变量，而且需要比较的是几个固定值时，适合使用 `switch`。常见例子包括：

- 工单类别对应基础优先级；
- 工单状态对应下一步操作；
- 用户选择的菜单编号对应一个功能。

如果判断的是数值范围，或者条件同时涉及多个变量，通常使用 `if` 更自然：

| 要处理的问题 | 更适合的写法 |
| --- | --- |
| 类别是 `SAFETY`、`PRODUCTION` 还是 `GENERAL` | `switch` |
| 优先级是否在 1 到 5 之间 | `if` |
| 设备已停机并且受影响人数超过 20 | `if` |
| 非法输入需要立即拒绝 | `if`，然后抛出异常或提前返回 |

不要因为 `switch` 看起来更特别就强行使用它。选择 `if` 还是 `switch`，只看哪一种更能直接表达当前规则。

### 8.3 新代码常用箭头写法

下面的 `switch` 根据工单状态得到下一步操作：

```java
String action = switch (status) {
    case "CREATED" -> "WAIT";
    case "ASSIGNED", "IN_PROGRESS" -> "WORK";
    case "CLOSED" -> "ARCHIVE";
    default -> "REJECT_UNKNOWN";
};
```

这段代码中：

- `CREATED` 对应 `WAIT`；
- `ASSIGNED` 和 `IN_PROGRESS` 都对应 `WORK`，所以它们可以写在同一个 `case` 中；
- `CLOSED` 对应 `ARCHIVE`；
- 其他状态对应 `REJECT_UNKNOWN`。

箭头右边就是这一种情况的结果。执行完匹配的分支后，不会自动继续执行下面的分支，因此这种写法不需要 `break`。

### 8.4 旧代码中的冒号和 break

在旧代码中，还会看到 `case "CREATED":` 这种冒号写法。使用这种写法时，一个分支执行完以后可能继续执行下一个分支，因此通常需要用 `break` 停下来。

如果本来只想执行一个分支，却因为漏写 `break` 而继续执行了后面的分支，这种现象叫作 `fallthrough`，可以理解为“从当前分支继续掉进下一个分支”。

现阶段不需要专门练习这种旧写法，只要以后阅读旧代码时能认出来即可。自己写新代码时，优先使用前面的箭头形式。

### 8.5 default：没有匹配时怎么办

`default` 表示：如果前面的 `case` 全部没有匹配，就执行这里。

对于未知工单类别，可以直接拒绝：

```java
default -> throw new IllegalArgumentException("unknown category");
```

也可以返回一个明确表示“未知状态”的结果：

```java
default -> "REJECT_UNKNOWN";
```

关键不在于一定要抛异常还是返回文本，而在于不能悄悄把未知值当成正常值。例如，把未知状态直接当成 `WORK`，程序虽然可以运行，但业务结果可能是错的。

编译器只能检查这段代码能不能产生结果，并不知道公司实际允许哪些工单类别。因此，合法类别有哪些，仍然需要由业务规则明确规定。

### 8.6 “至少为 4”表示不能低于 4

工单规则有时会写成：“如果影响人数达到标准，优先级至少为 4。”这不是在原来的优先级上加 1，而是在原值和 4 之间选择较大的那个：

```java
priority = Math.max(priority, 4);
```

如果原来的优先级是 2，结果会变成 4；如果原来已经是 5，结果仍然是 5。这样可以提高过低的优先级，又不会把 5 错误地加成 6。

这一节现在必须掌握的是：能看懂箭头形式的 `switch`，并知道它适合根据同一个变量的几个固定值选择结果。传统冒号形式和 `fallthrough` 目前见过、能认出即可。

## 9. 循环：让同一段代码重复执行

循环的作用是重复执行一段代码。例如，一个数组中有很多张工单，程序需要逐张读取；或者一个操作最多允许尝试三次。没有循环时，只能把相同代码复制很多遍，而且数据数量一变，代码也要跟着改。

### 9.1 理解循环时先问五个问题

看到一个循环时，可以先不管具体语法，依次回答下面五个问题：

1. 从什么状态开始？
2. 满足什么条件时还要继续？
3. 每一轮具体做什么？
4. 哪个值会在每一轮发生变化，让循环最终停下来？
5. 循环结束后，可以确定什么结果？

第四个问题尤其重要。如果循环条件一直为真，相关变量又不变化，而且没有其他退出语句，循环就会一直执行下去，也就是通常所说的无限循环。

### 9.2 for：适合遍历数组或执行固定次数

下面的代码从头到尾读取 `priorities` 数组：

```java
for (int i = 0; i < priorities.length; i++) {
    process(priorities[i]);
}
```

这里的 `process(...)` 只是代表“处理当前元素”的方法名。这一小段主要用来观察循环顺序，不需要先了解这个方法里面的代码。

可以按下面的顺序理解它：

1. `int i = 0`：从数组的第一个位置开始，只执行一次；
2. `i < priorities.length`：每一轮开始前，判断 `i` 是否仍是合法索引；
3. `process(priorities[i])`：处理当前位置的元素；
4. `i++`：本轮结束后，把 `i` 加 1，移动到下一个位置；
5. 再次检查 `i < priorities.length`，决定是否继续。

数组索引从 0 开始，最后一个索引是 `length - 1`，因此判断条件写成 `i < priorities.length`，不能写成 `i <= priorities.length`。

如果循环处理的不是数组索引，而是业务编号 1、2、3……N，起点和结束条件可能会写成 `int number = 1; number <= n; number++`。所以选择 `<` 还是 `<=` 之前，先弄清楚这个变量代表“数组位置”还是“业务编号”。

边界少执行一次或多执行一次，通常称为“差一错误”（off-by-one）。它往往不会造成编译错误，只会悄悄得到错误结果。

### 9.3 增强 for：只关心每一个值

如果只想逐项读取数组，不需要知道当前索引，可以使用更简洁的增强 `for`：

```java
for (int priority : priorities) {
    process(priority);
}
```

它可以读成：“依次取出 `priorities` 中的每一个值，暂时叫作 `priority`，然后处理它。”

需要当前索引、需要修改数组中指定位置，或者需要比较前后元素时，普通 `for` 会更合适。

### 9.4 while：满足条件就继续

`while` 适合“只要某个条件成立就继续”的情况。执行次数通常由状态怎样变化来决定，不一定直接写在循环开头。

```java
int remainingAttempts = 3;

while (remainingAttempts > 0) {
    tryOnce();
    remainingAttempts--;
}
```

这里的 `tryOnce()` 代表“尝试一次操作”。

每轮开始前，程序先检查 `remainingAttempts > 0`。如果为 `true`，就尝试一次，再把剩余次数减 1；如果为 `false`，就结束循环。

因为 `while` 会先判断，所以 `remainingAttempts` 一开始就是 0 时，循环一次也不会执行。

如果忘了写 `remainingAttempts--`，剩余次数会一直是 3，条件也会一直为 `true`，程序就无法正常停下来。因此阅读 `while` 时，要特别检查：让循环停止的变量到底在哪里更新。

### 9.5 do-while：先做一次，再决定是否继续

`do-while` 和 `while` 的主要区别是判断顺序。`do-while` 会先执行一次循环体，然后才检查条件：

```java
int attempts = 0;

do {
    attempts++;
    tryOnce();
} while (attempts < 3);
```

因此，无论条件一开始是否成立，循环体都至少会执行一次。它适合“菜单至少展示一次”或者“操作至少尝试一次”这样的需求。

如果业务允许一次都不处理，例如空数组中没有任何工单，那么 `for` 或 `while` 更合适。还要注意，`do-while` 最后一行的右括号后面有一个分号。

### 9.6 分清次数、总和以及让循环停止的值

循环中经常会同时出现几种变量：

| 变量作用 | 回答的问题 | 常见更新方式 |
| --- | --- | --- |
| 记录次数 | 已经处理了多少项？ | `count++` |
| 记录总和 | 已处理数据加起来是多少？ | `total += currentValue` |
| 控制循环结束 | 还剩多少次，或者下一个位置在哪里？ | `remaining--`、`i++` |

记录次数的变量通常称为“计数器”，记录总和的变量通常称为“累加器”。让循环一步步靠近停止条件的变量，有时称为“终止量”。这些名称不需要死记，关键是不要混淆它们的作用。

例如，把本来应该写成 `total += priority` 的代码写成 `total++`，得到的只是元素数量，不是优先级总和。只更新 `count`，却不更新 `remaining`，则可能导致循环一直不结束。

### 9.7 怎么判断循环目前算得对不对

阅读循环时，可以用一句话说明：“执行到这里，哪些数据已经处理完，当前结果代表什么。”例如：

```text
urgentCount 等于已经处理过的元素中，priority >= 4 的数量；
i 指向下一项还没有处理的数组位置。
```

假设当前已经处理完数组的前 3 项，那么 `urgentCount` 就应该只统计这 3 项中的紧急工单，不能提前统计后面的内容，也不能漏掉前面的内容。

这种在循环执行过程中始终应该成立的说明，专业名称叫作“循环不变量”。它不是 Java 语法，也不是需要背诵的固定句子，而是一种检查思路：用它判断计数写错了位置、某个分支漏了更新，或者循环结束后的结果是否可信。

这一节现在必须掌握的是：知道什么时候选择 `for`、`while` 和 `do-while`，能看懂数组循环的索引范围，并能找到让循环最终停下来的变量。“循环不变量”和“终止量”这些名称目前理解含义即可。

## 10. break、continue 和 return：改变执行方向

这三个关键字都会让程序不再按照原来的顺序继续执行，但它们影响的范围不同：

| 关键字 | 它会做什么 | 接下来从哪里继续 |
| --- | --- | --- |
| `continue` | 跳过当前这一轮剩余代码 | 进入循环的下一轮 |
| `break` | 结束当前循环 | 执行循环后面的代码 |
| `return` | 结束当前整个方法 | 回到调用这个方法的位置 |

### 10.1 break：提前结束当前循环

下面的代码只查找第一个优先级 5 的索引：

```java
int foundIndex = -1;

for (int i = 0; i < priorities.length; i++) {
    if (priorities[i] == 5) {
        foundIndex = i;
        break;
    }
}
```

找到第一个 5 后，`foundIndex` 已经不会再被后面的数据改变，所以可以用 `break` 结束循环。程序随后继续执行循环后面的代码。

`break` 只结束当前循环。如果这里改成 `return i`，结束的就会是包含这段循环的整个方法，两者影响范围不同。

能不能提前结束，要看循环的完整职责：

- 只查找第一个 5：找到后可以 `break`；
- 还要统计所有工单数量：不能提前结束；
- 还要计算后半段中的最大值：不能提前结束。

### 10.2 continue：跳过当前这一项

如果只想忽略当前元素，但还要继续处理后面的元素，可以使用 `continue`：

```java
for (String label : labels) {
    if (label == null || label.isBlank()) {
        continue;
    }

    process(label);
}
```

当 `label` 是 `null` 或空白字符串时，程序跳过本轮剩余的 `process(label)`，然后读取数组中的下一个元素。这里的 `process(...)` 只是代表“处理有效标签”的方法。

普通 `for` 执行 `continue` 后，仍然会执行循环头中的 `i++` 等更新操作。但 `while` 没有自动更新位置，如果把必要更新写在 `continue` 后面，可能一直停在同一个状态：

```java
while (remaining > 0) {
    if (remaining == 2) {
        continue;
    }

    remaining--;
}
```

当 `remaining` 等于 2 时，`continue` 会不断跳过 `remaining--`，所以循环无法结束。问题不是 `continue` 本身，而是回到下一轮之前没有更新控制条件的变量。

### 10.3 return：结束当前整个方法

如果一个方法的结果已经确定，可以直接使用 `return` 返回：

```java
static int findFirstCritical(int[] priorities) {
    for (int i = 0; i < priorities.length; i++) {
        if (priorities[i] == 5) {
            return i;
        }
    }

    return -1;
}
```

一旦执行 `return i`，整个 `findFirstCritical` 方法立即结束，方法中后面的代码不会再执行。如果循环全部结束也没找到 5，就执行最后的 `return -1`。

`return` 结束的是当前方法，不是自动关闭整个 JVM。被调用的方法返回后，调用它的方法会从调用位置继续。只有当 `main` 返回，并且没有其他需要继续运行的线程时，当前普通命令行程序才会随之结束。

这一节现在必须掌握的是：`continue` 跳过一轮，`break` 结束循环，`return` 结束方法；还要根据当前任务是否需要后续数据，判断能不能提前离开。

## 11. 方法：给一段代码明确的职责

方法可以把一段有明确用途的代码命名并封装起来。阅读一个方法时，可以先看三个部分：它接收什么输入、内部负责做什么、最终返回什么结果或执行什么动作。

```text
参数输入 → 方法执行自己的职责 → 返回结果或完成动作
```

### 11.1 一个方法最好能用一句话说明

下面的方法只负责判断一个优先级是否紧急：

```java
static boolean isUrgent(int priority) {
    return priority >= 4;
}
```

可以用一句话描述它：“根据一个优先级，返回它是否大于等于 4。”

方法不一定只能写一行，但职责应该清楚。常见的合理拆分是：

- 一个方法读取或接收输入；
- 一个方法把文本转换成数字；
- 一个方法执行优先级规则；
- 一个方法输出最终结果。

不要机械地把每一行代码都抽成单独方法，也不要把读取输入、转换、计算、打印和退出全部塞进一个难以说明的万能方法。判断标准是：这个方法能不能用一句清楚的话说明，而且调用者是否容易理解它的输入和结果。

### 11.2 return 和 void 的区别

方法需要把计算结果交给调用者时，在方法名前声明返回类型，并使用 `return`：

```java
static int increasePriority(int priority) {
    return priority + 1;
}
```

调用者可以接住这个结果：

```java
int increased = increasePriority(3);
```

如果方法只负责执行动作，不需要返回业务值，可以使用 `void`：

```java
static void printPriority(int priority) {
    System.out.println("priority=" + priority);
}
```

`void` 可以理解为“这个方法没有需要交回的结果值”。打印、写文件和发送请求都会产生外部动作，但不一定需要返回一个业务结果。

只要方法声明了返回类型，例如 `int`，所有能够正常走到方法结尾的路径都必须返回兼容的值：

```java
static int normalize(int priority) {
    if (priority > 5) {
        return 5;
    }

    return priority;
}
```

如果存在一条正常路径没有 `return`，编译器会直接报错。

### 11.3 Java 的参数永远按值传递

调用方法时，Java 会把实参当前保存的值复制给形参。这叫作“按值传递”。

对基本类型来说，复制的是基本值：

```java
static void increase(int value) {
    value++;
}
```

如果调用者原来有：

```java
int priority = 3;
increase(priority);
```

方法中的 `value` 得到数字 3 的副本。把 `value` 改成 4，不会把调用者的 `priority` 一起改掉。

对数组来说，复制的是引用值：

```java
static void changeFirst(int[] values) {
    values[0] = 5;
}
```

调用者变量和形参是两个不同变量，但两个变量中保存的引用都指向同一个数组：

```text
调用者变量 ──┐
             ├──> 同一个数组
形参 values ─┘
```

因此，通过 `values[0]` 修改共享数组元素，调用者可以看到变化。

但是，给形参重新赋值只会改变形参自己的引用：

```java
static void replaceLocally(int[] values) {
    values = new int[]{9, 9};
}
```

这不会让调用者的变量改为指向新数组。稳定、准确的说法是：“Java 始终按值传递；数组参数传递时，复制的值恰好是一个引用。”不要把它说成“Java 的数组按引用传递”。

### 11.4 把计算代码和输入输出代码分开

下面这种方法只根据参数计算结果，不读取控制台，也不直接打印：

```java
static long calculateTotalCents(long unitPriceCents, int quantity) {
    return Math.multiplyExact(unitPriceCents, quantity);
}
```

它具有一个容易理解的特点：同样的输入会得到同样的结果。测试和复用时，只需要传入参数并检查返回值。

程序入口可以负责外部交互：

```text
main 读取命令行文本
  → 解析成数字
  → 调用计算方法
  → 输出结果或错误
```

把计算规则和控制台、文件、网络等外部操作分开，可以让每个部分更容易理解和验证。只依赖参数并返回计算结果的方法，通常称为“纯计算方法”；打印、写文件等会改变程序外部可观察状态的操作，通常称为“副作用”。术语理解即可，重点是职责分开。

这一节现在必须掌握的是：能从方法签名看出参数和返回类型，区分 `return` 与 `void`，并准确解释“Java 按值传递，数组复制的是引用值”。纯计算和副作用的术语目前理解用途即可。

## 12. 方法重载和递归：两个需要区分的概念

方法重载和递归都与“方法调用”有关，但它们解决的问题完全不同：重载是让同一个方法名支持几种清楚的输入形式；递归是一个方法在执行过程中再次调用自己。

### 12.1 方法重载：同一个名字，不同参数

如果两个方法表达的是同一个概念，但接收的参数数量或类型不同，可以使用相同的方法名：

```java
static String formatTicket(int id) {
    return "ticket=" + id;
}

static String formatTicket(int id, String status) {
    return "ticket=" + id + ", status=" + status;
}
```

调用时，编译器会根据方法名、参数数量和参数类型选择对应版本：

```java
formatTicket(10);
formatTicket(10, "CREATED");
```

这种“方法名相同，但参数列表不同”的写法叫作“方法重载”。参数列表不仅包括参数数量，也包括参数类型和顺序。

只改变返回类型不能形成重载：

```java
static int parse(String text) {
    return Integer.parseInt(text);
}

static long parse(String text) { // 编译失败
    return Long.parseLong(text);
}
```

调用者只写 `parse("10")` 时，编译器无法根据希望得到 `int` 还是 `long` 来区分这两个方法，所以这种声明不合法。

重载适合同一个概念的清楚变体。如果两个方法职责不同，只是碰巧参数不同，使用不同名字通常更容易理解。

### 12.2 递归：方法调用自己

下面的方法会在 `remaining` 大于 0 时再次调用自己：

```java
static int countdownSteps(int remaining) {
    if (remaining <= 0) {
        return 0;
    }

    return 1 + countdownSteps(remaining - 1);
}
```

调用 `countdownSteps(3)` 时，可以简单理解成：

```text
countdownSteps(3)
  → 1 + countdownSteps(2)
  → 1 + 1 + countdownSteps(1)
  → 1 + 1 + 1 + countdownSteps(0)
  → 3
```

递归必须同时满足两个条件：

1. 有一种输入会直接返回，不再继续调用自己；这叫作“基线条件”或“终止条件”；
2. 每次调用都要更靠近这个终止条件，例如这里每次把 `remaining` 减 1。

如果没有终止条件，或者每次调用反而离终点越来越远，方法会不断增加新的调用层，最终可能抛出 `StackOverflowError`。

简单计数和普通数组遍历通常使用循环更直接。递归更适合树、文件夹层级等天然嵌套结构。Week 02 只需要能看懂最小递归，并知道它必须有终止条件；不要求用递归替代已经清楚的循环。

这一节现在必须掌握的是：知道重载依靠不同参数列表，返回类型不能单独区分重载。递归目前属于见过即可，重点只放在终止条件和每次调用必须靠近终点。

## 13. 调试：先找最早出现问题的位置

调试不是从头猜代码哪里不对，而是先判断问题发生在哪个阶段，再寻找最早、最具体的证据。越接近问题起点的信息，通常越有用。

### 13.1 先判断程序在哪个阶段失败

常见现象可以分成下面几类：

| 现象 | 问题发生在哪里 | 程序是否真正运行 |
| --- | --- | --- |
| 主代码编译失败 | Maven 的 `compile` 或 `javac` 阶段 | 否 |
| 测试代码编译失败 | Maven 的 `testCompile` 阶段 | 业务代码可能已编译，但测试没有执行 |
| 出现异常堆栈 | JVM 运行阶段 | 是 |
| 测试显示 expected 和 actual 不同 | 测试执行阶段 | 是 |
| 没有异常，但输出结果错误 | 业务逻辑 | 是，甚至可能没有测试发现它 |

日志最后的 `BUILD FAILURE` 只是在说“整个构建失败了”，它不是最具体的原因。真正应该优先寻找的是：

- 编译器指出的项目文件、行号和错误内容；
- 异常堆栈中第一条属于自己项目代码的位置；
- 测试断言中的预期值 `expected` 和实际值 `actual`；
- 实际业务结果第一次与手算规则不同的位置。

这些最早能直接说明偏差发生在哪里的信息，可以称为“第一处可信证据”。这个说法的重点是：先找最早、最具体的错误位置，不要只盯着日志最后的失败总结。

### 13.2 断点：让程序在指定位置暂停

断点会让程序运行到某一行时暂停。暂停后可以查看：

- 方法参数当前是什么；
- 局部变量当前是什么；
- 数组中保存了哪些值；
- 当前进入了哪个条件分支；
- 是哪些方法一步步调用到这里。

断点只负责暂停和观察，不会修改规则，也不会自动修复问题。

比较有价值的断点位置通常是：

- 第一次进入错误业务路径的位置；
- 决定分支结果的重要条件；
- 产生错误结果的计算表达式；
- 即将调用可疑方法的位置。

不要看到程序很长就到处打断点。先提出一个具体问题，例如：“执行这一行后 `urgentCount` 应该从 1 变成 2 吗？”然后把断点放在能验证这个判断的位置。

### 13.3 Step Over、Step Into、Step Out 和 Resume

程序暂停后，IntelliJ 常用的几个操作是：

| 操作 | 通俗理解 |
| --- | --- |
| Step Over | 执行当前行；如果当前行调用了方法，不进入方法内部 |
| Step Into | 进入当前行调用的方法，查看里面怎样执行 |
| Step Out | 继续执行当前方法，直到它返回调用者 |
| Resume | 继续正常运行，直到下一个断点或程序结束 |

如果只是想知道 `calculatePriority(...)` 返回了什么，可以先用 Step Over。如果怀疑错误就在 `calculatePriority(...)` 内部，再使用 Step Into。

不要无目的地进入所有 JDK 或框架内部方法。调试的目标是验证自己的判断，而不是把每一行底层代码都走一遍。

### 13.4 调用栈：程序是怎样走到这里的

假设当前暂停在 `calculatePriority` 中，调用关系可能是：

```text
main
  → printPriority
      → calculatePriority
```

这条调用路径叫作“调用栈”。它能回答：当前方法是谁调用的，上一层又是谁调用的。

每一次方法调用都有自己的一组参数、局部变量和当前执行位置。调试器通常把这一层信息叫作一个 `frame`，可以理解为“这一次方法调用的现场”。

在调试器中切换不同 `frame`，只是查看不同调用层的变量，不会让程序真的倒退。面对异常堆栈时，通常先找到第一条属于自己项目的调用层，再从那里检查输入和规则，而不是先研究大量 JDK 内部调用。

### 13.5 找到原因后先做最小修复

如果已经发现第一个错误是边界写成了 `i <= priorities.length`，先只把它修正为 `<`，再用原输入重新运行。

一次同时升级依赖、重写结构、修改业务规则和改测试，会让人无法判断究竟是哪一项解决了问题，也可能引入新的错误。可靠的过程是：

```text
找到第一处偏差
  → 只修改恢复原规则所需的代码
  → 使用同一个失败输入复跑
  → 再运行受影响的其他验证
```

“最小修复”不是永远拒绝重构，而是在诊断阶段先建立明确因果关系。确认问题已经解决后，如果结构确实需要改善，再把重构当作单独工作处理。

这一节现在必须掌握的是：先区分编译、测试编译、运行异常、断言失败和逻辑错误；能使用断点、Step Over 和 Step Into 查看变量；并从异常或调用栈中先找自己项目的第一条相关位置。`frame` 等英文术语能认出即可。
