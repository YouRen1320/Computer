# 机器学习：数据、监督学习、无监督学习与评估

## 1. 机器学习先从业务决策开始

不要先问“用什么模型”，先写清：

```text
谁在什么时候做什么决定？
可用哪些当时已经存在的信息？
模型输出怎样改变行动？
错一次的代价是什么？
什么情况必须交给人工？
```

若输出不会改变任何行动，训练出更高分的模型也没有实际价值。

## 2. 预测时刻决定哪些数据可以使用

假设目标是“工单创建时预测是否会超时”，那么工单关闭后的处理时长、最终负责人和结案备注都属于未来信息，训练时不能使用。

每个特征都要问：在真实预测时刻，这个值是否已经产生并能稳定获得？

## 3. 样本单位必须明确

一行可以代表一张工单、一台设备的一天、一次传感器读数或一个用户会话。样本单位不同，标签、划分和独立性假设都会不同。

同一设备的多条记录往往高度相关，不能假装每一行都是完全独立的新样本。

## 4. 标签是要学习的目标定义

```text
回归标签：最终维修时长（小时）
分类标签：是否超过 SLA
多分类标签：故障类型
```

标签应包含计算规则、时间窗口、来源、成熟时间和缺失处理。标签定义不稳定，模型学到的目标也会漂移。

## 5. 特征是预测时可用的输入信息

特征不等于数据库里的所有列。ID、审计字段、结案结果和人工决定可能造成泄漏；敏感属性还涉及公平、合法性和最小使用原则。

为每个特征记录名字、含义、类型、单位、产生时间、来源、缺失率和允许用途。

## 6. 数据集合同应能被版本化

一次实验至少关联：

- 数据快照或不可变查询版本；
- 样本和标签定义；
- 特征 Schema；
- 划分清单；
- 清洗规则；
- 代码、依赖和配置版本。

仅记录随机种子无法重建后来已经变化的源数据。

## 7. 训练集、验证集和测试集职责不同

```text
训练集：拟合模型参数和预处理参数
验证集：选择模型、阈值和超参数
测试集：最后一次评估已冻结方案
```

反复查看测试集并据此改模型，测试集事实上已经变成验证集。最终结论会过于乐观。

## 8. 随机划分只适合样本近似独立的情况

随机划分能保持总体混合，但同一实体、同一事件派生行或时间相邻记录可能跨集合，造成信息泄漏。

划分前先看数据生成过程，而不是默认调用一个随机 split 函数。

## 9. 分层划分保持目标类别比例

分类中少数类很少时，随机划分可能让某集合几乎没有正例。分层按标签比例分配，能让评估更稳定。

它不能解决同一设备跨集合，也不能解决未来数据进入训练，因此常需与分组或时间约束结合。

## 10. 分组划分防止同一实体跨集合

如果模型将用于从未见过的设备，就应按设备 ID 分组，让同一设备的所有记录只进入一个集合。

其他常见分组是用户、工厂、工单和文档。分组标准应与部署时的泛化目标一致。

## 11. 时间划分模拟用过去预测未来

训练使用较早时间，验证和测试使用更晚时间。时间字段应选择“信息可用时刻”，不是后来修改时间。

还要留意标签成熟窗口：近期工单可能尚未关闭，不能被错误标成“不超时”。

## 12. 数据泄漏是模型提前看到了不该知道的信息

常见类别：

- 目标泄漏：特征直接或间接包含答案；
- 未来泄漏：使用预测时刻之后的信息；
- 实体泄漏：同一主体跨训练和测试；
- 预处理泄漏：先在全量数据拟合均值、词表或缩放器；
- 测试集泄漏：用测试结果挑方案。

分数异常高时，先查泄漏，不要先庆祝模型优秀。

## 13. Point-in-time join 防止历史特征偷看未来

把工单和设备状态表连接时，每条工单只能使用预测时刻之前最近可用的状态。直接按设备 ID 连接“当前最新状态”，可能把未来维修结果带回过去。

需要同时保存事件时间、数据到达时间和特征生成逻辑。

## 14. 预处理必须只在训练数据上拟合

```text
训练集：fit + transform
验证集：只 transform
测试集：只 transform
```

全量计算均值、标准差、类别词表或特征选择，再切分，就是泄漏。交叉验证中每一折都要在该折训练部分重新拟合预处理。

## 15. Pipeline 把预处理和模型绑成同一合同

```text
原始 Schema
  → 缺失处理
  → 类别编码
  → 数值缩放
  → 特征组合
  → 模型
```

Pipeline 能减少训练与推理不一致，也便于交叉验证正确嵌套。顺序是模型的一部分，保存模型时也要保存预处理配置和字段顺序。

## 16. 缺失值处理要基于缺失原因

缺失可能表示传感器故障、用户没填写、字段不适用或系统版本不支持。统一填零可能把这些含义混在一起。

可选策略包括拒绝样本、统计填补、专门类别和缺失指示特征。策略只能在训练数据上拟合，并在服务端保持一致。

## 17. 类别编码必须处理未知类别

One-hot 把每个类别变成一个 0/1 列。线上出现训练未见过的新工厂、新设备类型时，编码器应有明确策略，而不是直接崩溃或映成错误旧类别。

高基数 ID 通常不适合直接 one-hot；它可能记住训练实体而无法泛化。

## 18. 数值缩放影响基于距离或梯度的模型

标准化常将数值变为减均值再除标准差。K-means、KNN、线性模型和神经网络常受尺度影响；树模型通常不依赖同样的缩放。

零方差列无法正常除以标准差，应在管线中明确处理。

## 19. 特征工程需要数据血缘

历史 7 天故障数、平均维修时长等聚合特征必须说明：

- 使用哪个实体键；
- 窗口起止是否包含当前事件；
- 更新延迟；
- 缺失和时区；
- 线上如何得到同一数值。

没有血缘的“聪明特征”很难验证，也最容易泄漏。

## 20. 监督学习使用带答案的样本

给定特征 `X` 和标签 `y`，算法从训练数据拟合参数，使预测在某种损失下更接近标签。

模型学习的是数据中的统计关系，不会自动理解业务因果、道德边界或法律要求。

## 21. 回归预测连续数值

例如预测维修时长或费用。最简单线性回归：

```text
ŷ = w₁x₁ + w₂x₂ + ... + b
```

模型输出可以是任意实数，若业务要求非负，要在目标变换、模型选择或结果策略中处理，而不是默默把所有负数截成零后不报告。

## 22. 分类预测类别或类别分数

二分类模型常先输出一个分数或概率，再用阈值决定正类：

```text
if probability ≥ threshold → 预计超时
else → 预计不超时
```

模型概率和最终动作是两层。阈值由漏报、误报和人工容量共同决定，不应隐藏在模型文件里不可追踪。

## 23. 决策边界是类别切换的位置

在线性分类器中，特征空间被一条线、一个平面或高维超平面分开。非线性模型可形成更复杂边界。

边界复杂不自动更好；它可能更贴合训练噪声。是否泛化要看未参与训练的数据。

## 24. 损失函数和业务指标回答不同问题

训练用损失需要可优化且提供稳定梯度；业务指标关注最终决策代价。模型可能用交叉熵训练，却用 recall、人工审核量和延误成本验收。

不要因为训练损失下降就宣称业务效果改善。

## 25. 基线是模型必须超过的最低对照

回归基线可预测训练集的中位数；分类基线可预测多数类、按业务规则或使用现有人工流程。

基线必须走相同数据划分和指标。复杂模型若不能稳定超过朴素基线，不应投入生产。

## 26. 欠拟合和过拟合看训练与验证的差距

```text
训练差、验证也差：可能欠拟合、特征不足或实现错误
训练很好、验证明显差：可能过拟合或分布差异
二者都异常好：先查泄漏
```

先排数据、标签、指标和代码错误，再讨论模型容量和正则化。

## 27. 正则化限制模型过度依赖复杂参数

L1、L2 等正则把参数复杂度加入训练目标。它们可能改善泛化，但不会修复标签错误、数据泄漏和错误划分。

正则强度是超参数，只能用训练/验证过程选择，不能看最终测试集反复调整。

## 28. 无监督学习没有现成标签答案

它从特征结构中寻找模式，例如聚类、降维和异常结构。结果取决于表示、距离、缩放和算法假设。

没有标签不等于结论天然客观。聚出的组只是数学结构，需要领域审查才能命名或行动。

## 29. K-means 寻找离簇中心更近的分组

算法反复执行：分配到最近中心、重新计算中心。目标是减少簇内平方距离。

它偏好大致球形、尺度相近的簇，对初始化、离群值和特征缩放敏感。簇编号 0、1、2 没有等级含义，重跑后编号可交换。

## 30. K 值必须用多种证据选择

可看簇内误差、轮廓值、重采样稳定性、代表样本和业务可解释性。没有一个指标能自动给出“真实簇数”。

如果不同初始化、时间窗口或轻微数据扰动就让分组完全变化，说明结果不稳定，不宜直接驱动高风险决策。

## 31. PCA 把数据投影到方差较大的方向

PCA 用少量新轴概括原特征中的主要线性变化，可用于压缩、去相关和可视化。

它不是自动挑出“最重要业务特征”，高方差也不等于对目标最有用。输入缩放会显著改变主成分。

## 32. 二维降维图只是投影

高维结构压到二维必然丢信息。图上分开不代表原空间有绝对类别，图上重叠也不代表模型无法区分。

应同时报告解释方差、重构误差、稳定性和原空间指标，不凭一张漂亮散点图下结论。

## 33. 混淆矩阵先固定哪个类别是正类

```text
TP：实际正，预测正
FP：实际负，预测正
FN：实际正，预测负
TN：实际负，预测负
```

若“将超时”是正类，FN 就是漏掉真正会超时的工单。换正类后 precision 和 recall 的解释也会换。

## 34. Accuracy 在类别不平衡时可能骗人

1000 张工单只有 10 张超时，永远预测“不超时”也有 99% accuracy，但完全没有发现风险。

准确率必须与类别比例、混淆矩阵和业务代价一起看。

## 35. Precision 和 Recall 关注不同错误

```text
precision = TP / (TP + FP)
recall = TP / (TP + FN)
```

precision 回答“被模型报出的风险中多少是真的”；recall 回答“真实风险中找到了多少”。提高一个常会牺牲另一个，阈值选择就是业务权衡。

F1 是二者调和平均，但它不包含 TN，也不直接表达不同错误成本。

## 36. 回归常用 MAE 和 RMSE

- MAE：绝对误差平均，单位与目标一致，对极端误差相对稳健。
- RMSE：平方误差平均后开方，对大误差惩罚更重。

一个总体数字不够。还要看误差分布、分位数、系统性高估/低估和关键切片。

## 37. ROC 与 PR 曲线观察不同阈值

ROC 展示真正率与假正率；PR 展示 precision 与 recall。在正类稀少时，PR 往往更直接反映发现正例的质量。

AUC 衡量排序能力，不等于概率校准，也不确定最终操作阈值。

## 38. 概率校准回答预测概率是否可信

如果许多预测约为 0.8 的样本中大约 80% 真为正类，可称这一范围较好校准。一个模型排序更好，概率却可能更不准。

涉及资源安排和期望成本时，校准通常很重要。校准也必须在独立数据上评估。

## 39. 交叉验证减少单次划分偶然性

K 折把训练区域分成 K 份，轮流用一份验证、其余训练。每折的预处理必须只在该折训练部分拟合。

时间序列、分组数据应使用对应的时间或分组验证方式，不能机械随机 K 折。

最终报告应展示各折分布，不挑最好的一折当代表。

## 40. 误差分析要切片看模型在哪些地方失败

按设备类型、工厂、时间、工单类别、缺失模式和置信区间等切片，比较样本量与指标。

切片太小会高度不稳定；切片很多又容易偶然发现差异。应事先定义关键群体，并报告不确定性。

## 41. 公平性没有单一万能指标

不同目标可能要求不同概念：各群体获得正预测比例相近、真实正例被发现概率相近、预测概率在各群体校准相近等。这些条件常不能同时满足。

阈值本身也是政策。公平评估需要法律、业务和受影响群体共同定义，不是模型团队独自选一个数字。

## 42. 模型上线后会遇到漂移

- 数据漂移：输入分布变化。
- 标签漂移：目标比例变化。
- 概念漂移：输入与目标的关系变化。
- 预测漂移：模型输出分布变化。

漂移不一定表示模型坏了，也可能是现实真的变化。告警必须连接调查、降级、重训或回滚动作。

## 43. 没有及时标签时不能声称质量稳定

可以监控 Schema、缺失率、范围、输入/预测分布和服务健康，但这些只是代理信号。真实 precision、recall 或误差需要成熟标签回填。

标签延迟应进入监控设计，避免面板永远显示旧时期的“绿色质量”。

## 44. 人工兜底必须是真实流程

“有人审核”要明确：谁审核、看到什么解释、多久响应、能否推翻、如何记录、用户如何申诉、系统故障时是否有容量。

若人只是机械确认模型建议，不能算有效控制。高风险动作应允许拒绝自动化和回到确定性规则。

## 45. 模型卡记录适用范围和已知限制

至少包括：用途、禁止用途、数据范围、指标与切片、阈值、训练版本、已知偏差、监控、人工流程和回退策略。

模型卡不是宣传页，而是部署和审查合同。数据文档、模型卡、变更记录和事故记录互相补充。

## 46. 一次完整实验的证据链

```text
问题卡与预测时刻
  → 数据版本与划分清单
  → 无泄漏预处理 Pipeline
  → 朴素基线
  → 候选模型与固定指标
  → 验证/交叉验证
  → 阈值与代价分析
  → 冻结方案后一次测试
  → 切片、限制、模型卡
```

失败运行和被放弃方案也应记录，避免以后重复走同一条错误路线。

## 47. 这一阶段应形成的整体地图

```text
业务决定 → 预测时刻 → 样本/标签/特征
  → 按实体或时间无泄漏划分
  → 训练集拟合预处理和模型
  → 验证集选模型、阈值和超参数
  → 测试集做最终估计
  → 监控漂移、真实质量、公平与人工兜底
```

必须掌握：先定义决定再选模型；预测时刻以后产生的信息不能用；预处理只能在训练部分拟合；阈值是业务策略；accuracy 可能被类别不平衡欺骗；无监督结果没有天然业务名称；测试集不能反复参与选择；上线后代理漂移指标不能替代真实标签质量。

具体算法 API 和指标实现以项目锁定库的官方文档为准；这里的核心是问题定义、数据边界、无泄漏验证和结论边界。
