## 解释规则

- 内部累计 Token 包含当前任务的上下文和生成活动，不保证等于套餐计费权重。
- 2026-07-16 复核的 [Codex pricing 官方说明](https://learn.chatgpt.com/docs/pricing)只提供相对使用倍率，没有提供本项目可验证的固定 Token 总池，因此不能可靠计算“1% 等于多少 Token”。
- 本机 `codex app-server --stdio` 的只读 `account/rateLimits/read` 是首选：读取 `rateLimitsByLimitId.codex.primary.usedPercent`，剩余按 `100 - 已用` 计算；该调用不发送模型请求，也不读取或输出认证 Token。
- 服务端响应头 `x-codex-primary-used-percent` 是 app-server 不可用时的第二证据，并用界面读数交叉核对。
- 读取时必须同时核对 `x-codex-primary-window-minutes=10080` 和同一窗口的 `reset-at`；旧摘要、其他模型窗口或无法在原始日志复现的数字一律不用于停止判断。
- 当一个批次或阶段结束时重新读取服务端百分比；若日志不可用，则退回界面读数，而不是用内部 Token 编造精确百分比。
- 不使用或兑换账号中可用的 usage reset，除非用户另行明确授权。
- 用量审计只提取百分比、窗口长度和重置时间，不保存或输出请求中的认证信息。
