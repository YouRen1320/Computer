# 百科重建实施契约

## 最终目标

构建一套能让零基础读者从计算机基本操作开始学习，并能把 Java、Spring、PostgreSQL、Vue、uni-app、Flutter、Python、机器学习与 AI Agent 用于真实工作的中文编程百科全书。它同时是连续课程、项目手册、故障手册和长期参考书。

## 已确认的关键决策

| 决策 | 采用方案 | 原因 |
|---|---|---|
| 仓库 | 与现有 48 周课程同仓演进 | 进度、实验和 FactoryCare 证据可复用，迁移可审计 |

## 单章完成定义

核心章节必须具备：

1. 要解决的问题与可观察学习目标；
2. 前置知识及零基础补救链接；
3. 直觉模型、精确定义与运行过程；
4. 目标版本下可运行的最小示例；
5. 正例、边界、失败案例及错误日志阅读；
6. 调试、测试、安全、隐私和无障碍中适用的部分；
7. 与用户已知语言或框架的对照；
8. FactoryCare 中的真实落点；
9. 预测、动手、故障、需求变更和关闭 AI 独立练习；
10. 复述题、间隔复习点、速查表；
11. 版本、复核日期与直接支持结论的来源；
12. 元数据通过 schema 与仓库校验器。

纯索引、路线页和附录不强制套用完整教学模板，但必须声明内容类型。

## 批次规则

- 正文批次默认 5—8 章，或约 4—8 万个 Unicode 字符；先到者可触发评审。
- 基础设施批次按可独立验证的能力切分，不为了凑章节数扩大范围。
- 一批只有在评审问题已关闭、延期理由已登记后，才能进入下一批。
- 任何“通过”都要区分静态检查、构建、自动化测试、人工版式检查和未验证项。

## 内容规模目标

- 主叙事目标：150—190 万 Unicode 字符，不含代码；
- 实验、练习、解析和索引目标：70—100 万 Unicode 字符，不含代码；
- 规模是覆盖度信号，不是验收替代品。重复、注水或无来源堆砌不计为完成。

## 兼容策略

迁移期保留 `weeks/`、`learning-kits/` 和现有顶层文档的可用入口，只添加到权威章节 ID 的映射。P9 默认建议移除重复正文而保留必要的跳转页；是否保留长期兼容入口，以 P9 迁移审计结果为准，不预先承诺永久兼容。

## 停止条件

用户要求本周套餐剩余接近 30% 时停止。2026-07-16 复核的 [Codex pricing 官方说明](https://learn.chatgpt.com/docs/pricing)把 Pro/20x 描述为相对 Plus 的使用倍率，没有在该页给出可供本项目换算的固定 Token 总池；本机 `/usage` 实测显示 Token 活动而不是套餐剩余百分比。因此，本项目没有可验证的“每 1% 固定 Token 数”，不得把内部线程 Token 等同于计费百分比。

执行时采用三层证据：

1. Codex 服务端响应中的 `x-codex-primary-used-percent` 是当前 7 天主窗口的直接用量证据；停止线为已使用约 70%；
2. 用户界面显示的周剩余百分比用于交叉核对，应约等于 `100 - primary-used-percent`；
3. 当前任务的内部 Token 计数只用于诊断，不用于宣称套餐余额。

只读取非敏感的用量百分比、窗口和重置时间，不输出认证信息。不得自动兑换 usage reset。到达停止线时，应完成当前原子写入、记录验证状态并安全交接；不得用破坏性命令强行回退未完成批次。

## 明确非目标

- 不把所有生态库都列为主线；
- 不复制无明确许可的第三方教材、培训 PDF 或图片；
- 不在课程构建阶段伪造学习、面试、项目上线或生产运行证据；
- 不在未经用户授权时推送远程、发布网站或投递岗位。
