# 内容优先执行策略（2026-07-16）

## 决策与适用范围

用户在 2026-07-16 决定调整百科重建节奏：P3—P8 以教材内容、示例、实验、练习和项目的连续生产为主，全面审查集中到 P9。该决定覆盖此前要求“每批完成独立复审后才能继续”的实施节奏，但不改写已经发生的 R0—R1 历史事实，也不降低最终质量目标。

本策略只调整审查时点，不修改 `PROGRESS.md`，不把课程建设记录成用户学习进度。

## P3—P8 执行规则

继续执行成本低且能阻止直接损坏的必要自动检查：

- schema、目录、清单和生成契约校验；
- Markdown 链接、章节引用、前置依赖和公开/私有边界检查；
- 示例代码的编译、运行及已有自动化测试；
- 与本批实际改动直接相关的最小回归检查。

下列工作不再作为 P3—P8 的逐阶段或逐批前置门，统一排入 P9：

- 独立 Agent 全面复审及长篇审查报告；
- 人工版式、无障碍和阅读器兼容性评估；
- 编程零基础读者试读与复测；
- 每个小批次的全仓穷举回归；
- 对全书覆盖、难度、重复、矛盾、过时内容和路线偏移的系统审查。
- 出版级 verification manifest、严格临时环境输出封闭、证据树原子写入及其独立安全复审。

延期审查不等于通过。未完成相应人工证据和全局审计的章节不得因此晋升为 `verified`，也不得作为正式公共发行物发布。P3—P8 可以保持 `planned`、`drafting` 或在满足当前机器门时保持既有状态；状态晋升仍须遵循生命周期门禁。

## P9 集中审查与回修

P9 必须集中完成所有延期项目，并至少覆盖：

1. 零基础路线是否从隐藏前置开始，知识难度是否连续；
2. 16 卷、四条路线、示例、实验、练习、答案和 FactoryCare 项目是否完整对应；
3. 代码、命令、测试、链接、版本、安全和公开/私有边界是否真实有效；
4. 是否存在遗漏、重复、矛盾、过时内容或脱离教程目标的章节；
5. HTML、EPUB、PDF 的人工版式、无障碍和目标阅读环境证据；
6. 编程零基础读者试读、卡点修订和受影响任务复测；
7. 全仓回归、迁移、回滚和最终发布边界。
8. 把 P3—P8 使用的轻量代码 recipe 收敛为完整 verification manifest，并验证输入漂移、未声明输出、工具版本与可复现证据。

发现问题必须回修正文、代码、路线或构建契约，再重跑受影响检查；不能用“已到 P9”降低验收标准。只有最终证据完整时，章节才可进入 `verified`，发行物才可进入正式发布流程。

## 风险与控制

- **集中返工风险**：较晚发现结构性问题可能影响多个卷。控制方式是保留必要自动检查、稳定章节模板和权威目录映射。
- **暂时不一致风险**：P3—P8 允许中间状态存在，但不得宣称已完成审查、合规或发布。
- **审查规模风险**：P9 工作量会增大。P3—P8 应持续保留可定位的来源、版本、代码和章节映射，避免 P9 无证据可查。

## 回滚

若内容生产出现大范围结构漂移，可撤销本策略文档及其同步文档修改，恢复逐批审查；已经写出的教材内容不需要删除，改为按恢复后的门禁逐批补审。回滚不自动晋升或降级章节状态，也不修改 `PROGRESS.md`。

## 明确非目标

- 不取消最终审查，也不降低 P9 完成标准；
- 不把“自动检查通过”表述为人工评审、无障碍合规或零基础可学性已证明；
- 不因追求速度跳过示例可运行、schema、链接或私有答案隔离等基本检查；
- 不在 P3—P8 提前公开发布未完成最终审查的教材；
- 不新增阶段性 review 记录来证明本策略本身。
