# 百科批次评审标准

每一批完成后先由作者自审，再进行独立复审。结论只能是 `PASS`、`PASS_WITH_FOLLOW_UP` 或 `FAIL`；存在阻断项时不能用篇幅或“以后再修”覆盖。

## 七个评审面

### 1. 技术正确性

- 定义、执行模型、边界条件和错误分类是否准确；
- 版本敏感结论是否与 `versions/` 一致；
- 是否把经验判断清楚标记为判断，而非官方事实；
- 是否避免把简化模型冒充完整机制。

### 2. 零基础教学

- 隐藏前置是否已解释或提供补救链接；
- 是否先回答“为什么”和“会看到什么”，再引入术语；
- 示例能否由零基础读者按步骤复现；
- 练习是否从预测逐步过渡到独立实现。

### 3. 代码与可重复性

- 代码是否来自真实示例文件而非不可运行的孤立片段；
- 构建、运行和测试命令是否在目标环境执行；
- 正例、边界和故障用例是否都有可观察结果；
- 是否记录未执行的平台相关验证。

### 4. 安全、隐私与可靠性

- 是否存在硬编码凭据、真实个人信息或危险默认配置；
- 认证、前端可见性和服务端授权是否被区分；
- 并发、竞态、取消、超时、重试和幂等是否在适用处说明；
- 日志和示例数据是否可安全公开。

### 5. 可访问性与包容性

- Web/移动 UI 是否覆盖语义、键盘、焦点、对比度、屏幕阅读器和减少动画中适用项；
- 图片和图表是否有替代文字或等价文字说明；
- 不能只用颜色表达状态。

### 6. 版本与来源

- 来源是否直接支持对应结论，优先官方和一手资料；
- 是否记录复核日期、目标版本和历史差异；
- 旧笔记只作为覆盖线索，不作为无需复核的权威来源；
- 是否遵守引用和版权边界。

### 7. 出版与导航

- 标题层级、链接、章节 ID、术语和交叉引用是否稳定；
- 网站与书籍构建是否无断链；
- 代码块、表格、提示框和分页在目标格式中是否可读；
- 是否避免一个超长文件承担整卷内容。

## 阻断项

以下任一项存在即为 `FAIL`：

- 核心代码不能构建或测试，却标记为通过；
- 零基础路线出现无法由前置图解释的必需概念；
- 安全示例鼓励明文密码、泄漏 Token 或只做前端授权；
- 直接复制许可不明的第三方大段正文或资产；
- 章节元数据、ID 或路线引用无法通过校验；
- 修改了学习进度但没有用户真实学习证据；
- 已知断链、错误输出或平台限制未在交付记录中披露。
