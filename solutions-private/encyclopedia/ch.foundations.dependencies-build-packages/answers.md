# 隔离解析：依赖与构建

完成公开练习并保存预测后再阅读。

## A

A 是根项目显式声明的直接依赖，B、C 是通过依赖边到达的传递依赖。删除根项目里多余的 B 声明并不会删除 A→B 的边；解析器仍会经 A 引入 B。要判断是否移除，必须看完整图、scope/可选规则和实际工具输出。

## B

约束描述允许选择的集合，锁文件记录一次解析后的精确版本及常见的完整性信息。新增 1.0.4 后，源代码和声明都没变，候选仓库状态却变了；没有锁时解析可改变。锁也不是永远正确，升级应显式更新、审查并复测。

## C

可以确认当前热缓存含有足以构建的内容，不能确认源仓库、镜像、代理或新机器能完整解析。先保存工具/配置与日志，再用隔离空缓存离线或受控联网复现；不要先清空用户全局缓存。

## D

旧 package 的存在不是本次运行证据。clean 应删除目标范围的旧产物；test 非零后 package 必须 not-run；报告应记录每阶段和 artifact 摘要。本次失败不能引用旧摘要冒充新产物。

## E

记录 `type -a`/等价命令、解析后的绝对路径、工具版本、wrapper 版本、关键非敏感环境值及子进程实际观察。CI 应用同一项目化入口。不要把完整环境或认证配置写入报告。

## F

同机两次摘要相等是基础证据，可发现部分时间戳不稳定；仍可能同时泄漏用户名、绝对路径、区域设置或同一个缓存。第三方重建需要独立环境和同一输入。插件与依赖同样要固定并验证。

## G

漂移故障：向候选仓库加入更高允许版本，未锁解析应变，恢复锁后摘要不变。旧包故障：先生成包，再注入 test failure；若未 clean 可能看到旧文件。修复为目标范围 clean、失败即停止、报告绑定本次输入与摘要，最后恢复故障并复跑原命令。
