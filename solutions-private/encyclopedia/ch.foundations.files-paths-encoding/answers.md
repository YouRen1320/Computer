# 隔离解析：文件、路径、字符与编码

完成公开练习并保存预测后再阅读。

## A 组

1. 起点 `project/`：`docs/guides/start.md`。
2. 从 `project/docs/guides/` 先回到 `docs/`，再回到 `project/`，然后定位 `README.md`；图示可写为 `../../README.md`，重点是两个父层移动。
3. 从 `docs/` 解释时，它会尝试进入 `docs/docs/guides/start.md`，多出一个 `docs` 路径段。
4. 绝对路径从系统根或盘符开始，能帮助定位本机目标，但包含机器布局和用户名，团队配置应使用稳定项目相对位置或显式配置。

## B 组

- `.env`：点开头在许多 macOS/Linux 界面中默认隐藏，但不加密；
- `archive.tar.gz`：最后扩展名通常是 `.gz`，名称还暗示先 tar 再 gzip，真实格式仍需检查；
- `config.json.txt`：最后扩展名是 `.txt`，不能当成可信 JSON；
- `LICENSE`：没有扩展名仍然是普通文件。

## C 组

UTF-8 字节数为 `1 + 3 + 4 = 8`。用户看见三个符号，但语言可能按字节、Unicode 码点、UTF-16 代码单元或字素簇计数；必须查看 API 的测量单位。

## D 组诊断要点

1. 先记录程序实际工作目录和解析后的目标，不因搜索找到同名文件就新建副本；
2. 比较编辑文件路径与程序读取路径，核对双扩展名和缓存；
3. 保留原始字节，用正确编码重新打开副本，确认后再转换；
4. 查看 LF/CRLF 与格式化设置，把纯行尾转换和业务修改分开。

## E 组需求变更

至少需要中文往返预言、LF/CRLF 等价读取案例、非法字节失败行为、BOM 边界、原件保护和错误报告。编码声明与真实字节必须一致；页面最终显示正常不能单独证明导入导出往返无损。
