# 实验：把安全矩阵、异步测试和 OpenAPI 契约接成发布门

本实验把三个容易被分开处理的问题接成一个可执行闭环：

1. 凭据解析、身份建立、权限检查与租户资源检查；
2. HTTPX `ASGITransport` + `AsyncClient` + pytest/AnyIO 的异步接口测试；
3. OpenAPI 结构投影与本地基线比较。

运行：

```bash
./verify.sh
```

测试覆盖匿名、错误认证方案、未知/失效令牌、权限不足、跨租户资源、成功响应、敏感字段过滤、依赖覆盖清理和 OpenAPI 安全契约。未授权请求还会检查仓储读取次数，证明在认证或操作授权失败时没有进入资源读取阶段。

实验完全在进程内运行，不访问外部网络，也不声称验证了 ASGI lifespan、真实 OAuth/OIDC、JWT 加密签名、JWKS、外部 IdP、反向代理或 Java 服务联调。固定令牌只用于教学。

在 FactoryCare 中，Java 仍然拥有用户、角色、租户、令牌签发和工单状态；这个 FastAPI 端点只读取内部的可重建建议数据。若契约或安全语义需要跨服务统一，应由 Java 公共 API/网关策略主导，而不是在 Python 中复制业务账号体系。
