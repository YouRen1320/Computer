# Lab：FactoryCare 设备状态卡

本实验训练“预测 → 独立构建 → 制造失败 → 读取日志 → 最小修复”。公开目录不含实现答案。

## 环境

- JDK 25；
- Maven 3.9.x；
- 从仓库根目录执行命令；
- 开始前用 `java -version`、`javac -version`、`mvn -v` 确认实际工具链。

## 第一关：先写预测

不要打开或运行 `diagnostics/`，先记录：

1. `UninitializedLocal.java` 是编译失败、运行异常，还是输出 `0`？
2. `OutOfScope.java` 中哪个名字在何处失效？
3. `WrongTypeAssignment.java` 会不会把“两个”自动变成整数？
4. `OverlappingLocalName.java` 是合法遮蔽，还是重叠作用域中的重复声明？
5. `DiscardedNormalization.java` 会不会报错？它的原文本最后是否已被去空格并转大写？
6. `RegexSplitBoundary.java` 的两个数组长度是多少？哪条 API 契约导致结果？
7. 每个错误最可信的证据应由编译日志还是预期/实际输出差异产生？

## 第二关：独立完成状态卡

只修改：

```text
starter/src/main/java/com/factorycare/learning/DeviceStatusCard.java
```

在 `main` 中完成以下契约：

1. 使用 `long` 局部变量保存设备 ID `100000025L`；
2. 使用 `String` 保存设备名称 `"B区-冷却泵-02"`；
3. 使用 `int` 保存未关闭工单数量 `2`；
4. 使用 `boolean` 保存启用状态 `true`；
5. 在一个内层代码块中声明 `String` 局部变量，值为 `"值班检查"`，并在块内输出；
6. 声明原始标签 `"  b区.冷却泵.02.  "` 和空白文本 `" \t"`，分别输出 `isEmpty()` 与 `isBlank()` 结果；
7. 用 `strip().toUpperCase(Locale.ROOT)` 得到 `"B区.冷却泵.02."`，不覆写或伪造原始输入；
8. 用 `split("\\.", -1)` 保留尾部空段，输出段数 `4`；
9. 用一个 `StringBuilder` 与循环生成 `"B区|冷却泵|02|<empty>"`；
10. 使用 `print` 或 `println` 输出所有契约字段，结果必须与 `expected-output.txt` 逐字一致；
11. 不使用集合、方法拆分、业务对象或输入解析；数组仅用来接收 `split` 结果，循环仅用来组装汇总。

先手写预期，再运行：

```bash
labs/encyclopedia/ch.java.values-variables-types/verify.sh
```

在 starter 尚未完成时，Maven 构建可以成功，但输出比较应失败。这正好说明“可编译”不等于“功能符合契约”。

## 第四关：需求变更

在不重新生成整个类的前提下，把状态卡改为：

- 设备 ID：`100000026L`；
- 设备名称：`B区-冷却泵-03`；
- 未关闭工单：`0`；
- 启用：`false`；

先复制并更新一份预期输出，再修改最少的变量初始化语句。说明为什么类型不需要随这次业务值变化而变化。

## 第五关：关闭 AI 验收

在空白临时目录重写一个最小类，满足第二关契约，然后完成 120 秒复述：

- 值、类型和变量的区别；
- 局部变量为什么不能依赖默认值；
- 四个失败样例各违反哪条规则；
- `BUILD SUCCESS` 为什么不等于输出正确。

## 验收标准

- 状态卡构建成功，输出与固定预期逐字一致；
- 能区分空与空白，原文本保持不变，正规化、保留尾空的分割与 builder 汇总结果均与 oracle 一致；
- 两个非重叠代码块可使用同名局部变量的边界能口述；
- 至少能独立复现并修复未初始化、作用域外访问、错误类型赋值三类失败；
- 能解释重叠作用域中的局部同名声明为什么不是合法遮蔽；
- 记录失败阶段、首个可信位置、最小修复和重跑证据；
- 能说明行为故障没有编译错误位置，首个可信证据是预期/实际输出差异；
- 未把控制台输出当成生产日志，也未加入真实个人或企业敏感数据。
