# 实验：为设备与工单写一张可证伪的 API 契约表

## 边界

本实验只研究资源表示、稳定错误、兼容演进、分页、缓存验证器和幂等重试。不要实现 Web 框架、数据库事务、认证或真实外部接口；不要填入生产设备、人员、Token 或内部错误堆栈。

## 步骤

1. 在 `worksheet.md` 先写每个场景的 expected，不运行脚本。
2. 执行 `ruby run_lab.rb`，把实际摘要与预期逐项比较。
3. 打开示例的 `contract_model.rb`，找到资源投影、Problem、游标、ETag 和幂等键各自的规则入口。
4. 把 v1.1 的新增 `location` 临时改成把 `displayName` 重命名为 `name`，确认兼容断言失败；恢复后复跑。
5. 把幂等键相同但 payload 不同的 409 分支临时放宽，确认记录数断言失败；恢复后复跑。
6. 用 120 秒解释为什么 304 空 Body、末页空数组和幂等重放都不是异常。

## 必须观察

- 空页与末页的 `items`、`nextCursor` 有明确形状；
- offset 漂移的重复项与 cursor 结果可以逐项手算；
- 同一幂等键/同一 payload 的重放保持同一资源 ID；
- 同一幂等键/不同 payload 不会创建第二条记录；
- ETag 命中返回 304 且不复制 200 Body；
- 未知内部异常仍只输出稳定公开字段；
- 兼容与否由旧消费者依赖是否被破坏判断，不由版本号大小猜测。

## 验收

预测表、自动输出、两个故障注入、恢复复跑和 120 秒复述均存在；验证器最终退出码为 0。单次 PASS 不证明生产并发、数据库事务、代理缓存、签名游标或多版本客户端已经验证。
