# 实验：建立 claim → evidence → next-review 学习账本

## 目标

为一个即将学习的小概念建立可证伪账本，完成正常观察、受控故障、修复复跑和 1/3/7 天检索计划。文件存在、投入时长和 AI 自述都不能直接写成掌握结论。

## 操作

1. 复制 `starter-ledger.yml` 为自己的实验记录；
2. 把所有 `<填写>` 换成具体内容；
3. claim 必须写明任务、固定范围和可能推翻它的结果；
4. explain/build/diagnose 各写一个不同任务；
5. 执行前写 prediction，再记录 observation；
6. 故意引入一个窄故障，填写首个可信证据、单一修复和复跑；
7. 至少写一个“尚未验证”边界；
8. 为第 1、3、7 天安排逐步减少提示的主动检索。

完成后可用示例目录的校验器检查结构：

```text
ruby ../../../examples/encyclopedia/ch.foundations.learning-evidence/verify.rb my-ledger.yml
```

这条命令通过仍不等于内容正确。你还需要向另一人做 120 秒复述，并让对方指出一条证据不能证明的边界。

## 验收

- 每项主张都有可重放输入、预测、观察和范围；
- 三类证据不是同一句话的重复；
- 故障有第一条具体证据，不只写“失败”；
- 修复后按原正常预言复跑；
- 边界项明确标为未验证；
- `artifact_exists` 没有被当成掌握；
- 复习任务要求从记忆产生答案，而不是再次阅读。
