# Week 08 深度教学包：并发、虚拟线程与 JVM

本教学包服务于[第 8 周计划](../../weeks/week-08.md)，也是 Java 基础阶段门 G1 的收口周。

本周核心不是追求“高并发数字”，而是建立三个工程顺序：

1. 先有串行正确版本；
2. 再判断任务依赖与失败语义；
3. 最后选择受控并发模型，并为稀缺资源、超时、取消和生命周期负责。

## JDK 25 边界

- 虚拟线程是稳定能力，可以学习和使用；
- 结构化并发在 JDK 25 仍是 preview，本项目不开启 preview，也不使用；
- Scoped Values 已在 JDK 25 正式定稿，但本轮不作为项目依赖；
- 虚拟线程不池化，但外部 API、数据库连接等稀缺资源仍需 Semaphore、连接池或服务端限额；
- 不把本机一次计时包装成生产性能结论。

## 本周完成标准

完成后你应能：

1. 用例子区分并发、并行、原子性、可见性和顺序性；
2. 优先用不可变、线程封闭和减少共享状态，而不是先加锁；
3. 正确处理中断，不吞 InterruptedException；
4. 构造有界 ThreadPoolExecutor，说明队列、线程数与拒绝策略；
5. 管理 Executor 的关闭、等待、超时和拒绝；
6. 使用 CompletableFuture 组合独立任务，并区分 thenApply、thenCompose、thenCombine；
7. 设计必须成功、可降级、总超时和失败来源；
8. 使用每任务虚拟线程处理阻塞型任务，同时限制稀缺资源；
9. 用线程转储和 JFR/jcmd 建立基础证据链；
10. 解释堆、栈、Metaspace、GC、JIT、死锁、OOM 的高层区别；
11. 无 AI 修复竞态、中断或资源泄漏；
12. 完成排序/二分算法副线，并通过 G1。

## FactoryCare 本周切片

EquipmentEnrichmentService 从三个模拟慢源补全：

- 保养摘要：必须成功；
- 备件可用性：可超时降级；
- 最近故障统计：可失败但要保留来源。

实现并比较：

- 串行正确基线；
- 有界平台线程池 + CompletableFuture；
- 每任务虚拟线程 + Semaphore。

本周慢源必须是本地可控模拟器，不接真实 HTTP、数据库或消息队列。

## AI 使用边界

AI 可以：

- 帮你画任务依赖图；
- 审查线程池是否无界、Executor 是否泄漏；
- 提议超时、错配、取消和资源耗尽测试；
- 辅助阅读线程转储，但结论必须回到代码位置验证。

你必须：

- 定义串行正确结果；
- 决定必须成功、可降级与整体失败；
- 选择平台池或虚拟线程并说明理由；
- 定义外部资源并发上限；
- 亲手修复竞态、中断吞噬和未关闭 Executor；
- 无 AI 完成阶段门。
