# Week 00 实验手册

所有实验先写“预期看到什么”，再执行命令。这里给验收条件，不直接给出你的机器应使用的安装命令或最终配置，因为安装来源与现状必须由你确认。

## 实验记录格式

每个实验保存：目标、现状、假设、操作、实际输出、结论、回滚、仍未确认。输出要脱敏，隐藏用户名、token、私有仓库地址和代理凭据。

## Lab 0：只读环境盘点（45 分钟）

### 任务

收集以下证据，不进行安装、卸载或配置修改：

```bash
uname -m
sw_vers
echo "$SHELL"

/usr/libexec/java_home -V
```

## Lab 1：统一 JDK 与 Maven（75—105 分钟）

### 任务

1. 根据只读盘点选择唯一主 JDK 来源；
2. 修改前备份可能涉及的 shell 配置，并写恢复命令；
3. 让新开的登录/交互终端都能找到 JDK 25；
4. 验证 `java`、`javac` 和 Maven 实际 JVM；
5. 在 IDE 中检查 Project SDK、Maven Runner 与测试 Runner；
6. 保存终端与 IDE 的证据。

### 约束

- 不卸载旧 JDK；
- 不同时新增第二个版本管理器；
- 不执行未经检查的远程安装脚本；
- 不把本机完整配置文件提交仓库。

### 验收

- 三个命令链路都指向 JDK 25；
- Maven 明确显示 3.9.16；
- 新开终端复验通过；
- IDE 内执行测试时的 JDK 可从日志或设置证明；
- 回滚步骤能恢复配置，但无需真的破坏正确环境。

## Lab 2：非 Spring Maven + JUnit 烟雾工程（60—90 分钟）

### 任务契约

建立一个最小工程，只包含：

- 一个命名清晰的 package；
- 一个有返回值的纯 Java 方法，例如两个维修时长相加；
- 一个 JUnit 测试类，至少包含正常值和一个边界值；
- Maven 编译目标为 Java 25；
- 从空的构建产物状态运行 `mvn test`。

不要加入 Spring、Lombok、数据库、JSON 库或代码生成器。

### 故障注入

依次制造并恢复：

1. 源文件 package 与目录/测试 import 不一致；
2. 一个断言预期值错误；
3. 一个编译语法错误。

记录三者分别属于编译错误、测试失败还是运行时错误，并指出最先可信的错误位置。

### 验收

- `mvn test` 最终通过；
- 能解释源码、测试、构建输出分别在哪里；
- 故障恢复不是靠删除整个工程重建；
- 依赖树中没有业务框架。

## Lab 3：安全的版本冲突模拟（45—60 分钟）

### 场景

不要修改系统默认或删除 JDK。使用一个临时 shell 会话，局部改变 `JAVA_HOME` 或 `PATH`，制造以下任一现象：

- `java -version` 与 `mvn -v` 的 Java home 不符合预期；
- 旧 shell 与新 shell 结果不同；
- IDE Maven Runner 与终端结果不同。

### 排查要求

按证据顺序使用：

1. `type -a` 确认候选；
2. 打印 `PATH` 与 `JAVA_HOME`；
3. 分别运行 `java -version`、`javac -version`、`mvn -v`；
4. 提出一个假设；
5. 只改变一个变量；
6. 复验并退出临时会话恢复。

### 验收

- 记录“现象 → 假设 → 证据 → 修复 → 恢复”；
- 不使用 `sudo`、删除或覆盖系统文件；
- 能解释为何只看一个版本命令不够。

## Lab 4：五项能力基线（75—90 分钟）

每项限时 15—18 分钟。目标是测起点，不是临时补课。

| 领域 | 基线任务 | 证据 |
| --- | --- | --- |
| Java | 阅读一个方法、修一个编译错误、补一个断言 | 测试输出/口述记录 |
| SQL | 手写过滤、排序、分组的伪 SQL | 纸面答案；未装库也可 |
| Vue/TS | 解释一个 composable 的输入、状态、副作用 | 旧代码片段或口述 |
| Python | 写一个带类型提示的数据转换函数 | 代码或标记未运行 |
| Flutter | 解释 Widget/state/async 数据流或审查旧 App | 旧代码证据或标记未运行 |

每项记录 L0—L4、卡点、证据强度。未运行不能用“应该会”代替。

## Lab 5：岗位样本与事实型简历（2—3.5 小时）

### 样本要求

采集至少 40 个可追溯岗位：Java 16、Java+Vue/全栈 10、Vue/uni-app 8、AI 应用/Python 6。记录链接、发布日期、城市、经验、学历、薪资、行业、必选、加分和原文证据。

### 分析要求

- 同义词先规范化再统计，例如 SpringBoot/Spring Boot；
- 区分必选与加分；
- 区分有效在招、长期模板和疑似重复；
- 给出样本限制，不能声称代表全部南昌市场。

### 简历要求

建立 Vue/全栈版与 Java/AI 应用版。只能重排真实经历；尚未完成的 FactoryCare 只写“学习项目规划”或暂不出现。

## Lab 6：FactoryCare 准备增量（30—45 分钟）

本周只写文档：

1. 一句话：哪类用户、在什么场景、解决什么问题；
2. 三类首批用户：报修人、维修人员、运维管理员；
3. 词汇表：设备、故障、工单、优先级、处理人、状态、SLA；
4. ADR：为什么 JDK 25、Spring Boot 4.1、PostgreSQL 18、模块化单体；
5. 明确非目标：本周不创建业务代码和基础设施。

状态只写“工单状态”这一概念，不在 Week 00 自创状态词或状态流转。
