# Week 00 无 AI 考核

> 考核期间关闭 Codex、Claude 和其他生成式 AI。允许查看系统自带帮助、官方文档、自己保存的环境基线。提交后再打开[答案册](./answers.md)。

## 规则

- 建议时长：90 分钟；
- 满分：100 分；75 分通过；
- 使用下方映射换算为全局六类分数；项目增量、测试与排错、无 AI 任务分别低于 15/25、12/20、9/15 时，即使总分达到 75 也需补考；
- G0 的环境证据和回滚清单属于额外硬门槛：没有实际版本/测试证据，或无法写出恢复临时变更的步骤，均不能通过；
- 不允许为了制造问题删除 JDK、卸载 Maven或覆盖系统配置；
- 所有输出先脱敏。

## A. 工具链图与口述（20 分，15 分钟）

在纸上或 Markdown 画出执行 `mvn test` 时以下对象的关系：终端、shell、alias/function、`PATH`、`mvn` 可执行文件、`JAVA_HOME`、JDK、Maven、`pom.xml`、JUnit、JVM。

然后回答：

1. 为什么 `java -version` 正确不证明 Maven 正确？
2. 为什么修改 `.zshrc` 后旧终端可能不变？
3. IDE 自身运行 JDK 与项目构建 JDK 是否必须相同？

## B. 受控故障诊断（30 分，30 分钟）

在临时 shell 或由同伴预设的安全场景中，面对以下现象：

```text
java -version 显示 JDK 25
mvn -v 显示的 Java home 不是你预期的 JDK 25 路径
IDE 测试结果与终端不一致
```

要求：

1. 先列三种可能原因，不急着改；
2. 写并执行最小只读取证命令；
3. 每次只改变一个因素；
4. 找到最可能根因并复验；
5. 恢复临时变更；
6. 标出哪些结论已经验证，哪些仍是推测。

## C. Maven/JUnit 烟雾验证（20 分，15 分钟）

从干净构建产物开始运行 Week 00 烟雾工程：

- 证明编译和测试执行；
- 故意让一个断言失败；
- 根据报告定位失败测试和期望/实际值；
- 恢复后再次通过；
- 解释这与编译错误的差异。

## D. 安全与回滚（15 分，10 分钟）

审查下面的行为，只写风险与替代流程，不执行：

```text
从陌生回答复制 curl URL | sh
随后用 sudo 修改系统目录
把整个 settings.xml 和 shell 配置发给 AI 排错
```

至少指出五个风险，并写出安全替代步骤和回滚证据。

## E. 基线与求职诚信（15 分，20 分钟）

给出五项能力中一个“未运行”案例，说明如何如实记录。再检查两版简历：

- 圈出所有无法由现有证据支持的词；
- 将一个“熟练/精通”表述改成事实型项目描述；
- 说明 40 个岗位样本可以支持什么结论、不能支持什么结论。

## 评分 Rubric

| 部分 | 满分表现 | 主要扣分点 |
| --- | --- | --- |
| A 工具链 | 关系和边界正确，能解释多处 JDK 选择点 | 把终端等同 shell；认为只看 `java` 即可 |
| B 诊断 | 先假设后取证，单变量修复，复验并恢复 | 直接重装；一次改多处；无证据宣称解决 |
| C 烟雾测试 | 区分编译错误和测试失败，能读报告 | 只看到 BUILD SUCCESS；不会定位失败 |
| D 安全回滚 | 识别远程脚本、权限、秘密和不可逆修改 | 只说“有风险”；无替代步骤 |
| E 诚信 | 未运行明确标记，简历由证据支持 | 把计划当能力；样本过度外推 |

## 口述加问（不另计分，但必须完成）

1. LTS、stable、RC、preview 的区别是什么？
2. `PATH` 与 `JAVA_HOME` 各自做什么？
3. Maven 本地仓库和 `pom.xml` 的职责是什么？
4. 为什么 Node/Python/Flutter 本周可以不升级？
5. Git 能否回滚 Homebrew 安装和 IDE 设置？为什么？
6. AI 在环境安装中可以做什么，最终由谁确认成功？
