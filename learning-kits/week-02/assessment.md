## 题目：`EquipmentCode` Value Object

### 业务契约

- 输入非 null；
- 去除首尾空白并使用 `Locale.ROOT` 转为大写；
- 规范值必须匹配 `EQ-[A-Z0-9]{4,12}`；
- 对外保存和返回规范值；
- 两个规范值相同的对象必须相等且 hashCode 相同；
- 创建成功后不可变。

## A. 设计说明（10 分，10 分钟）

回答：

1. 为什么它是 Value Object，不是 Entity 或 DTO？
2. 为什么规范化发生在创建时？
3. 为什么大写使用 `Locale.ROOT`？
4. 为什么不用裸字符串加多处正则？
5. 正则中的长度到底限制哪一部分？

## B. 独立实现与接入（25 分，35 分钟）

1. 使用 record 实现 `EquipmentCode`；
2. 将 `Equipment` 中的裸编码替换为该类型；
3. 构造器或工厂保证 `EquipmentId`、`EquipmentCode` 和名称有效；
4. 不提供任意 setter；
5. 保留 Entity 身份，不在本周用全部字段自动生成 equals/hashCode。

## C. 测试（20 分，25 分钟）

至少覆盖：

- 标准合法值；
- 首尾空白与小写规范化；
- null、空、空白；
- 缺少 `EQ-`；
- 正文长度 3/4/12/13；
- 非法连字符位置、下划线、中文；
- 两个来源不同但规范值相同的相等性与 hashCode；
- Equipment 拒绝 null code。

## D. 不可变故障实验（15 分，10 分钟）

给定一个包含 `int[]` 组件的 record：

- 证明仅有 final 组件仍可被外部修改；
- 写出构造时和访问时的防御性复制；
- 说明数组对 record 默认 equals 的影响。

不要求把该 record 放入 FactoryCare 正式模型。

## E. 字符串/频次算法（10 分，15 分钟）

对已经规范化的 `EquipmentCode` 正文，返回第一个只出现一次的 ASCII 字符；无则返回约定结果。不能使用 Map/集合。

要求写 5 个测试、字符集假设、时间和空间复杂度。

## F. 口述答辩（15 分，20 分钟）

1. class、record、enum、interface 分别适合什么；
2. 什么是不变量，getter/setter 为什么不等于封装；
3. `final` 引用为何不代表深层不可变；
4. Entity、Value Object、DTO 如何区分；
5. 组合优先于继承是什么意思，不是绝对禁止继承；
6. enum 为什么不用 ordinal 对外持久化；
7. 为什么本周不实现完整工单状态机；
8. Java record 与 TypeScript readonly 类型有何关键差异。
