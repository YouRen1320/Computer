## 推荐学习回路

1. 从周 README 选择一个 20—45 分钟可验证结果；
2. 新概念先看整体地图和完整可运行示例；
3. 用少量自我解释理解入口、数据流、规则和边界；
4. 保留样板，只补全或改变承载概念的关键部分；
5. 完成一个相似但不相同的小迁移；
6. 运行能证伪当前声明的最轻证据，已有同类证据时不重复造错或写测试；
7. 完成普通周收束，记录“证据通过”或一个明确缺口；阶段门才做正式评分与短独立抽查；
8. 只把真实小时、分数和证据写入进度表。

## 边界

- 当前实践与考核包只覆盖 Week 00—08；Week 09—48 直接使用章节配套的 example/lab/exercise，不能假装已有同等答案册；
- 示例是实验和考核材料，不是已实现的完整 FactoryCare；
- 版本进入实际周次时按 [TECH_STACK.md](../TECH_STACK.md) 重新核对稳定补丁；
- AI 可生成完整示例、脚手架、实现和测试；新概念必须经过一次关键补全或迁移，熟悉项目则以契约、diff 和验证接管；
- [当前学习执行方案](../STUDY_EXECUTION.md)、[AI 协作规范](../AI_WORKFLOW.md)与[阶段考核](../ASSESSMENTS.md)是执行口径。Week 01 已迁移；Week 00、02—08 中仍写着“无 AI”“手写”或逐项故障注入的旧题，在对应周迁移前只作为可选练习，不再作为普通周通过门槛。
