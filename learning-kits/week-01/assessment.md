# Week 01 无 AI 考核

## 规则

- 时间：120 分钟；允许 JDK/JUnit 官方 API 文档，不使用 AI、答案册或旧实现复制；
- 提交：源码、测试、命令输出、简短设计说明；
- 通过：总分 ≥75，项目增量、测试与排错、无 AI 任务各自 ≥60%；
- 本考核不测试数组循环、类实例或 Spring。

## 题目：维修服务费 CLI

实现一个 CLI 和纯业务方法：输入基础金额（分）与服务费率（基点，10000=100%），输出服务费和总金额。

业务契约：

- 金额/费率不能为负；
- 费率最大 3000（30%）；
- 整数计算，先定义舍入策略；
- 0 金额或 0 费率服务费为 0；
- 溢出必须明确失败；
- 非数字控制台输入给出错误，不打印假成功。

## A. 概念解释（20 分）

1. 写出经典 main 各部分含义；
2. 解释 stdout、return 和 JUnit assertion 的不同；
3. 解释整数除法、narrowing、溢出；
4. 解释 Java 参数按值传递；
5. 解释 BUILD SUCCESS 为什么还要看 Tests run。

## B. 最小实验（15 分）

先预测并运行：整数除法、字符串拼接、long→int cast、乘法溢出。提交预测/实际/结论。

## C. 项目增量（25 分）

- 纯业务方法与 CLI 分离；
- 方法名、参数单位和失败契约清楚；
- 不用 double 作为金额事实；
- main 只负责输入、调用、输出和顶层错误反馈。

## D. 测试与排错（20 分）

- 正常、0、上限、负值、溢出、非法输入；
- 故意让 expected 错一次，指出 failure 文件/行/expected/actual；
- 故意制造一个 compile 错误，说明为何无 Tests run；
- 恢复后命令行全绿。

## E. 无 AI 任务（15 分）

考核整体即无 AI；额外要求最后 15 分钟独立增加“最低服务费 100 分，但 0 金额仍为 0”的开关参数或单独方法。先写测试，不重写整体。

## F. 复盘与求职（5 分）

当前求职暂停，因此写：一个误解、一个可复用规则、一个未验证点、下次复习日期。不得虚构投递。

## 提交格式

```text
commit/目录：
运行命令：
Tests run / Failures / Errors：
设计与单位：
故障证据：
独立变化：
复盘：
```

## 补考

只补失败类别：类型/数值、I/O 分层、方法边界、测试证据或日志定位。3—7 天后使用不同费率/单位题重测。
