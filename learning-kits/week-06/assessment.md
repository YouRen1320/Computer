# Week 06 无 AI 考核与评分标准

## 1. 考核规则

- 总时长：120 分钟编码与排错，另加 20 分钟口述；
- 允许：JDK API 文档、Jackson 官方文档、项目源码、IDE 补全；
- 禁止：Codex、Claude、ChatGPT、搜索答案、复制旧实现；
- 开始前关闭 AI 插件和自动生成；
- 提交：代码、测试输出、评分自评、卡点记录；
- 考后才能打开[独立答案册](./answers.md)。

若环境或依赖在前 10 分钟内无法运行，记录证据后使用纸面伪代码继续；环境问题不自动算通过。

## 2. 综合任务：修复并扩展设备目录导入器

你会拿到一个故意有缺陷的导入器，至少包含以下问题：

- catch Exception 后返回空成功；
- 文件使用默认字符集；
- JSON 直接映射到领域实体；
- 同文件重复 code 会覆盖；
- createdAt 使用真实系统时间；
- 导出直接覆盖目标文件；
- 包装异常丢失 cause。

### 任务 A：失败分类

设计并实现：

- JSON 语法/结构损坏：整批失败；
- 业务字段错误：返回带记录序号、field 和稳定 code 的问题列表；
- 文件技术失败：抛出语义化异常并保留 cause；
- 编程错误：不伪装成导入失败。

### 任务 B：重复与原子语义

- 检测同一文件内重复设备编码；
- 检测仓储已有设备编码；
- 任何问题存在时，本批次不得写入任何设备；
- 测试证明不是“先保存前几条，再发现后面错误”。

### 任务 C：可测试时间

- WorkOrder 的 createdAt 由注入 Clock 产生；
- 使用固定 Instant 测试；
- 将展示区从 UTC 换到 Asia/Shanghai；
- 用一句话解释 Instant 为什么没有变化。

### 任务 D：安全快照导出

- 输出 DTO 与领域实体分离；
- 明确 UTF-8；
- 先写临时文件再替换；
- 在替换前注入失败，证明旧目标保持完整；
- enum 输出稳定 code。

### 任务 E：链表

无 AI 实现反转单链表：

- 空链表；
- 单节点；
- 多节点；
- 时间 O(n)，额外空间 O(1)；
- 画出一次循环中的 previous、current、next 变化。

## 3. 必测场景

至少包含：

1. 合法两条记录；
2. 损坏 JSON；
3. 必填字段空白；
4. 同文件重复；
5. 仓储重复；
6. 文件不存在且 cause 可追踪；
7. 固定 Clock；
8. 导出替换前失败，旧文件不变；
9. 中文 UTF-8 往返；
10. 链表空、单节点和多节点。

## 4. 口述题

不看笔记，每题最多 90 秒：

1. checked 与 unchecked 的选择依据；
2. 为什么不 catch Exception 后返回空列表；
3. try-with-resources 如何处理关闭失败；
4. Path.normalize 的安全边界；
5. Instant、LocalDateTime、ZonedDateTime 的差别；
6. Clock 如何让测试稳定；
7. JSON 解析成功为什么不等于业务有效；
8. DTO 与领域对象为什么分开；
9. 原子导出流程；
10. 链表反转的不变量。

## 5. 100 分评分表

| 部分 | 分值 | 满分证据 |
| --- | ---: | --- |
| 概念解释 | 20 | 口述 8/10 正确，能指出边界和代价 |
| 最小实验 | 15 | cause、Clock、UTF-8、临时替换均有可重复实验 |
| 项目增量（FactoryCare） | 25 | 导入、导出、DTO/领域分离和批次语义完整 |
| 测试与排错 | 20 | 至少 10 场景；真实触发故障并以测试修复 |
| 无 AI 任务 | 15 | 限时完成主要修改与链表题 |
| 复盘与求职 | 5 | 记录卡点、错误假设和一段面试表达 |

### 分项细则

项目增量 25 分：

- 异常分类与 cause：5；
- 整批校验、重复检测、无部分写入：6；
- Clock 与时间语义：4；
- JSON DTO 与领域映射：4；
- 安全快照导出：6。

测试与排错 20 分：

- 成功与边界：5；
- 损坏 JSON、文件失败、重复：6；
- 导出失败保护旧文件：4；
- 测试稳定、不依赖真实时间或用户目录：5。

无 AI 15 分：

- 任务范围主要完成：8；
- 链表正确且有边界测试：4；
- 能解释自己的改动：3。

## 6. 通过门槛

总分至少 75，且同时满足：

- 项目增量（FactoryCare）至少 15/25；
- 测试与排错至少 12/20；
- 无 AI 任务至少 9/15；
- 没有 catch Exception 后假成功；
- 没有 JSON 直接反序列化核心领域实体；
- 没有真实时间或用户主目录依赖；
- 导出失败不会破坏旧文件。

任何一条硬性项失败，即使总分超过 75 也需补考。

## 7. 补考规则

3—7 天内使用不同变体：

- 设备目录改为“位置目录”；
- 重复 key 改为 locationCode；
- UTC/上海改为 UTC/纽约；
- 链表反转改为找中点或判环；
- 导出目标已有旧文件，注入不同失败点。

只补最影响后续的 1—2 个缺口，但必须重新证明硬性项。
