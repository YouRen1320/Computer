# Lab 6：FactoryCare 一页业务说明

- 日期：2026-07-15
- 状态：Week 00 项目准备材料
- 依据：`PROJECT_SPEC.md` 与 `factorycare-design/adrs/0001-modular-monolith.md`

## 一句话业务目标

为制造业和园区设备运维场景中的报修人、维修人员与运维管理员，提供从扫码报修、分诊派单、现场处理到验收关单的统一协作平台，解决设备信息分散、工单流转难追踪、SLA 难管理和维修知识难沉淀的问题。

## 首批用户

| 用户 | 当前问题 | 首批核心动作 |
| --- | --- | --- |
| 报修人 | 不清楚设备信息、报修入口和处理进度 | 扫码报修、补充故障信息、查看进度、确认结果 |
| 维修人员 | 工单信息分散，现场弱网，历史经验难查 | 接单、现场处理、记录工时与结果、查询手册和案例 |
| 运维管理员 | 派单、SLA、权限和处理质量缺少统一视图 | 分诊派单、跟踪超时、管理设备与人员、查看报表 |

## 最小业务词汇

| 词汇 | 本项目中的含义 |
| --- | --- |
| 设备 | 需要被登记、定位、扫码和维护的实体资产 |
| 故障 | 报修人或系统发现的设备异常现象 |
| 工单 | 对一次故障从创建到关闭的可追踪处理记录 |
| 优先级 | 表示故障处理紧急程度的业务属性 |
| 处理人 | 当前负责工单处理的班组或维修人员 |
| 状态 | 工单当前所处的生命周期阶段；具体状态沿用项目唯一状态机 |
| SLA | 对响应和解决时限的服务目标及其计时规则 |

## 技术决策基线

- **JDK 25 LTS**：作为 Java 学习和项目运行基线，获得较长支持周期；不使用 preview API。
- **Spring Boot 4.1 稳定线**：承载 Java 后端与企业应用能力；实际初始化时再锁定当期稳定补丁并验证兼容性。
- **PostgreSQL 18 稳定线**：作为核心事务数据源，支持关系约束、事务、JSON 和后续向量检索；进入数据库阶段再安装和验证补丁版本。
- **模块化单体**：当前由一名学习者建设，优先控制开发、测试、部署和事务复杂度，同时用模块边界为未来拆分保留接缝；详细权衡见 `factorycare-design/adrs/0001-modular-monolith.md`。

## 范围边界

本周只固定目标、用户、词汇和技术方向，不创建 Spring Boot、Vue、uni-app、Flutter、数据库、Redis、消息队列或 AI 服务，不声称系统已经实现。
