## 2. 教学方式

采用“完整主题讲义 + 分步项目 + 按熟悉度提速”。百科是权威知识源和查询入口；[`study-guides/`](./study-guides/README.md) 是面向连续阅读和长期复习的讲义层。每次先形成一个按真实知识主题命名的完整讲义，再进入一个能产生可见行为的项目。

| 当前证据 | 学习通道 | 顺序 |
| --- | --- | --- |
| 新概念或心智模型不稳 | 习得 | 完整主题讲义 → 连续阅读与提问 → 分步项目 → 一个小变化 |
| 以前学过但不确定 | 复健 | 快速浏览讲义 → 只问真实缺口 → 直接进入项目变化 |
| 已能导航和修改 | 工程 | 人定契约 → AI 实现 → diff 审查 → 风险验证 → 需求变化 |

```text
生成或更新按技术主题命名的完整讲义
  → 学习者从头到尾连续阅读
  → 有疑问时按小节提问；熟悉内容直接略读
  → 概念阶段结束后查看项目目标与数据流
  → AI 分步骤提供或实现主要代码
  → 在项目上下文中完成一个小规则变化或审查决定
  → 按风险运行证据
  → 下次课做一次短间隔回忆
```

概念讲义一次性交付，不按小节要求回复“继续”，不在首次阅读中插入输出预测、TODO、代码增量或实现型追问。学习者读完且没有疑问，只表示概念阶段结束。项目阶段最多保留两个真正影响行为的检查点，并且必须先给完整业务上下文。

跟着示例输入代码可以帮助注意和语法熟悉，但逐字复制不是掌握证据；只阅读讲义也不能单独证明整周掌握。每个连贯模块只保留一个分步项目和一个小变化，不要求每章从零重写整套项目。

## 6. AI 怎样参与

AI 的权限随学习通道变化：

- 习得：AI 先生成或更新一份完整主题讲义，让学习者连续阅读和提问；概念阶段不要求补代码；
- 项目：AI 先说明目标与数据流，再提供或实现主要代码；学习者不抄样板，负责理解概念落点和提出疑问；
- 迁移：项目已有上下文后，学习者决定一个规则位置、预期结果或边界，AI 可以实现、解释和排错；若学习者明确跳过决定，则只记录技术实现，不冒充学习者迁移证据；
- 工程：AI 可以生成主要实现与测试，学习者负责需求、边界、diff、风险、验收和回滚；
- 阶段门：项目部分可以用 AI；只有 5—15 分钟的代码导航、解释、局部修改或诊断抽查需要独立完成。

不要求重复输入样板代码。“讲义读完、没有问题”可以结束概念阶段，但整周通过仍需要项目运行和一点超出原说明的证据，例如规则位置判断、diff 审查、边界定义或小需求变化。

## 7. 每周收束

普通周不做百分制考试。用一个 20—45 分钟的连贯任务复用本周代码，判断为“证据通过”或写出一个具体缺口：

1. 一个整合后的行为可以真实运行；
2. 学习者能指出入口、数据流和规则位置；
3. 能补全、迁移或指挥 AI 完成一个非同构的小变化；
4. 验证方式与声明风险相称，已有测试不重复改写；
5. 能区分已验证结果和仍需查询的内容。

G0—G8 阶段门才记录正式分数并做短独立抽查。普通周不因观看、文件数量或 AI 生成完成而自动通过，也不因没有从零手写整套项目而失败。
