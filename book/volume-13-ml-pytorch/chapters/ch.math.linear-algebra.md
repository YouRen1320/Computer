一张设备表可以看成二维表格，一条设备记录可以看成一串数字，多天、多站点、多设备的测量可以组成更多维的数据。线性代数给这些数字一个统一语言：向量表示有顺序的一组分量，矩阵表示按行列组织的二维数组，张量是对更多维数组的统称。真正进入程序后，仅会写公式还不够；你必须始终知道每个轴代表什么、每个维度多长、运算前后形状怎样变化。

本章从零解释向量、矩阵、张量、点积、矩阵乘法、线性变换、轴和广播。我们只讨论数值表示与前向计算，不讲导数、梯度、自动求导或具体深度学习框架。核心方法是“先写形状合同，再手算极小样本，最后让 NumPy 复核”。运行成功不等于语义正确，因为许多错误次序仍能算出一个形状合法却含义错误的数组。

## 1. 从标量到张量

### 1.1 标量

标量是一个单独的数，例如设备温度 `36.5`、工单耗时 `42`、是否启用的数值编码 `1`。标量没有多个分量。单位属于语义合同的一部分：`42 分钟`和`42 小时`虽然数值相同，却不能直接比较。

在 NumPy 中，`np.array(36.5)`是零维数组，形状是空元组 `()`，`ndim` 为 0。Python 的 `float` 也能表示标量，但它不是 `ndarray`。学习形状时要区分“一个 Python 数”和“包含一个元素的一维数组”：前者或零维数组形状为 `()`，后者如 `np.array([36.5])` 形状为 `(1,)`。

### 1.2 向量

向量是有顺序的分量列表。设备特征可写成：

```text
x = [运行小时, 最近七天告警数, 距上次保养天数]
  = [1200, 3, 45]
```

这里位置有含义，不能随便换序。把第一项和第三项互换后，数组仍有三个数字，形状仍是 `(3,)`，但语义已经损坏。因此形状只能防一类错误，字段顺序、单位、缩放口径还需要名称或数据合同约束。

向量可以画成从原点指向某点的箭头，也可以只当作特征容器。几何解释帮助理解方向和长度，数据解释帮助写程序；二者共享相同运算法则。向量 `[x1,x2,x3]` 有三个分量，维数为 3。这里“向量空间的维数”和 NumPy 的 `ndim` 不同：一个含三个分量的 NumPy 向量形状 `(3,)`，数组轴数 `ndim` 仍是 1。

### 1.3 矩阵

矩阵是矩形数字表。两台设备、每台三个特征，可以写成：

```text
X = [[2, 1, 0],
     [1, 3, 2]]
```

它有 2 行、3 列，形状为 `(2,3)`。本章约定第 0 轴是样本轴，第 1 轴是特征轴，即 `X[设备索引, 特征索引]`。`X[1,2]=2` 表示第二台设备的第三个特征。约定不是数学强制规定，却必须在整个项目中一致。

矩阵不能有参差不齐的行。Python 列表可以写 `[[1,2],[3]]`，但它不是规则二维数值矩阵；现代 NumPy 通常会拒绝直接构造成普通数值数组。数据进入矩阵前，应验证每行字段数一致。

### 1.4 张量、阶数与形状

在数据计算语境中，张量通常泛指多维数组。零阶可看作标量，一阶是向量，二阶是矩阵，三阶及以上继续增加轴。例如 2 个站点、3 天、4 个特征可写成形状 `(2,3,4)` 的三阶张量。

必须区分三个量：

- `ndim` 或阶数：轴的数量；`(2,3,4)` 有 3 个轴。
- `shape`：每个轴的长度；这里是 `(2,3,4)`。
- `size`：元素总数；这里是 `2×3×4=24`。

总元素数相同不代表语义相同。`(2,3,4)`、`(3,2,4)`与`(4,6)`都有 24 个元素，却分别可能表示站点—日期—特征、日期—站点—特征和未知二维展开。只保存 `size=24` 无法恢复轴含义。

## 2. 形状合同是第一等设计信息

形状合同描述输入输出的轴名称、次序和长度关系。一个批量线性评分函数可写：

```text
features: (batch, feature)
weights:  (feature, output)
bias:     (output,)
result:   (batch, output)
```

其中 `batch`、`feature`、`output` 是符号维度，不要求提前固定具体数值。合同规定 `features` 的第二维必须等于 `weights` 的第一维，`weights` 的第二维必须等于 `bias` 长度。若输入是 `(2,3)`、权重 `(3,2)`、偏置 `(2,)`，输出就是 `(2,2)`。

### 2.1 为什么先预测形状

先预测能把错误定位到运算之前。如果直接运行，看到一个 `(3,3)` 结果，很容易误以为“能算就对”。写下 `(2,3)@(3,2)->(2,2)` 后，任何 `(3,3)` 都立刻违反合同。预测也是可测试的 oracle：`assert result.shape == (2,2)`。

推荐每一步都记录：

```text
变量名 | 轴含义 | 实际形状 | 预期形状 | 单位/数据类型
X      | 设备,特征 | (2,3) | (B,F) | 已缩放特征
W      | 特征,输出 | (3,2) | (F,O) | 权重
Y      | 设备,输出 | (2,2) | (B,O) | 分数
```

### 2.2 形状正确仍可能错误

两个轴长度恰好相等时，误交换轴可能不改变形状。例如 `(3,3)` 转置后仍是 `(3,3)`。此时必须依赖带有不同数值的手算样本、轴名称与逐元素预期值。测试数据不要全用 0、1 或对称矩阵，否则很多次序错误会被隐藏。

### 2.3 空维、单例维与批次为一

形状 `(3,)` 与 `(1,3)` 不相同。前者是一维向量，后者是“一批、三个特征”的二维矩阵。批次恰好为一时，不应随意 `squeeze` 掉批次轴；否则下游接口会在批量为二时改变行为。单例维长度为 1，常用于广播，但其语义必须明确。

空数组也要设计。形状 `(0,3)` 表示没有样本但仍知道三个特征；形状 `(0,)` 丢失了特征宽度。函数是接受空批次并返回 `(0,O)`，还是拒绝空批次，应写进合同和测试，而不是碰到后临时猜。

## 3. 索引、切片与轴

NumPy 从 0 开始索引。二维数组 `X[i,j]` 访问第 i 行第 j 列。`X[i]` 取一行，通常形状从 `(B,F)` 变成 `(F,)`；`X[i:i+1]` 保留二维形状 `(1,F)`。两者数值看似一样，后续矩阵乘法和广播行为可能不同。

### 3.1 轴不是“横着还是竖着”的模糊说法

轴是索引坐标中的位置。对 `(station,time,feature)`：

- `axis=0` 沿站点轴聚合，结果保留时间和特征；
- `axis=1` 沿时间轴聚合，结果保留站点和特征；
- `axis=2` 沿特征轴聚合，结果保留站点和时间。

“沿某轴求和”意为那个轴被消去。例如 `(2,3,4)` 对 `axis=1` 求和得到 `(2,4)`。不要靠记“行/列”处理三维数组，应写轴名和消失后的预期形状。

### 3.2 `keepdims`

聚合默认删除被聚合轴。`X.mean(axis=0)` 对 `(B,F)` 得 `(F,)`；使用 `keepdims=True` 得 `(1,F)`。保留单例轴有利于后续按特征广播，例如中心化 `X - mean`。它不是多余括号，而是形状合同的一部分。

### 3.3 转置与换轴

二维矩阵转置把 `(R,C)` 变成 `(C,R)`，元素满足 `A.T[j,i]=A[i,j]`。三维以上的 `.T` 会反转所有轴，常常不是你想要的业务排列。更清楚的做法是 `np.swapaxes(a,0,1)` 交换两个轴，或 `np.transpose(a,(1,0,2))` 明确新轴顺序。

换轴只改变视图中的索引解释时，可能不复制底层数据；但本章关注语义，不以“是否复制”代替正确性判断。换轴后用一个带标签的元素验证，例如新数组 `[time,station,feature]` 某位置应等于原数组 `[station,time,feature]` 对应位置。

### 3.4 重塑不是换轴

`reshape` 在元素顺序约束下改变形状，`transpose` 改变轴的排列。把 `(2,3)` reshape 成 `(3,2)` 并不等于转置。例：

```text
A = [[1,2,3], [4,5,6]]
reshape(3,2) = [[1,2], [3,4], [5,6]]
A.T         = [[1,4], [2,5], [3,6]]
```

总元素数允许 reshape，只证明存储数量匹配，不证明轴语义允许重组。

## 4. 向量的基本运算

同维向量可逐分量相加：`[a,b]+[c,d]=[a+c,b+d]`。数乘把每个分量乘同一标量。向量减法描述差异，范数描述大小。二维欧氏范数为 `sqrt(x1²+x2²)`，更高维同理。

### 4.1 点积

同长度向量的点积是对应分量乘积之和：

```text
[2,3] · [4,5] = 2×4 + 3×5 = 23
```

结果是标量。点积可解释为加权和，也与方向相似程度有关。在设备评分里，特征 `[2,3]` 与权重 `[4,5]` 点积 23，代表两个特征贡献之和，但只有特征单位与缩放合同明确时，这个分数才有业务解释。

长度不同不能做普通点积。先检查 `(F,)·(F,)->()`。不要为“让代码通过”而截短较长向量；那会静默丢字段。

### 4.2 逐元素乘法不是点积

`a*b` 对两个 `(F,)` 数组得到 `(F,)`，保留各分量乘积；`a@b` 或明确的点积得到标量。前者 `[8,15]`，后者 `23`。二者可能都能运行，所以结果形状是首个证据。

### 4.3 长度、距离与相似度边界

欧氏距离是差向量范数，余弦相似度用点积除以两个范数。零向量没有可定义的普通余弦方向，必须处理零分母。相似不表示因果或业务等价；尺度不同也会改变距离。是否标准化属于后续数据合同，不应由线性代数函数暗中决定。

## 5. 矩阵乘法

若 A 形状 `(m,n)`，B 形状 `(n,p)`，则 `A@B` 形状 `(m,p)`。中间两个 n 必须相等，结果保留外侧 m 和 p。第 i 行第 j 列是 A 第 i 行与 B 第 j 列的点积：

```text
C[i,j] = Σ(k=0..n-1) A[i,k] × B[k,j]
```

这是“行乘列”，但更可靠的记法是轴合同 `(row,inner)@(inner,column)->(row,column)`。

### 5.1 完整手算 oracle

令：

```text
X = [[2,1,0],
     [1,3,2]]                 shape=(2,3)

W = [[1,2],
     [0.5,-1],
     [3,1]]                   shape=(3,2)
```

预测 `X@W` 为 `(2,2)`。四个元素分别是：

```text
C00 = 2×1 + 1×0.5 + 0×3 = 2.5
C01 = 2×2 + 1×(-1) + 0×1 = 3
C10 = 1×1 + 3×0.5 + 2×3 = 8.5
C11 = 1×2 + 3×(-1) + 2×1 = 1
```

所以 `C=[[2.5,3],[8.5,1]]`。再加偏置 `[10,-2]`，按每行广播得到 `[[12.5,1],[18.5,-1]]`。这个小样本包含零、负数、小数和不对称结果，能暴露较多错误。

### 5.2 次序通常不能交换

一般 `A@B != B@A`。甚至一个方向合法，另一个方向非法。上例 `X@W` 是 `(2,2)`；`W@X` 也恰好合法，因为 `(3,2)@(2,3)` 得 `(3,3)`，但它完全不是“每台设备的两个输出”。没有异常，却违反预期形状，这是典型语义故障。

### 5.3 单位矩阵、零矩阵与对角矩阵

单位矩阵 I 的对角线为 1，其余为 0，满足 `AI=A` 和 `IA=A`（形状匹配时）。零矩阵把线性部分归零。对角矩阵可独立缩放各坐标。它们适合作为测试输入，但不能只测单位矩阵，因为错误次序常被其对称性隐藏。

### 5.4 `@`、`matmul`、`dot`

对两个二维 NumPy 数组，`A @ B` 与 `np.matmul(A,B)`表达矩阵乘法，官方文档建议二维矩阵积优先使用 `@`。`np.dot` 对一维、二维和高维有不同规则，初学阶段容易混淆。教材示例用 `@` 表达明确的向量/矩阵乘积，用 `*` 表达逐元素乘法。

NumPy 官方也明确指出线性代数中的“矩阵”通常指二维 `ndarray`，不是旧式 `np.matrix`；新代码不要引入 `np.matrix` 来获得特殊乘法语义。

## 6. 线性变换与仿射变换

矩阵 W 可看成一个把输入向量映射到输出向量的线性函数 `y=W x`（使用列向量约定时）。它保持向量加法与数乘：`W(u+v)=Wu+Wv`、`W(cu)=cWu`。旋转、缩放、投影都是典型线性变换。

程序里的批量样本常采用行向量约定，因此写成 `Y=XW`。这并不矛盾，只是每个样本放在 X 的一行。必须说明约定，不能从公式图片直接复制次序。

加入偏置 `b` 后得到 `y=Wx+b` 或批量形式 `Y=XW+b`，严格说这是仿射变换，因为它不一定把零映射到零。工程中常把它口语化称“线性层”，但数学边界要知道。

### 6.1 每一列权重的含义

在 `X(B,F) @ W(F,O)` 中，W 的第 j 列为第 j 个输出提供 F 个权重。结果 `Y[i,j]` 是第 i 个样本与第 j 列权重的点积，再加 `b[j]`。从索引公式理解后，形状不再靠死记。

### 6.2 组合变换

先做 A 再做 B，对列向量是 `B(Ax)=(BA)x`；矩阵乘法次序与执行顺序相反。批量行向量约定下会写成 `(XA)B=X(AB)`。结合律允许改变括号，但不允许交换次序。选择括号还可能影响中间数组大小和性能，但任何优化都必须保持数学结果合同。

## 7. 广播

广播让不同形状的数组进行逐元素运算。它不是矩阵乘法规则。NumPy 从最右边的维度向左比较；每一对维度相等，或其中一个为 1，才兼容。缺失的左侧维度按 1 看待。结果每个维度取兼容后的较大值。

### 7.1 标量广播

`(B,F)` 数组加标量 `()`，标量概念上应用到每个元素，结果仍 `(B,F)`。NumPy 通常无需真的复制 B×F 份标量。

### 7.2 按列偏置

`Y` 为 `(B,O)`，`b` 为 `(O,)`。从右对齐：O 与 O 相同，b 缺失的批次维看作 1，因此可扩展为每行相同偏置，结果 `(B,O)`。这是 `X@W+b` 的合同。

### 7.3 合法却意外的广播

列向量 `(2,1)` 加一维向量 `(2,)`：

```text
(2,1)
  (2)  -> 看作 (1,2)
结果 (2,2)
```

如果你原本希望两个对应元素相加得到 `(2,1)`，这个合法扩展就是 bug。广播不会理解“两个 2 都代表设备”；它只按位置和长度工作。解决办法是把两个数组都规范成 `(2,1)`，并断言结果形状。

### 7.4 非法广播

`(2,3)+(4,)` 从右比较 3 与 4，既不相等也没有 1，因此抛 `ValueError`。异常文本中的两个形状是首个可信证据。不要在捕获后随意 flatten 或 resize；先查轴语义。

### 7.5 广播与内存

广播常避免显式复制，但某些组合会产生巨大的结果，例如 `(100000,1)+(1,100000)` 得一百亿元素。规则合法不代表资源可接受。运行前预测结果形状，也是在预测内存数量级。生产计算还要设置批次上限和资源监控。

## 8. 数据类型与数值边界

形状正确不保证数值安全。整数乘加可能溢出，浮点数存在舍入误差，缺失值可能传播。NumPy 数组通常有统一 `dtype`。用设备计数时可能是整数，用归一化特征和权重时通常是浮点数。

### 8.1 整数溢出

固定宽度整数超过范围可能环绕或产生警告，结果仍有相同形状。高数量级乘法应选择足够宽的类型并做边界测试。不要看到 Python 普通整数可任意增大，就假定 NumPy 固定宽度整数也一样。

### 8.2 浮点比较

许多十进制小数不能被二进制浮点精确表示，因此一般用 `np.testing.assert_allclose` 在声明容差内比较浮点结果；对本来就应精确的整数或简单可精确表示值，可用逐元素相等。容差必须根据问题尺度决定，不能为通过测试无限扩大。

### 8.3 NaN 与无穷

NaN 表示未定义或缺失的数值状态，和任何值（包括自身）的普通相等比较通常为假。无穷可能来自除零或溢出。线性变换入口若合同要求有限值，应显式 `np.isfinite` 检查。选择拒绝、填补还是传播属于数据策略，不应静默发生。

## 9. NumPy 实现模板

```python
import numpy as np

def linear_scores(features, weights, bias):
    x = np.asarray(features, dtype=np.float64)
    w = np.asarray(weights, dtype=np.float64)
    b = np.asarray(bias, dtype=np.float64)

    if x.ndim != 2 or w.ndim != 2 or b.ndim != 1:
        raise ValueError("expected 2-D, 2-D, 1-D")
    if x.shape[1] != w.shape[0]:
        raise ValueError("inner dimensions differ")
    if w.shape[1] != b.shape[0]:
        raise ValueError("bias width differs")

    result = x @ w + b
    assert result.shape == (x.shape[0], w.shape[1])
    return result
```

这段实现先标准化类型，再验证阶数、内维和偏置，最后运算并检查后置条件。`assert` 适合内部不变量；用户输入校验应显式抛异常，因为优化模式可以禁用断言。

### 9.1 手写三重循环的价值

学习时为 2×3 与 3×2 写一次循环，可以把索引公式变成直觉；生产中应使用经过优化和充分测试的 NumPy 运算。手写版本作为小规模 oracle，不承担大数据性能。正确的验证是两条独立路径：纸笔/朴素循环与 NumPy 结果一致，而不是用同一实现算两次。

### 9.2 版本表面与稳定核心

截至 2026-07-24，NumPy 稳定文档显示 2.5 手册；本仓库当前可执行环境实际验证的是 Python 3.14.3 与 NumPy 2.4.4。向量分量、点积定义、矩阵乘法内维规则、轴与广播的一般规则属于稳定数学/数组核心。具体函数签名、新增 `numpy.linalg` 辅助函数、错误措辞、类型推断和性能属于版本表面，使用时以目标环境官方文档与测试为准。

本章没有声称在 NumPy 2.5 上实测，也没有把本机输出包装为所有平台结论。NumPy 线性代数底层可能使用不同 BLAS/LAPACK 实现，线程与性能会因平台变化；小矩阵数学 oracle 应一致，但耗时不能从本机推广。

## 10. 故障定位：先判断失败阶段

### 10.1 构造阶段

症状：参差列表无法形成规则数组、字符串混入导致类型异常。首证据是数组构造处异常和输入样本。修复数据合同，不要直接设 `dtype=object` 绕过数值矩阵要求。

### 10.2 前置合同阶段

症状：`ndim`、内维或偏置宽度不匹配。首证据是函数抛出的包含实际形状的 `ValueError`。修复调用方的轴排列、特征选择或权重版本，不能靠删断言。

### 10.3 运算阶段

症状：`matmul` 内维错误、广播不兼容。首证据是异常里的操作数形状。把形状按右对齐或内维规则写在纸上，再决定 transpose/reshape 是否语义正确。

### 10.4 后置 oracle 阶段

症状：运算完成但形状或元素不等于预期。矩阵次序反转、错轴聚合、合法意外广播多发生在这里。首证据是“预期形状/手算元素 vs 实际结果”，不是最后一行 `PASS/FAIL`。

### 10.5 数值阶段

症状：形状正确但包含 NaN、无穷或误差过大。检查输入有限性、dtype、数值范围和容差。不要先调整预期值；先证明数学 oracle 和单位。

## 11. 四类典型故障的修复路径

### 11.1 矩阵次序错误

先列语义轴：`设备×特征`、`特征×输出`。再写预期 `(B,F)@(F,O)->(B,O)`。如果反序结果也合法，用非方阵和不对称手算值暴露。修复后重跑原测试，而不是新增一个只覆盖修复路径的宽松测试。

### 11.2 轴含义错误

为轴命名，选一个可追踪元素，验证换轴前后索引映射。聚合时写“哪个轴消失”。残余风险是多个轴长度相同导致形状断言无法发现，需用标签数据或属性测试补充。

### 11.3 广播方向错误

将两个形状从右对齐，在每一维标相等、为 1 或冲突。对单例轴明确 `(B,1)` 还是 `(1,F)`。修复后断言结果形状和至少两个不相同元素。残余风险是未来 B 或 F 恰好相等，错误数组又变得合法。

### 11.4 行列不匹配

异常是正确保护，不应吞掉。记录实际形状、期望符号形状和数据版本。常见根因是特征列表变更但权重未同步。需要在边界按特征名称对齐，而不是只按数量截取。

## 16. 参考答案要点

1. `(4,2)`，内维 3 被求和，保留外侧 4 和 2。
2. 能，`(5,1)` 与 `(1,3)` 对齐，结果 `(5,3)`。
3. 前者没有批次轴，后者明确批次为一，索引和后续乘法行为不同。
4. `(2,4)`；若 `keepdims=True` 则 `(2,1,4)`。
5. `*`逐元素，`@`矩阵乘法；输出形状和数学含义不同。
6. 对称性、相同维度或相同数值可能让错误次序产生相同/貌似合理结果。
7. 字段名合同、单位、非对称带标签样本和逐元素手算 oracle。
8. NumPy只检查维度兼容，不知道轴代表设备还是特征。
9. reshape 按元素顺序重新分组，转置重新排列轴索引。
10. Java 拥有业务事实和授权边界；Python 结果只能作为受合同约束、可重建的派生输入。
