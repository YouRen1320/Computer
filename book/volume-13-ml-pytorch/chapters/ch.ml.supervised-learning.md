# 回归、分类与决策边界

监督学习从带答案的历史样本中学习映射：输入设备和工单特征，输出维修时长或“是否超时”的估计。它不会自动发现业务真理。标签可能错误，训练数据可能只代表过去，模型还可能记住训练样本而不能处理未来。本章从一个样本、一列特征和一次手算开始，建立回归、分类、损失、正则化、残差、概率与阈值的完整边界。

## 1. 先认识数据表中的四个角色

一行通常称为一个**样本**。每个样本用于预测的输入列称为**特征**，希望模型学习的答案称为**目标或标签**，样本身份和时间等审计列用于划分与追踪，不应不加判断地作为特征。

例如历史工单表有 `device_age_days`、`alarm_count_7d`、`technician_level`、`opened_at`、`repair_minutes` 和 `was_overdue`。预测维修分钟时，`repair_minutes` 是连续目标；预测是否超时时，`was_overdue` 是类别标签。`closed_at` 在工单创建时尚不存在，把它放进特征就是时间泄漏。

用矩阵记号，`X` 是形状为 `(样本数, 特征数)` 的特征矩阵，`y` 是对应目标。第 i 行 `X[i]` 必须与 `y[i]` 属于同一业务事件。索引错位、连接重复或过滤后未同步标签会让程序能运行却学习错误关系。

## 2. 回归还是分类由问题语义决定

**回归**预测有数量尺度的值，如维修分钟、能耗和费用；误差 10 分钟与 100 分钟有大小差异。**分类**预测有限类别，如超时/未超时、故障类型；模型需要区分类别并给出类别概率或分数。

不能只看存储类型。标签 `0/1` 可能是二分类，也可能是次数；故障代码 `101/102/103` 虽是整数，却只是类别编号，不能用均方误差解释代码距离。相反，“未来 7 天告警次数”是整数，但如果关心数值差异，仍可作为计数回归问题。

先写预测时点、输入可用信息、输出含义和决策用途，再选任务。若业务真正需要“是否安排加急”，可以先预测连续超时风险，再由单独的成本策略选阈值；不要让模型类型替代业务决策设计。

## 3. 学习、参数与预测

模型是一族带参数的函数。训练是在训练集上选择参数，使某个损失尽量小；预测是把新特征代入已固定参数。线性回归的一维形式为：

```text
预测时长 = 截距 + 斜率 × 告警数
ŷ = b + w x
```

`b` 和 `w` 是训练得到的参数。超参数则在训练前由人或搜索流程选择，例如正则化强度、迭代次数、特征集合。不要在最终测试集上反复挑超参数，否则测试集也参与了学习。

“拟合”描述参数适应训练数据，“泛化”描述在未见数据上仍有用。训练损失下降只证明优化器更贴近训练样本，不证明泛化。

## 4. 一元线性回归手算

给三条合成样本：告警数 `x=[1,2,3]`，维修分钟 `y=[3,5,7]`。它们满足 `y=1+2x`。普通最小二乘选择直线，使残差平方和最小。一元情形可以手算：

```text
w = Σ((xi-x̄)(yi-ȳ)) / Σ((xi-x̄)²)
b = ȳ - w x̄
```

这里 `x̄=2`、`ȳ=5`；分子 `(-1)(-2)+0+1×2=4`，分母 `1+0+1=2`，所以 `w=2`、`b=1`。对 `x=4` 的预测是 9。

这个手算 oracle 很重要：若库调用输出斜率 -2 或截距 5，先检查形状、行对齐和中心化，而不是相信“机器学习库不会错”。现实数据不会恰好落在直线上，最小二乘只找平方误差意义下最合适的线性近似。

## 5. 多元线性模型与系数解释

多个特征时：

```text
ŷ = b + w1x1 + w2x2 + ... + wpxp
```

它对参数是线性的，并不要求原始业务关系看起来是一条直线。可以加入平方项或交互项作为新特征，但特征构造必须只用预测时可得信息，并在每个训练折内拟合需要学习的转换。

系数 `wj` 的朴素解释是“其他输入保持不变时，xj 增加一个单位，预测改变 wj”。这个解释依赖模型、单位、共线性和数据范围，不自动表示因果。告警数和设备年龄高度相关时，单个系数可能不稳定；模型预测尚可，系数却不能当政策依据。

截距是所有特征为零时的预测。若零不在数据范围，截距主要是数学定位，不一定有业务意义。缩放会改变系数数值，比较重要性前必须统一尺度并考虑相关性。

## 6. 损失函数与业务指标要分开

训练算法优化的量叫损失，验收和业务沟通使用指标。二者可以相同，也可以不同。线性回归常最小化残差平方和或均方误差：

```text
MSE = Σ(yi-ŷi)² / n
```

平方会放大大误差，且便于求解。平均绝对误差 MAE 对离群值相对温和，单位与目标相同。模型用 MSE 训练，不代表上线门槛也必须是 MSE；业务可能更关心 90 分位绝对误差或超出 SLA 的比例。

损失为零只说明这些样本被完美拟合。若特征含标签副本，训练损失同样可以为零。先检查数据合同与留出结果，再讨论优化。

## 7. 残差是诊断入口

残差常定义为 `实际值 - 预测值`：`ei=yi-ŷi`。正残差表示模型低估，负残差表示高估。必须在报告中写清符号约定。

对留出集保存 `y`、`ŷ`、残差、关键切片和样本 ID。若残差随预测值形成弧线，线性关系可能不足；误差随目标增大而扩散，可能存在异方差；某设备类别残差长期为正，说明特征、标签或分布存在分组问题。

残差图是线索，不是自动证明。小样本中的图形可能是随机波动；异常点也可能是合法稀有事件、传感器错误或单位混乱。回到原始记录和标签流程核查。

## 8. 朴素基线是最低对照

回归最简单的基线可以始终预测训练目标均值或中位数。分类可以始终预测训练集中多数类，或使用当前业务规则。模型若在独立留出集上不能超过合理基线，就不应因为“用了算法”而上线。

基线只能从训练数据计算。用整个数据集均值预测测试集，会让测试信息进入模型。基线也要匹配业务：多数类准确率在稀有故障中很高却毫无召回；当前人工规则可能比多数类更有价值，应一起比较。

报告应保存基线定义、拟合数据范围、预测和同口径指标。只写“比 baseline 好 10%”而无分母和样本范围不可复核。

## 9. 训练集、验证集与测试集

训练集用于拟合参数；验证集或交叉验证用于选择特征、模型和阈值；最终测试集只在方案冻结后提供一次近似无偏评估。样本少时可在训练部分做交叉验证，仍保留最终测试集。

划分必须模拟未来使用。相同设备的相邻工单高度相关，随机按行拆分可能让同一设备同时进入训练和测试；应按设备分组。预测未来时通常按时间向前验证，不能用未来样本训练过去。

所有会“学习数据”的步骤都只在训练部分拟合：缺失值、均值方差、类别词表、特征筛选、PCA 和目标编码。先用全量数据标准化再拆分也是泄漏。

## 10. 过拟合与欠拟合

欠拟合是模型连训练规律也表达不好，训练和验证误差都高；过拟合是训练很好、验证明显恶化。复杂度相对数据量、噪声和任务而言，不是“某算法永远复杂”。

诊断至少看训练与验证曲线、不同数据量表现、基线和误差切片。仅凭训练分数不能区分好模型和记忆器。验证差距也可能来自划分分布不同、预处理不一致或标签质量变化，不应立刻增加正则化掩盖数据问题。

收集更多代表性数据、简化特征、加强正则化、改进标签和调整模型都是可能措施，必须由证据选择。

## 11. 正则化的目标与方向

正则化在拟合损失之外惩罚参数规模。L2 常加入 `λΣwj²`，L1 加入 `λΣ|wj|`。较大的 `λ` 通常带来更强惩罚，使系数整体更靠近零；它可能降低方差、改善泛化，也可能导致欠拟合。

“正则化越大分数越高”是错误规则。应在训练折内对候选强度做验证，并保存训练/验证指标与系数范数。库的参数命名可能使用惩罚强度 `alpha`，也可能使用其反向量 `C`；理解 API 定义后再判断方向。

截距是否惩罚、特征是否标准化也会影响结果。不同单位特征若未缩放，L1/L2 对系数数值的惩罚并不公平。本章手写岭回归明确不惩罚截距，实际库调用需核对文档。

## 12. 分类从分数到概率

二分类逻辑回归先计算线性分数 `z=b+w·x`，再通过 sigmoid：

```text
p = 1 / (1 + exp(-z))
```

`z=0` 时 `p=0.5`；z 越大，p 越接近 1。训练常使用对数损失，让正确类别概率低时受到大惩罚。逻辑回归名字含“回归”，在机器学习任务分类中却是分类器，因为目标是类别并输出类别概率。

概率输出不是天然可信概率。类别不平衡、正则化、采样、数据漂移和模型错误都会造成校准偏差。需要用独立验证数据检查概率区间内真实发生率；不能把 0.8 解释为“必然发生”。

## 13. 决策边界是什么

给定阈值 0.5，逻辑回归把 `p>=0.5` 判为正类。因为 sigmoid 单调，这等价于 `z>=0`；二维特征中 `b+w1x1+w2x2=0` 是一条直线，分隔两侧预测类别，这就是决策边界。

改阈值会移动判定边界对应的分数条件，但不会重新训练概率模型。非线性特征或其他模型可以形成弯曲边界。二维图只是高维边界的投影，不能证明所有样本可分。

边界附近的样本更容易因测量误差或漂移改变决策。保存距离/概率、原始特征和不确定性策略，比只保存 0/1 更利于复盘。

## 14. 阈值是业务策略，不应藏在模型里

默认 0.5 不是自然法则。如果漏掉真正超时工单代价很高，可以降低阈值提高召回，但会增加误报；人工复核资源有限时又要限制误报量。

模型版本输出概率，策略版本根据预先声明的成本、容量和公平约束选择阈值。阈值应配置化、可审计、在独立验证集选择，并与指标报告共同保存。不能看完测试结果后挑一个最漂亮阈值再把同一测试分数当最终证据。

阈值改变还可能影响不同设备类别或站点。全局收益更好并不保证每个关键切片都可接受，后续指标章会系统处理。

## 15. 类别标签与正类定义

分类前明确类别集合、正类和标签来源。`1` 应表示哪种事件？标签是在预测时点之后多久观察？未关闭工单是否被误标为未超时？如果观察窗口不完整，负类可能只是“尚未发生”。

类别编号无大小意义。多分类的 `class 2` 不比 `class 1` 更严重，除非业务明确有序并选择对应方法。二分类翻转正类会交换 precision/recall 语义，报告必须写清。

标签由 Java 权威业务流程产生；Python 可以读取版本化快照训练派生模型，不能自行覆盖工单状态来“修正标签”。疑似标签错误进入数据质量反馈流程。

## 16. 标签类型与任务不匹配

把 `"LOW"/"HIGH"` 字符串交给线性回归数值求解会直接报类型错误；把故障代码转整数后回归则更危险，因为程序能运行并产生不存在的“中间类别”。首证据不是某个分数低，而是目标定义和唯一值/数据类型与任务合同不符。

反方向也常见：把连续分钟分箱成是否超过 60 分钟，丢失了多少分钟的数量信息。若最终决策确实只关心 SLA，这可能合理；若还要排班和估时，应该保留回归目标或做多任务评估。

任务定义属于建模之前的业务协议，不能通过换一个能接受输入的算法绕过。

## 17. 从数据到模型的无泄漏顺序

建议顺序：

1. 定义预测时点、目标、实体和评价单位。
2. 冻结带数据版本的原始快照，只读保存。
3. 按时间/设备/用户等真实独立单位划分。
4. 仅在训练部分拟合清洗、缺失填补、缩放和类别映射。
5. 建立朴素和业务基线。
6. 训练候选模型，在验证部分选择超参数与阈值。
7. 冻结方案，在测试集一次评估。
8. 保存预测、残差/概率、切片、代码、依赖和随机种子。

任何“先看看全量相关性再决定特征”的操作都可能把测试知识带入选择。探索性分析可以使用专门探索集，最终结论需在未参与选择的数据上验证。

## 18. 小数据 oracle 比黑盒分数更重要

复杂训练前先建立能手算的小数据：`x=[1,2,3]`、`y=[3,5,7]` 的斜率 2、截距 1；分数 `[-ln3,0,ln3]` 的 sigmoid 概率是 `[0.25,0.5,0.75]`；阈值 0.7 只选最后一项。

这些 oracle 验证公式、轴、符号、阈值比较符和输出顺序。大数据测试只能告诉你某次结果，不容易定位基础实现错误。每次重构仍保留小数据测试。

容差必须有依据。浮点比较使用 `pytest.approx` 或 `numpy.testing`，不要因为失败就把容差调到足以隐藏错误。整数混淆矩阵和键集合应精确相等。

## 19. 可复现不只是一颗随机种子

记录 Python、NumPy、pandas、测试工具版本，输入快照哈希、特征顺序、标签查询、划分 ID、随机生成器、算法配置和输出。线性代数底层库、硬件和并行执行可能造成末位差异，因此数值 oracle 使用合理容差并保存汇总。

随机种子能复现一次随机序列，不能修复抽样偏差，也不能保证跨版本字节完全相同。必须分开报告“实验可重跑”和“结论能泛化”。

本章资产用 NumPy 手写最小算法，目的是暴露数学过程；生产可使用成熟库，但必须锁版本、使用管线、阅读当前 API 并重跑相同合同。

## 20. 数据泄漏的常见形式

- 特征直接包含目标、目标后发生的字段或人工处置结果。
- 全量数据先标准化、填补、特征选择，再交叉验证。
- 同一设备、工单副本或相邻窗口跨训练和验证。
- 用测试集反复选择特征、正则化或阈值。
- 聚合特征计算时包含预测时点之后的记录。
- 标签编码、目标均值编码在全量数据拟合。

泄漏通常让分数异常漂亮。首证据来自字段可用时间、实体交集、预处理拟合索引和数据血缘，不是“模型太强”。修复后分数下降是评估变诚实，不是修复失败。

## 21. 训练分数不能作为泛化结论

报告 `training accuracy=100%` 没有说明新工单表现。最低可信证据包括未参与拟合的预测、同口径基线、样本数量、划分规则、误差或混淆明细。若模型选择和阈值也使用了该留出集，它只是验证集，不再是最终测试集。

训练指标仍有诊断价值：连训练集都不如基线可能是实现或容量问题；训练极好、验证很差提示过拟合或分布差异。但它必须与留出证据成对出现。

不能挑最好的一次随机划分报告。保存所有预先约定折或种子的结果及离散程度，下一章详细展开。

## 22. 维修时长回归实验应保存什么

最小工件包括：训练/留出样本 ID；特征 schema 与单位；训练均值基线；线性模型截距、系数和正则化强度；每条留出样本的真实值、预测、残差；MAE/RMSE；按设备类别、站点和工单优先级的切片；输入和代码版本。

系数只在相同预处理和单位下解释。维修分钟被转成小时后，系数数值会按比例变化但预测可等价。残差符号约定要写入报告。

若留出集只含 2 条合成样本，只能验证代码和公式，不能声称生产效果。本章 Lab正是这种教学证据，并明确限制。

## 23. 超时分类实验应保存什么

保存正类定义、观察窗口、训练类别比例、概率、阈值、预测类、真实类和混淆矩阵。至少比较多数类/当前规则基线，并展示多个阈值的 precision、recall、误报量和漏报量。

概率样本必须能从保存的 `b`、`w` 与特征复算；阈值决策能从概率和策略版本复算。只保存最终 0/1 会丢失重新选择阈值和校准检查的能力。

若训练时对少数类过采样，输出概率可能不再反映真实先验，需要在自然分布验证集校准和评价；不要在重采样训练集上报告准确率。

## 24. 四类故障的定位模板

### 24.1 标签与任务不匹配

检查目标定义、dtype、唯一值、单位和观察窗口。首证据是标签 schema 与任务合同冲突。修复定义或选择合适任务，重跑小数据和留出比较；残余风险是标签语义仍可能漂移。

### 24.2 只报训练分数

首证据是报告没有独立样本 ID和留出预测。修复为先划分、训练拟合、留出评估并加入基线。残余风险是实体/时间泄漏，需审计划分。

### 24.3 概率阈值写死

首证据是在模型函数内部出现 `>=0.5` 且没有策略版本或成本依据。让模型输出概率，策略层从配置选择阈值；重跑阈值矩阵和关键切片。残余风险是概率漂移和容量变化。

### 24.4 正则化方向误解

首证据是更强惩罚反而被断言系数范数必增，或把库的 `C` 当 `alpha`。用小矩阵比较系数范数并核对官方 API。修复后重跑训练/验证曲线；残余风险是缩放和共线性。

## 25. FactoryCare 架构边界

Java 后端拥有工单、设备、SLA、用户权限、状态迁移和最终审计。Python 训练服务只读取经授权、版本化的只读快照，产出可重建的模型、概率、建议和解释。预测“超时概率 0.8”不能直接把工单改为加急，也不能覆盖 Java状态。

需要动作时，Python 把模型版本、输入版本、概率和建议阈值结果提交到 Java受控 API；Java重新验证权限、当前状态、幂等和业务规则。原始标签修订也在权威系统完成，再重建训练数据。

模型不是事实数据库。删除模型和派生特征后应能从权威快照与版本化代码重建；无法重建的人工判断要回到正式业务记录。

## 26. AI 辅助开发边界

AI可以解释公式、生成手算测试、搭建数据表、列出泄漏检查和比较残差，但必须给它明确目标、预测时点、正类、划分单位和业务成本。让 AI“自动选择最好模型”而不提供这些合同，只会更快地产生不可信分数。

审查 AI代码：是否在拆分前拟合预处理；是否把标签后字段当特征；是否只打印训练分数；是否把 0.5 藏在预测函数；是否把类别编号回归；是否误读正则化参数；是否丢掉样本 ID；是否把相关性写成因果。

开发者必须能手算一个预测、一个残差、一个 sigmoid 和一个阈值决策。工作时可以 vibe coding，但不能 vibe judging。

## 28. 120 秒讲回

“监督学习用带标签样本学习 `X→y`。回归预测有数量尺度的值，分类预测类别或概率，任务由目标语义而非存储类型决定。线性回归最小化残差平方，残差是实际减预测；逻辑回归把线性分数经 sigmoid变成正类概率，阈值是独立业务策略。训练分数不能证明泛化，必须先按时间/实体划分，预处理只在训练数据拟合，并与朴素基线比较。正则化越强通常越收缩系数，但不保证验证更好。越界反例是让 Python预测直接修改 Java工单状态；模型只能产出可重建建议，Java仍裁决业务事实。”

## 29. 完成判据

你应能独立手算一元直线、残差和 sigmoid；从标签语义判断回归/分类；解释系数、损失与指标的边界；区分训练、验证、测试；列出至少四类泄漏；解释 L1/L2 方向；把概率与阈值拆开；保存能复算的留出证据；面对四类故障指出阶段与首证据。

脚本判据：example、lab、private 退出 0；public exercise稳定退出 41。Lab的模型在固定留出集以同口径超过训练数据基线，残差从 `y-ŷ`复算，分类概率从参数复算，多个阈值决策可复核。它证明教学实现，不证明生产泛化。

## 30. 外推、漂移与拒绝决策

模型只在训练数据覆盖的区域获得经验。设备年龄训练范围是 30～1000 天时，给 5000 天设备做线性预测属于外推；公式仍会返回数字，却没有相邻样本支撑。分类概率也一样，极端输入得到 0.99 不代表证据更强。保存每个特征的训练范围、类别词表和缺失模式，对明显越界输入报警、拒绝自动决策或转人工。

数据分布会随设备更新、SLA调整、录入流程和站点扩张变化。输入漂移不一定导致性能下降，标签关系变化也可能在输入分布稳定时发生。因此同时监控输入、预测、阈值后动作和延迟标签上的真实误差；监控告警是调查入口，不是自动重训命令。

自动重训仍需冻结数据窗口、无泄漏划分、基线门槛、审批和回滚。新模型整体指标更好但关键设备切片更差时不能静默替换。模型版本与阈值策略分开部署，使概率模型未变时可以审计策略调整，也避免把一次业务容量变化误当成模型重新训练。

拒绝决策不是失败。对缺字段、未知类别、严重越界、概率靠近边界或模型版本不可用的请求，返回“需要人工复核”往往比强行给出 0/1 更可靠。拒绝率、人工处理结果和后续标签应进入监控，但是否允许自动动作仍由 Java业务策略裁决。
