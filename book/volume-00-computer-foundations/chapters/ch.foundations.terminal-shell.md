# 终端、Shell、命令与引用规则

第一次打开“终端”时，屏幕可能只有一行提示符和一个闪动光标。它看起来不像网页，也没有明显按钮，于是初学者容易产生两个极端印象：要么认为终端是一种高深编程语言，要么把网上看到的每一行文字都原样粘贴进去。两种理解都不安全。

终端首先是一个文字交互界面，Shell 是在其中读取字符、解释命令语法并启动命令的程序。命令又是另一个程序或 Shell 自己提供的操作。你输入的一行文字不会“整体原封不动”交给命令；zsh 会先识别命令名、参数边界、引号、转义和 glob，再把解析后的参数交给目标程序。空格、星号和引号因此既可能只是文件名中的字符，也可能在 Shell 解析阶段承担语法职责。

本章只建立一条安全而精确的最小链路：终端与 Shell 的职责、提示符与命令的边界、当前工作目录、命令名与 argv、单引号与双引号、反斜杠转义，以及 glob 文件名匹配。我们会使用 macOS 自带的 Terminal 或 IDE 终端、zsh、`pwd`、`cd`、`ls` 和一个固定的 Ruby 参数观察器。管道、标准输入输出的系统模型、重定向和退出状态属于后续章节；本章遇到相关符号时只标明“尚未学习”，不会把它们偷偷塞进练习。

## 学完后你必须能做什么

读完并完成实验后，你应当能够：

1. 区分终端窗口、zsh、提示符、命令和被启动程序，避免把它们统称为“黑框”；
2. 说明 Shell 收到键盘字符后，为什么要先解析再启动命令；
3. 用 `pwd` 观察当前工作目录，并解释相对路径为何必须绑定这个起点；
4. 用 `cd` 在固定练习树内改变工作目录，再用观察而不是记忆确认结果；
5. 把一条简单命令拆成命令名和若干参数，预测程序最终收到的 `argv`；
6. 解释未引用空格为何会切开 token，引号为何通常不会成为参数内容；
7. 根据“是否需要字面值、是否需要保留部分 Shell 解释”选择单引号、双引号或局部转义；
8. 区分字面 `*` 与未引用 glob，预测零个、一个和多个文件匹配时的风险；
9. 面对“路径不存在”“参数数量不对”“文件数量忽然变化”，从 cwd 与 argv 开始定位；
10. 在执行 AI 或网页给出的命令前识别未解释的路径、通配符与个人环境依赖，先移到隔离练习目录验证。

这里的掌握标准不是“记住十条命令”，而是能够对一条没见过的简单命令画出解析边界，预测参数，安全运行，制造一个受控错误，修复后复跑原验证。

## 零基础补救：界面上每一块是什么

### 终端窗口

终端应用负责显示文字、接收键盘输入并与前台程序交互。在 macOS 上，你可能使用 Terminal.app、iTerm2、VS Code 集成终端或 IntelliJ 的 Terminal 面板。它们外观不同，但“终端界面”与“解释命令的 Shell”仍是两个职责。

同一个 Terminal 窗口可以运行 zsh，也可以暂时运行 Ruby、Java 或其他交互程序。此时键盘输入由当前前台程序处理，不一定仍由 zsh 解释。反过来，同一个 zsh 也可以出现在不同终端应用里。看到黑色背景不能证明使用的是哪一种 Shell；看到 `%` 或 `$` 也只是线索，不是完整证据。

### Shell

Shell 是一个程序。它通常循环做几件事：显示提示符、等待输入、解析输入、找到并启动命令、等待下一次输入。macOS 当前常见默认交互 Shell 是 zsh，但项目脚本可能明确要求其他 Shell。本章所有可运行资产都明确使用 `/bin/zsh -f`，其中 `-f` 让固定验证不加载个人 zsh 配置，避免别名、插件或主题改变结果。

“Shell 是程序”有一个重要后果：它也有版本、配置、状态和语法。网页上的命令在作者的 Shell 中成立，不代表在你的 Shell、当前目录和文件集合中自动成立。先确认上下文，才能谈复制。

### 提示符

提示符是 Shell 告诉你“现在可以输入”的显示内容，常包含用户名、主机名、当前目录缩写或分支。下面只是界面示意：

```text
learner@mac Computer % pwd
```

这里真正输入的命令通常只有 `pwd`。`learner@mac Computer %` 是提示符，不应从教程中一起复制。教程有时用 `$`、`%` 或 `>` 作为排版标记；复制前要区分它是语法还是展示。

提示符可能被主题高度定制，所以不要用颜色或图标推断命令成功。可靠观察来自你明确运行的固定命令和它的结果，而不是提示符“看起来正常”。

### 命令

“命令”在日常交流中有两层含义：一是你提交给 Shell 的整行输入，二是这一行解析出的命令名。例如：

```text
ruby argv_probe.rb alpha beta
```

Shell 解析后，命令名是 `ruby`，后面有三个参数文本：脚本路径 `argv_probe.rb`、`alpha`、`beta`。Ruby 启动后还会把脚本路径用于选择程序，而脚本中的 `ARGV` 通常只包含 `alpha` 和 `beta`。这说明不同运行时对“自己的参数”还有一层约定；本章只观察最终程序报告的边界，不扩展到每种语言的启动规范。

## 直觉模型：前台、翻译员与包裹标签

可以把终端想成服务台，把 Shell 想成读单员，把命令想成被派出的工作人员。你在单子上写字符，读单员先判断哪些词属于同一个标签，再把标签数组交给工作人员。引号和反斜杠像“把这些字符绑在同一标签上”的说明；它们通常不会印在最终标签里。

```text
键盘字符
   ↓
终端把字符交给当前前台程序
   ↓
zsh 识别命令名、token、引用、转义、glob
   ↓
启动命令，并给出解析后的 argv
```

这个模型有意省略了标准流、管道和退出状态。省略不是说它们不存在，而是学习顺序要求你先把“谁解析、参数是什么、从哪里找文件”讲清楚。将来加入更多机制时，这条主链仍然成立。

## 当前工作目录：相对路径的解释起点

### cwd 是状态，不是文件内容

每个进程都有当前工作目录，常缩写为 cwd。对交互 zsh 来说，cwd 会随着 `cd` 改变。相对路径由使用它的进程从 cwd 开始解释；绝对路径则从文件系统根开始。上一章已经学习路径，本章把“相对路径的起点”落到运行中的 Shell 状态上。

在终端输入：

```text
pwd
```

`pwd` 的名字来自 print working directory。它把当前工作目录显示为路径。不要把屏幕上最后出现过的目录当成永久事实；新终端标签、IDE 运行配置和脚本都可能有不同 cwd。要诊断相对路径，最先重新观察。

### `cd` 改变的是当前 Shell 的 cwd

`cd` 常理解为 change directory。下面的路径含空格，必须保护参数边界：

```text
cd 'fixture/Factory Care'
pwd
```

第一行让当前 zsh 把一个参数 `fixture/Factory Care` 交给 `cd`。第二行重新观察。`cd` 不会改名、复制或删除目录；它改变 Shell 后续解释相对路径的起点。

若你关闭这个终端标签并打开新标签，新 zsh 的初始 cwd 由终端应用和配置决定，不保证继承刚才的练习位置。若你在一个终端 `cd`，另一个已经打开的终端通常也不会同步改变。cwd 属于进程状态，而不是全电脑唯一的“当前文件夹”。

### 相同文本，不同目标

假设树为：

```text
lab/
├── argv_probe.rb
└── fixture/
    └── Factory Care/
        └── pump status.txt
```

从 `lab/` 出发，`fixture/Factory Care/pump status.txt` 指向固定文件；从 `lab/fixture/Factory Care/` 出发，同一文本会多走一遍 `fixture/Factory Care`，通常指向不存在的目标。文本没变、磁盘文件没变，变化的是解释起点。

诊断路径问题时，应记录三件事：观察到的 cwd、传给命令的路径参数、解析后期望的目标树。只说“文件明明在那里”缺少起点；在搜索结果里找到一个同名文件也不能证明程序尝试读取它。

### 安全移动原则

初学阶段只在教材固定目录与系统临时目录活动。执行 `cd` 前先读路径，执行后立即 `pwd`；若不确定当前层级，不用连续猜多个父目录。不要为练习进入系统配置目录，也不要把个人主目录内容粘贴到外部模型。路径中出现公司名、用户名、项目密钥目录时，截图和日志要脱敏。

## 从字符行到 argv：参数边界的精确定义

### token 与参数

本章把 Shell 解析出的一个语法单元称为 token。在最简单情况下，空白把命令名和参数候选分开；引用与转义可以让空白保留在同一个参数中。经过必要展开后，命令收到一个有顺序的字符串数组，常称 argv（argument vector）。

以固定观察器为例：

```text
ruby argv_probe.rb alpha beta
```

脚本报告：

```text
argc=2
argv[0]="alpha"
argv[1]="beta"
```

`argc` 是参数数量，索引从零开始。参数的顺序和边界是合同的一部分：一个值为 `Factory Care` 的参数，与两个值为 `Factory`、`Care` 的参数不是同一请求，即使屏幕上都包含相同字母。

### Shell 语法字符通常不会进入参数

输入：

```text
ruby argv_probe.rb 'Factory Care'
```

观察器收到 `Factory Care`，不会收到两侧单引号。引号的职责是指导 zsh 把中间字符作为一个单位并抑制特定解释；它通常不是业务数据。若业务参数本身必须包含一个引号字符，就需要专门表示那个字面字符，不能假设外层引号自动保留。

### 空参数也存在

两个引号之间可以表达长度为零的参数：

```text
ruby argv_probe.rb '' alpha
```

这里是两个参数，第一个是空字符串，第二个是 `alpha`。它不同于完全省略第一个参数。后续表单、环境变量和 API 也常区分“字段缺失”与“字段存在但为空”；Shell 参数为这个区别提供了一个早期例子。

### 参数不是“自动类型”

Shell 交给普通程序的参数本质上是字符串字节序列在相应接口中的表示。`42` 看起来像整数，但目标程序需要自行决定是否把它解析成数值；`false` 也不自动成为布尔值。Shell 引用解决边界与解释问题，不验证业务类型、范围或权限。

## 单引号：把一段内容当作强字面文本

在 zsh 的基础规则中，单引号内大多数字符按字面保留，空格和星号不会作为分隔或 glob。路径含空格时：

```text
cd 'fixture/Factory Care'
```

若只是要传字面星号：

```text
ruby argv_probe.rb '*'
```

观察器收到一个值为 `*` 的参数，而不是当前目录中匹配的文件名集合。

单引号的优点是边界直观：当参数就是固定文本时，它减少意外解释。边界是单引号本身不能简单地原样嵌在同一段单引号中。遇到同时包含多类特殊字符的复杂文本，不要在生产命令里边猜边加斜杠；先用参数观察器构造最小案例，或让程序从受控配置读取数据。后续章节会分别处理更复杂输入。

不要把“单引号更安全”误解为“单引号中的路径一定安全”。它只控制 Shell 的一部分解析。路径仍可能指向错误文件，命令仍可能有破坏性，权限与业务校验也仍需单独判断。

## 双引号：保持一个参数，同时允许有限解释

双引号也能保护空格和 glob 字符：

```text
ruby argv_probe.rb "Factory Care"
ruby argv_probe.rb "*"
```

前者收到一个含空格参数，后者收到字面 `*`。与单引号不同，双引号会保留某些 Shell 展开的可能性，例如 `$name` 形式的参数展开。下面只用于理解差异，不要求本章系统学习 Shell 变量：

```text
label='pump room'
ruby argv_probe.rb "$label"
ruby argv_probe.rb '$label'
```

双引号行通常把变量当前值作为一个参数，单引号行通常传入字符 `$label`。这个对照说明选择引用方式要依据数据合同：需要固定字面文本时优先单引号；确实需要受控替换且仍要保持参数整体时才选双引号。不要因为双引号在某次路径上“也能用”就忽略它允许的解释范围。

空值也值得注意。若一个被双引号保护的变量为空，通常仍可形成一个空参数；若省略保护，展开后的边界可能因 Shell 规则与选项产生不同结果。具体展开规则留待 Shell 深入章节，本章只建立原则：变量边界也要显式保护，并用 argv 观察，不凭视觉猜测。

## 反斜杠：局部取消下一个字符的语法职责

反斜杠常用于让紧随其后的一个字符按字面解释。空格路径可写为：

```text
cd fixture/Factory\ Care
```

字面星号可写为：

```text
ruby argv_probe.rb \*
```

局部转义适合短且清晰的参数。若路径有多个空格、括号和其他特殊字符，连续转义很难审查；整体单引号往往更易读。可读性是安全属性：同事和未来的你必须能在执行前准确看见参数边界。

反斜杠的行为也受上下文影响：在单引号、双引号和未引用区域中，规则不完全一样。不要把一种位置的经验机械搬到另一种位置。本章练习只覆盖未引用区域的空格与星号，复杂组合应查 zsh 官方引用规则并用最小固定输入验证。

## glob：Shell 启动命令前的文件名匹配

### glob 不是“任何字符都自动搜索”

在未引用位置，`*` 常作为 glob 模式的一部分，由 zsh 根据当前目录内容匹配文件名。例如固定目录只有 `fan.txt` 与 `pump.txt` 时：

```text
ruby ../argv_probe.rb *.txt
```

程序可能收到两个参数：`fan.txt`、`pump.txt`。程序看到的是匹配结果，不一定知道原输入写过 `*.txt`。因此调试时只查看程序源码仍可能找不到参数数量变化的原因，必须把 Shell 解析阶段纳入证据链。

### cwd 改变，匹配集合也改变

glob 从 Shell 的当前工作目录及模式路径出发。相同 `*.txt` 在不同 cwd 可以匹配不同集合。今天目录中一个文件、明天生成十个文件，同一命令的 argv 数量也会变化。脚本若暗中假定“总会恰好一个匹配”，就把偶然目录状态当成合同。

### 零匹配不是跨 Shell 的统一结果

当模式没有匹配时，有的 Shell 或配置会保留模式文字，有的会报告错误，有的脚本会启用不同选项。zsh 的默认交互行为与其他 Shell 不必相同。本章不要求背诵所有差异，只要求不要把本机一次结果当成普遍规则。固定验证器使用 zsh、固定目录和确定匹配数，保证教材预言可复现。

### glob 不是正则表达式

glob 与正则表达式都使用某些符号描述匹配，但语法、执行者和适用对象不同。`*.txt` 的 glob 通常表示文件名以任意序列开头并以 `.txt` 结束；正则中的 `*` 通常修饰前一个表达式。不要把正则教程直接套到 Shell glob，也不要假设业务程序接收 glob 后会继续按同一规则匹配。

### 字面星号与恰好同名文件

Unix 文件名可以包含 `*`。若目录中恰好存在 `literal*.note`，未引用的 `literal*.note` 可能经过 glob 后仍显示为同样文字，因为它匹配了这个同名文件。仅看可见输出无法判断是否展开过。更强证据是：引用该参数、观察零匹配或多匹配对照、使用 argv 观察器并固定目录夹具。

## `pwd`、`cd` 与 `ls` 的最小安全用法

### `pwd`：观察，不靠想象

运行 `pwd` 获取当前工作目录。它适合在执行相对路径命令前、切换目录后、IDE 新开终端时使用。输出是某一时刻观察；之后 `cd` 会让旧结果过期。

### `cd`：一次改变，一个复核

在固定树中每次只改变一个目录层级，再运行 `pwd`。不要连续输入多条未经观察的 `cd`，否则出错后难以定位第一处偏离。路径含空格或 glob 字符时先保护参数边界。

`cd` 常由 Shell 自身实现，因为它必须改变当前 Shell 的 cwd。如果把它当成完全独立、结束后才通知父 Shell 的普通程序，就难以解释为什么 cwd 能持续变化。进程与父子关系将在下一章建立；本章记住可观察事实即可。

### `ls`：列出名称，不证明内容正确

`ls` 可以帮助观察固定练习目录中的名称。看见文件名只证明该名称在观察时存在，不证明你有正确权限、不证明内容或编码正确，也不证明另一个进程使用同一 cwd。不同选项、别名和终端宽度还可能改变展示，因此固定验证不解析个人 `ls` 外观。

本章不使用 `rm`、`mv`、`cp` 等会删除、移动或复制真实文件的命令。需要练习名称变化时，教材验证器在新临时目录创建固定夹具并由运行时负责清理，避免误伤工作区。

## 一个完整预测：从输入到参数

固定目录：

```text
Factory Care/
├── fan.txt
├── pump.txt
└── literal*.note
```

观察以下四行时，不要只写“能运行”，而要写程序收到什么：

```text
ruby ../argv_probe.rb Factory Care
ruby ../argv_probe.rb 'Factory Care'
ruby ../argv_probe.rb '*.txt'
ruby ../argv_probe.rb *.txt
```

第一行的未引用空格把文本切成两个参数。第二行是一个含空格参数。第三行是一个值为 `*.txt` 的字面参数。第四行由 zsh 根据 cwd 展开为两个文件名参数。引号通常不进入最终参数。

若需求是“把目录名交给程序”，第一行错误；若需求是“让程序自己接收模式”，第三行合适；若需求明确要求 Shell 把当前两个文本文件逐个作为参数，第四行才符合。但第四行还必须考虑零匹配和未来新增文件。不存在脱离需求的“唯一正确引用”，只有与参数合同相符或不相符。

## 故障诊断方法：先找第一个发生变化的边界

### 故障一：含空格路径被拆开

现象可能是“找不到 Factory”或“参数太多”。不要立刻改文件名。先运行参数观察器，把同一参数位置替换为固定探针，观察 `argc` 和 `argv`。若 `Factory Care` 变成两个参数，故障发生在 Shell token 化阶段，目标程序甚至没有机会把它当成一个路径。

最小修复是选择合适引用：固定字面路径可用单引号，简单空格也可局部转义。修复后重跑原观察，确认 `argc` 从两个变为一个，再运行原命令。只看原命令“不再报错”证据较弱，因为它可能偶然使用了另一个存在的路径。

### 故障二：星号意外展开

现象可能是参数数量随目录变化，或名称被当作多个工单导入文件。先记录 cwd 与固定目录列表，再用 argv 探针观察。若命令收到具体文件名而非 `*` 或 `*.csv`，展开发生在目标程序启动前。

若需求是字面模式，引用或转义；若需求本来就是展开，给零个、一个、多个匹配写出明确预言，并固定输入目录。不要通过往目录里随便放一个文件让测试“通过”，那只强化了隐含依赖。

### 故障三：相对路径从错误 cwd 解释

现象是编辑器能打开文件，命令却说不存在。第一步不是搜索全盘，而是运行 `pwd`，再把相对路径从这个起点画到目标。如果 IDE 的运行按钮与终端有不同 cwd，就分别记录，不能用一个窗口的 `pwd` 证明另一个进程的状态。

最小修复可以是先进入规定项目根，也可以让运行配置明确工作目录；选择哪一个取决于项目合同。修复后必须从新终端或原运行入口复跑，避免只在临时状态下成功。

### 故障四：把提示符复制成命令

报错可能包含用户名、主机名或 `%`。先对照教程排版，删除仅用于展示的提示符，只保留命令文本。不要因为看见 `$` 就机械删除所有美元符号：在真正的 Shell 输入中，它也可能参与语法。关键是识别文档约定，而不是全局替换字符。

### 诊断记录模板

每次保留：

- 原始输入文本；
- 观察到的 Shell 与 cwd；
- 预测的命令名、argc 与 argv；
- 实际探针结果；
- 故障属于 cwd、token、quote、escape 还是 glob；
- 只改变的一项修复；
- 修复后对同一预言的复跑；
- 尚未验证的平台、Shell 配置与文件集合。

这比“加了引号就好了”更有复用价值，因为它保留因果边界。

## 安全：终端不会替你理解命令

### 粘贴前做五项检查

任何来自 AI、博客或聊天记录的命令，在执行前都回答：

1. 命令名是什么，实际从哪里找到？
2. 当前 cwd 是什么，相对路径会指向哪里？
3. 每个参数边界是什么，是否含空格、星号或引用？
4. 命令会读取、创建、覆盖、移动还是删除哪些对象？
5. 若预测错误，如何在隔离目录回滚？

本章只实践只读观察和临时夹具，不因“教程说安全”而省略边界检查。

### 不把个人环境当教材输入

个人 shell 配置可能包含别名、函数、插件、代理和敏感变量。固定验证器用 `/bin/zsh -f` 并清空继承环境，只设置最小固定值；这不是说个人配置有错，而是自动预言必须排除无关差异。截图时不要展示完整提示符中的公司主机名、真实用户名和项目绝对路径。

### 不在真实目录练习 glob 破坏动作

glob 会随着目录内容变化。即使你理解 `*`，也不要把它与未学习的删除或覆盖命令组合，在主目录、项目根或系统目录试验。教材所有 glob 练习只把匹配结果交给无副作用参数观察器。

### 引用不是授权和输入校验

正确引用可以让一个路径作为一个参数到达程序，却不能证明调用者有权读取它，也不能阻止路径指向不应访问的位置。后续安全章节会学习路径边界、权限和不可信输入。本章的安全结论必须限制为“Shell 解析符合预言”。

## FactoryCare 场景：设备导入目录改名

FactoryCare 的一个本地教学任务原先从 `imports` 目录读取固定样本。需求改为目录名 `incoming work orders`，还要能够把字面模式 `*.csv` 交给后续程序自己解释。

若直接写未引用目录名，zsh 会把它拆成三个参数。若未引用 `*.csv`，zsh 又可能依据当前目录提前展开。安全设计先写参数合同：第一个参数是一个含空格目录路径，第二个参数是一个值为 `*.csv` 的字面模式。然后用探针验证：

```text
ruby argv_probe.rb 'incoming work orders' '*.csv'
```

预言为 `argc=2`，两个 argv 按顺序保存完整文字。接着才把同样边界移交给真实、已审查的导入程序。若需求后来改成“由 Shell 枚举每个 CSV”，合同会变成可变数量文件参数，并必须补零匹配与多匹配场景；不能悄悄去掉引号后仍声称接口没变。

故障报告不要写“终端不支持空格”，而应写“zsh 在未引用区域把空格作为 token 边界，导入程序收到三个目录片段；使用单引号后探针收到一个路径参数”。这样的表述能指出阶段、证据和修复。

## 正例、边界与反例总表

| 需求 | 输入模型 | 预期 argv | 主要边界 |
| --- | --- | --- | --- |
| 两个普通标签 | `alpha beta` | 两个参数 | 顺序不能丢 |
| 一个含空格目录 | `'Factory Care'` | 一个参数 | 引号通常不进入值 |
| 一个字面星号 | `'*'` 或 `\*` | 一个值为 `*` 的参数 | 转义上下文不同 |
| 当前目录两个文本文件 | `*.txt` | 两个名称参数 | cwd 与文件集合会改变结果 |
| 空字符串 | `''` | 一个空参数 | 不等于省略参数 |
| 相对路径 | `fixture/...` | 一个路径文本 | 必须绑定 cwd |

反例不是为了记住“永远加引号”。若需求就是让 Shell glob 展开，给模式加引号会改变业务含义。正确流程是先写清谁负责展开、命令应收到什么、零/一/多匹配如何处理，再选择语法。

## 速查表

| 概念 | 最小定义 | 首个观察 | 常见误解 |
| --- | --- | --- | --- |
| 终端 | 文字输入与显示界面 | 当前前台程序与窗口 | 终端就是 Shell |
| Shell | 解析命令并启动程序的程序 | 明确使用 `/bin/zsh` | 所有 Shell 规则相同 |
| 提示符 | Shell 的输入提示显示 | 分开教程标记与输入 | 提示符也是命令 |
| cwd | 进程解释相对路径的起点 | `pwd` | 全电脑只有一个 cwd |
| token | Shell 解析阶段的语法单元 | 参数探针 | 屏幕空格必然属于数据 |
| argv | 命令最终收到的有序参数 | `argc` 与逐项值 | 引号会原样进入参数 |
| 单引号 | 强字面引用区域 | 探针比较 | 能保证命令整体安全 |
| 双引号 | 保持整体并允许有限解释 | 与单引号对照 | 与单引号完全一样 |
| escape | 局部取消字符语法职责 | `\ `、`\*` 对照 | 所有上下文行为相同 |
| glob | Shell 的文件名模式展开 | 固定 cwd/目录/argv | glob 就是正则 |

## 术语表

- **Terminal / 终端**：承载文字交互的界面或终端仿真程序。
- **Shell**：读取并解析命令语言、启动命令的程序；本章固定为 zsh。
- **prompt / 提示符**：Shell 表示等待输入的界面文字。
- **command / 命令**：可指一整行 Shell 输入，也可指解析出的命令名；叙述时应明确。
- **cwd / current working directory**：进程当前工作目录，相对路径的解释起点。
- **argument / 参数**：传给命令的一个有边界值。
- **argv**：有顺序的参数向量；本章用 Ruby `ARGV` 观察脚本参数。
- **token**：Shell 语法分析得到的单元；展开后与最终 argv 不一定一一对应。
- **quoting / 引用**：控制字符在 Shell 中按字面还是按语法解释的机制。
- **escape / 转义**：使特定字符失去当前语法职责、按字面参与参数的做法。
- **glob**：Shell 根据文件名模式与目录内容产生名称集合的展开机制。
- **literal / 字面值**：希望字符本身成为数据，而不是触发 Shell 语法。
